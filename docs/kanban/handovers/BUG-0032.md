## GROOMING · 2026-10-03T16:40:00Z · Claude Code (Opus 5.5)

**Source**: FLAG 4 of TASK-1251. `packages/services/src/waifu-tcg/__tests__/rarity-and-card-generator.test.ts`, test "should scale stats according to rarity multiplier", failed once in a full `pnpm test:coverage` run and passed on six reruns. A failure there fails the CI coverage gate.

**Cause (to confirm)**: the test builds `CardGenerator` without `randomFn`, so `generateStats` (`packages/services/src/waifu-tcg/card/card-generator.ts:191`) rolls base stats with `Math.random`. Comparing two independently rolled cards of different rarities can invert when one roll is low and the other high.

**Fix**: pass a deterministic `randomFn` (the repo already has `createSeededRng`, used by `balance-simulator.ts`), or compare stats produced from the same rolls. Check the rest of the file for other unseeded comparisons. Test-only change; `CardGenerator` already accepts `randomFn`.

**Pitfalls**: do not weaken the assertion (for example by widening ranges until it always passes). Keep the rarity ordering check meaningful.

## PROGRESS · 2026-10-03T17:10:00Z · ticket-worker (Sonnet 5.5) · REVIEW

**Root cause (confirmed)**: the `Card Generator` block built `new CardGenerator()` with no `randomFn`, so `generateStats` rolled base stats with `Math.random`. Base rolls overlap across tiers: COMMON attack tops out at 299 and MYTHIC attack starts at 250 (50 x 5.0); COMMON defense reaches 209 and MYTHIC defense starts at 150 (30 x 5.0). A high COMMON roll against a low MYTHIC roll inverts the `toBeGreaterThan` check. HP cannot invert (1499 vs 2500).
