## GROOMING · 2026-10-09T18:41:41Z · claude-opus-5-5 (coordinator)

**Approach**
1. Add `drizzle.sqlite.config.ts` and `drizzle.pg.config.ts` in `packages/database`, with `out: './migrations/sqlite'` and `out: './migrations/pg'`. The pg config needs only `dialect` and `schema` for `generate`; it needs no database credentials.
2. Generate the baseline: `drizzle-kit generate --config <file> --name baseline` for each dialect. Rename the result to `0000_baseline.sql` if drizzle-kit names it differently, and keep `meta/_journal.json` and the snapshot consistent with the new name.
3. Compare the baseline with the generated DDL. Both come from the same Drizzle schema, so they should match. Check the column sets in a test, not by reading text.
4. Extend `scripts/generate-ddl.mjs`, or add a sibling script, to write `src/migrations/generated/{sqlite,pg}.ts`. Follow the `ddl.ts` header style: `// Auto-generated ...`. Each entry is `{ id: '0000_baseline', statements: [...], checksum: '<sha256 hex>', contract: false }`.
5. Package scripts: `db:generate-migrations` in `@ririko/database`; `db:generate` at the root (both drizzle-kit runs, then the embedder, then `db:generate-ddl`).

**Relevant code** (from CodeGraph during grooming)
- `packages/database/scripts/generate-ddl.mjs`: already runs drizzle-kit (`export`) in-process and writes `ddl.ts`. Reuse its approach.
- `packages/database/drizzle.config.ts`: SQLite only, used by `db:push`. Leave it for development.
- `packages/database/src/schema/{sqlite,pg}/ddl.test.ts`: the DDL parity tests. Model the baseline test on them.

**Pitfalls**
- drizzle-kit 0.31 separates statements with `--> statement-breakpoint`. Split on that marker. Never split on `;`, because defaults and checks can contain one.
- The repository runs on Windows too. Normalise CRLF to LF before hashing, or checksums differ between machines.
- Prettier formats `.ts` files. Make the embedder's output already Prettier-clean, or add the generated folder to `.prettierignore` the way `ddl.ts` is handled. Check what `ddl.ts` does and do the same.

**Out of scope**
- Running the migrations anywhere (TASK-1852 and TASK-1854).
