## GROOMING · 2026-10-09T18:41:41Z · claude-opus-5-5 (coordinator)

**Approach**
- The "schema in sync" check:
  - Run drizzle-kit generate for each dialect with `out` pointed at a temporary copy of the migrations folder.
  - Fail if a new `.sql` file appears.
  - Never write into the real folder from CI.
- The embedded-module check: rebuild the modules in memory and compare them with the files on disk.
- The safety lint:
  - Remove SQL comments and string literals, then match the forbidden statements without regard to case.
  - Skip a file whose first line is `-- ririko:contract`.
  - The baseline is exempt. It only creates things, but check that it really passes the lint.
- CircleCI: add `pnpm db:check` to the `lint` job. Check that the `test-postgres` job already covers `packages/database/src/migrations`; widen its paths if not.

**Relevant code** (from CodeGraph during grooming)
- `.circleci/config.yml:142` (`lint`), `:200` (`test-postgres`).
- `scripts/circleci-deploy.test.ts`: tests that read the CircleCI config. Extend them so the new step is asserted.

**Pitfalls**
- drizzle-kit can print an interactive prompt (for example "is this a rename?"). Run it non-interactively. If a prompt would appear, the check fails with a message telling the author to run `pnpm db:generate` locally.
- Keep the check offline: no database, no network.

**Out of scope**
- Running a previous release's test suite against the new schema.
