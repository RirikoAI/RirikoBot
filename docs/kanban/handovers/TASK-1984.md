**Approach**
1. `apps/bot/src/commands/tickets/ticket.command.ts`: one `createTicketCommand(services)` with an `action` STRING option and choices, shaped like `createAutoRoleCommand` (`apps/bot/src/commands/roles/autorole.command.ts`) and `createGiveawayCommand`. `registrationScope: 'guild'`. Prefix parsing follows the `autorole` raw-args handling around line 130.
2. `components.ts`: `handleTicketButton` (`ticket:open` shows the subject modal, `ticket:close` shows the reason modal, `ticket:claim` claims) and `handleTicketModal` (`ticket:modal:open`, `ticket:modal:close`). Export them from `commands/tickets/index.ts` and `apps/bot/src/index.ts`, as the giveaway handlers are.
3. `component-interactions.ts`: add a `ticket:` branch in the button block, and a new `interaction.isModalSubmit()` block before the help fallback. No modal is routed today.
4. `services.ts` `createBotServices`: build `TicketRepository` and `TicketService` and add them to `BotServices`. `command-set.ts` `registerBotCommands`: register `createTicketCommand`.
5. `main.ts` line 198: inside the existing `channelDelete` listener, call `services.ticketService.handleChannelDeleted(channel.id)` in its own try/catch, so an auto-voice failure does not skip it.

**Relevant code**
- `autorole.command.ts` line 285 onward: `send-verify` posts an embed with a button to a channel. The panel works the same way.
- `component-interactions.ts`: routing by custom id prefix, with one try/catch for everything.

**Pitfalls**
- A modal must be the first response to the button. Do not `deferReply` before `showModal`.
- Answer modal submits with `deferReply({ ephemeral: true })` first, since channel creation and transcript paging can take more than 3 seconds.
- `command-set.test.ts` lists `GUILD_SCOPED` exactly. Add `ticket` there.
- Prefix commands cannot open modals. `!ticket close <reason>` takes the reason from the arguments.
