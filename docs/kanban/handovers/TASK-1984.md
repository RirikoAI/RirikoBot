**Decisions & gotchas**
- Panel permission is Administrator or Manage Server (checked in the command, not via `userPermissions`, so the other four actions stay open to openers and staff, whom the service checks). The panel refuses when tickets are disabled or have no category, and points to the Tickets dashboard page.
- Panel target: the chosen channel, else the current one; text or announcement channels only. A send failure is logged (error text only) and reported.
- `add` and `remove` confirm publicly (mentions suppressed); every other reply is ephemeral on slash. Prefix commands cannot reply privately, so the flag is ignored there.
- `close` (command and modal) defers first and sends the confirmation inside a try/catch, because the ticket channel is normally deleted by then and the reply may fail with Unknown Channel. This is logged and ignored. The opener sees nothing after a successful close; the transcript posts and the channel disappears.
- The Close modal sends an empty string when the reason is blank; `TicketService.close` already turns it into null (`cleanText`).
- Prefix ID parsing needs 17 to 20 digit ids or mentions, as the built-in prefix resolver does.
- Not covered by a unit test: the `main.ts` channelDelete wiring (the file is not unit tested; the logic it calls is covered in TASK-1983).
- The Discord `ephemeral` option prints the discord.js deprecation warning, as every other command in this repo does.
