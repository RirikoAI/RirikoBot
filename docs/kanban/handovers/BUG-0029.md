## GROOMING · 2026-10-01T15:25:36Z · Claude Code (Opus 5.5)

**Approach**
1. In `packages/core/src/config/schema.ts`, export `DEFAULT_DATABASE_URL = './data/ririko.sqlite'` and use it as the `DATABASE_URL` default of `BaseAppConfigSchema`.
2. In `packages/database/src/client/factory.ts`, add and export `databaseConfigFromEnv(env = process.env): DatabaseConfig`. It returns `{ dialect: env.DATABASE_DIALECT || 'sqlite', url: env.DATABASE_URL || DEFAULT_DATABASE_URL }`.
   - Keep `||` so empty strings count as unset, as every caller does today.
   - Do not validate the dialect. `createDatabaseClient` already rejects unsupported dialects, and the doctor check reports them itself.
3. Replace each hand-written fallback with the helper:
   - `createBotServices` (`apps/bot/src/services.ts:328-333`), which is the bug.
   - The four CLI commands (`economy-config`, `guild-config`, `passkeys-reset`, `tcg-rules`).
   - The doctor database check (`apps/cli/src/doctor/checks.ts:52-53`).
   - `scripts/db-reset.ts`, `reset-tcg-user.ts`, `tcg-balance-sim.ts`, `tcg-boss-builder.ts` and `tcg-card-builder.ts`. Scripts import from `../packages/database/src/index.js`.
4. Tests:
   - `databaseConfigFromEnv` defaults and set values in `factory.test.ts`.
   - `loader.test.ts` checks the schema default against `DEFAULT_DATABASE_URL`.

**Relevant code** (from CodeGraph during grooming)
- `apps/bot/src/services.ts:332`: `url: process.env.DATABASE_URL || 'sqlite:storage/ririko.db'`.
- `packages/database/src/client/sqlite.ts:10` `resolveDatabasePath`: passes `sqlite:` URLs through untouched. better-sqlite3 then treats the whole string as a relative file name, so the bot opened `<cwd>/sqlite:storage/ririko.db`.
- `packages/core/src/config/schema.ts:52`: `DATABASE_URL: z.string().default('./data/ririko.sqlite')`.
- `apps/web/src/lib/server/services.ts:296` `getDatabase`: the dashboard uses the schema default.

**Pitfalls**
- The apps typecheck against each package's `dist` types, so run `pnpm build` before `pnpm typecheck`, as `verify_cmd` does.
- `drizzle.config.ts` uses `../../data/ririko.sqlite`, relative to `packages/database`. drizzle-kit does not go through `resolveWorkspacePath`, so leave it.
- `.env.example` and the docs already say `./data/ririko.sqlite`.

**Out of scope**
- Validating `DATABASE_DIALECT`, and Postgres schema bootstrap (FLAG on STORY-122).
