# BUG-0003 Handover Note: OpenAI & LLM Providers Function Name Schema Validation & Sanitization

- **Ticket ID**: `BUG-0003`
- **Ticket Type**: Bug
- **Parent Story**: `STORY-060: Multi-Provider AI Core, Fallback Chain & Tool Calling Engine`
- **Story Points**: 2
- **Completed On**: 2026-09-17
- **Target Branch**: `develop/2.0.0`

---

## 1. Root Cause Analysis
When sending chat requests with function calling tools enabled to OpenAI, the API returned HTTP 400:
```text
OpenAI API error: 400 Invalid 'tools[1].function.name': string does not match pattern. Expected a string that matches the pattern '^[a-zA-Z0-9_-]+$'
```
The internal names of several Ririko tools use dotted namespace notations (e.g. `reminders.create`, `music.play`, `economy.check_balance`, `games.coinflip`, `anime.search`). While valid in TypeScript, OpenAI schema strictly forbids dots in function names and requires `^[a-zA-Z0-9_-]+$`.

When OpenAI failed with 400, the fallback chain routed to Ollama, which returned 404 because `llama3.3` was not pulled in the local Ollama environment, resulting in an `AiProviderExhaustionError`.

---

## 2. Solution & Implementation
1. **`OpenAIProvider` (`packages/ai/src/providers/openai.provider.ts`)**:
   - Added `sanitizeToolName(name: string): string`: converts characters outside `[a-zA-Z0-9_-]` (such as dots `.`) to underscores `_` (e.g., `reminders.create` -> `reminders_create`).
   - Added `restoreToolName(name: string, originalTools?: ToolDefinition[]): string`: dynamically maps incoming function call names from OpenAI back to original registered tool names.
   - Applied sanitization in `mapTools` and in `mapMessages` for conversation history (`role === 'assistant'` tool calls and `role === 'tool'`).
   - Applied restoration in `generate` and `stream` when emitting `ToolCall` arrays.
2. **`GeminiProvider` (`packages/ai/src/providers/gemini.provider.ts`)**:
   - Added identical `sanitizeToolName` and `restoreToolName` to protect against Gemini schema identifier rejections.
3. **`OllamaProvider` (`packages/ai/src/providers/ollama.provider.ts`)**:
   - Added identical `sanitizeToolName` and `restoreToolName` for consistent cross-provider tool calling.
4. **`ToolRegistry` (`packages/ai/src/tools/registry.ts`)**:
   - Updated `get`, `has`, `validateArgs`, and `execute` to flexibly resolve tool lookups by both dot and underscore formats (e.g., `reminders.create` <-> `reminders_create`).
5. **`ToolSecurityInterceptor` (`packages/ai/src/security/security-interceptor.ts`)**:
   - Normalized tool name checks in the guild allowed tools filter to match regardless of notation format.
