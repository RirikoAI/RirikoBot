**Approach**
1. `apps/cli/src/commands/setup.ts`: `registerSetupCommand(program)`, following `registerAiConfigureCommand`. Resolve the file: `--env-file` if given, else `.env` (source) or `.env.production` (`--docker`) in `process.cwd()`. The global `--config` option does not apply here.
2. Register it in `createProgram` (`apps/cli/src/program.ts`).
3. Root `package.json`: `"installer": "tsx apps/cli/src/index.ts setup"`.
4. Opening the browser: `spawn('cmd', ['/c', 'start', '', url])` on Windows, `open` on macOS, `xdg-open` elsewhere, `{ stdio: 'ignore', detached: true }`, errors ignored. Always print the URL first.
5. `apps/bot/src/main.ts` (the `!token` branch near line 43): add a line that names `pnpm installer` and, for Docker, `docs/deployment.md` section 2.4.
6. `Dockerfile`, bot stage: `assets` is already copied (`COPY assets assets`). Add `COPY docs/legal docs/legal` if TASK-1924 serves the legal texts from there.

**Relevant code**
- `apps/cli/src/program.ts:46` `createProgram`, `:22` `loadEnvConfig` (runs before every action; harmless for `setup`).
- `apps/cli/src/commands/ai-configure.ts:374` `registerAiConfigureCommand`: the option and action style.
- `apps/bot/src/main.ts:29` `main`.
- `Dockerfile` line 93: the `ririko` wrapper in the bot image; line 104: the image runs as `10001:10001`.

**Pitfalls**
- `pnpm setup` is a built-in pnpm command, so the script must not be called `setup`.
- In Docker the bind mount may be owned by another user than 10001, so the write can fail. The wizard then offers Download (TASK-1924); say so in the warning.
- `--listen 0.0.0.0` inside a container is safe only because Docker publishes the port to `127.0.0.1`. Print that warning for every non-loopback address.
- Do not change how the bot starts when a token exists.

**Out of scope**
- The docs (TASK-1926).
