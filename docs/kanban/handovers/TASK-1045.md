# TASK-1045 Handover: Tutorial Floor T4 Dynamic Elemental Disadvantage, Starter Pool Modernization & Direct Climb Prompt

## 1. Summary of Changes
- **Tutorial Service Modernization (`packages/services/src/waifu-tcg/dungeon/tutorial-service.ts`)**:
  - **Dynamic Elemental Loop**: Implemented `getCounterElement(element: CardElement)` mapping all 7 elements cyclically:
    `FIRE -> WATER -> ICE -> LIGHTNING -> EARTH -> WIND -> FIRE`, plus `LIGHT <-> SHADOW`.
  - **Common Starter Pool**: Removed synthetic `starter_waifu_01` creation in `ensureStarterCard(userId)`. The service now queries real active `COMMON` cards from the database (`waifuCardRepo.listCards({ rarity: 'COMMON', isActive: true })`) and falls back to any active card if none exist.
  - **Floor T4 Boss Element Locking**: Implemented `getFloor4BossConfig(userId, playerElement)`. Checks `tcg_system_configs` under `tutorial:floor4:${userId}`. If unset, calculates the counter element to the player's card, persists it, and locks it so subsequent retries keep the same boss element even after equipping a counter card.
  - **Loss Counter Card Grant**: Implemented `handleTutorialFloor4Defeat(userId, bossElement)`. When a player loses on Floor T4, checks if they already own a card of `bossElement`. If not, grants a real `COMMON` card of that element in `IDLE` state from the database, records `counterCardGiven: true` in metadata, and returns the granted card.
  - **Graduation Cleanup**: Updated `completeTutorial(userId)` to delete `tutorial:floor4:${userId}` via `tcgConfigRepo.delete(...)`.
- **Dungeon Runner Engine (`packages/services/src/waifu-tcg/dungeon/dungeon-runner.ts`)**:
  - Injected `tutorialService?: TutorialService` into `DungeonRunnerOptions`.
  - In `prepareFloorSetup()`, if running Floor 4 in `season_tutorial`, dynamically queries `tutorialService.getFloor4BossConfig(userId, playerCard.element)` to override the boss element and `ElementalWard` affix to counter the player.
- **Bot Combat HUD & Retries (`apps/bot/src/commands/tcg/dungeon-battle.manager.ts`)**:
  - In `finalizeBattle()`, when a defeat occurs on Floor T4 of `season_tutorial`, invokes `tutorialService.handleTutorialFloor4Defeat(userId, bossElement)`.
  - Renders an educational tactical breakdown in the defeat embed explaining elemental disadvantage, ward absorption, and how to shatter the boss's ward.
  - In `buildPostBattleRows()`, adds an interactive `[⚔️ Equip <CardName> & Retry]` button (`dungeon:action:equip_retry:<cardId>`) when a counter card is granted or already owned.
  - In the battle collector, handles `dungeon:action:equip_retry:<cardId>` by equipping the counter card (updating previous cards to `IDLE`) and re-launching the dungeon battle session immediately.
- **Direct Climb Gate Prompt (`apps/bot/src/commands/tcg/dungeon.command.ts`)**:
  - In `/dungeon climb`, if the user has not completed the prologue tutorial (`tutorialProgress.highestClearedFloor < 4`), prompts with an educational confirmation embed:
    `⚠️ You haven't finished the tutorial yet! ... Begin Tutorial Floor X / 4?`
  - Provides interactive buttons: `[⚔️ Begin Tutorial Floor X / 4]` (`dungeon:tutorial:begin:<nextFloor>`) and `[❌ Cancel]` (`dungeon:tutorial:cancel`).
  - Upon clicking `Begin`, launches the tutorial floor directly.
- **Database Seeding Cleanup (`scripts/db-reset.ts` & `apps/bot/src/services.ts`)**:
  - Removed `starter_waifu_01` hardcoded database seeding.
  - Injected `tcgConfigRepo` into `TutorialService` and `tutorialService` into `DungeonRunner`.

  - `packages/services/src/waifu-tcg/__tests__/tutorial-starter-pool.test.ts`: Verifies real common card granting and fallback.
  - `packages/services/src/waifu-tcg/__tests__/tutorial-floor4-element.test.ts`: 4 comprehensive unit tests verifying 7-element counter calculation, Floor T4 boss locking, defeat counter card granting, duplicate prevention, and graduation cleanup.

## 3. Decisions & Gotchas
- **Loop Prevention**: By persisting the boss element in `tcg_system_configs` under `tutorial:floor4:${userId}`, when the player equips the newly granted counter card, the boss does *not* dynamically change to counter the *new* card. The boss remains the counter to the *original* card, allowing the user to shatter the ward with their new card.
- **Card State Invariant**: When granting the counter card upon defeat, it is granted in `IDLE` state (not auto-equipped immediately in the database) so the user's current card remains equipped until they click `[⚔️ Equip & Retry]`.
