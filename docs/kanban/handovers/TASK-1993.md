## GROOMING · 2026-10-22T02:10:00Z · claude-opus-5-5 (coordinator)

**Approach**
1. `packages/services/src/event-logs/`: `event-log.service.ts` (cache, rules, send), `embeds.ts` (pure builders, one per event, easy to unit test), `types.ts` and `index.ts`. Export it from `packages/services/src/index.ts`.
2. Cache: copy `CommandOverrideService` (`packages/services/src/guild/command-override.service.ts`): a Map keyed by guild with cachedAt, `cacheTtlMs` 5 minutes, `invalidate(guildId)` and an injectable `now`.
3. Resolve the target channel with `guild.channels.cache.get(id)`. Skip it when it is missing or not text-based.
4. Bulk delete: build a .txt like the ticket transcript (`packages/services/src/tickets/transcript.ts`) from the cached messages, oldest first. Attach it with AttachmentBuilder.
5. Member update: compare `old.nickname` with `new.nickname`, the role id sets, and `communicationDisabledUntilTimestamp`. One embed per kind of change. When old is partial, there is nothing to compare, so skip.
6. Embed field values are capped at 1,024 characters and descriptions at 4,096. Cut with "…".

**Relevant code**
- `ModerationLogService.buildCaseEmbed` (`packages/services/src/moderation/moderation-log.service.ts`): embed style and colours used for logs today.

**Pitfalls**
- `messageUpdate` fires for link previews with the same content. Compare `old.content` with `new.content`, and skip when old is partial (unknown) and nothing else is known.
- Partial messages have a null author and content. Handle them without throwing.
- Never put message content in console logs.
- Deterministic tests: inject `now` and build fake discord.js objects. No network.

**Out of scope**
- Gateway subscription and wiring (TASK-1994).

**Public API (for TASK-1994)**
`new EventLogService({ repo: EventLogSettingsRepository, cacheTtlMs?, now? })`, then `invalidate(guildId?)` and these methods, each `Promise<void>` and never throwing:
`messageEdited(old, new)`, `messageDeleted(message)`, `messagesBulkDeleted(messages: ReadonlyMap, channel: GuildTextBasedChannel)`, `memberJoined(member)`, `memberLeft(member | partial)`, `memberUpdated(old | partial, new)`, `memberBanned(ban)`, `memberUnbanned(ban)`, `channelCreated(channel)`, `channelDeleted(channel)`, `channelUpdated(old, new)` (the three take `DMChannel | NonThreadGuildBasedChannel`, as the gateway events give them, and skip DMs), `roleCreated(role)`, `roleDeleted(role)`, `roleUpdated(old, new)`, `voiceStateChanged(old, new)`.

**Decisions & gotchas**
- Each method does its cheap checks first (no guild, content unchanged, partial old member, same voice channel), so those events never touch the cache or database.
- An edit whose old content is not cached is logged as "Content unknown" only when the new message has `editedTimestamp` set (Discord sets it on real edits, not on link previews); otherwise it is skipped. If the new content is null, it is skipped.
- `ignoreBots` also applies to member and voice events (the subject user) and drops bot messages from a bulk delete, which is how the "Leave out events caused by bots" setting reads. Ignored channels apply to message events only.
- `memberUpdated` sends one message holding up to three embeds (nickname, roles, timeout).
- Timeout is "set" when the new end is in the future and differs from the old one, and "lifted" when the old end was in the future and the new one is null or past.
- Errors log `error.message` only, with guild and channel IDs; a send error, a settings read error and any unexpected error in a handler are each caught.
- Types in the new tests use `fake<T>()` casts of plain objects; no network.
