## 1. Why this task exists (audit findings, 2026-09-28)
- **Drops never spawn.** `DropManager` ([drop-manager.ts](file:///Z:/Projects/ririko-v2-2026/packages/services/src/waifu-tcg/drops/drop-manager.ts)) keeps `GuildDropConfig` in an in-memory `configs` Map (:53). `setGuildConfig` (:68) is only called by tests. Nothing in `apps/` calls `recordMessage` (:115) or `spawnDrop` (:162). The bot only uses `getActiveDropById`, `getActiveDrop` and `claimDrop` in [card.command.ts](file:///Z:/Projects/ririko-v2-2026/apps/bot/src/commands/tcg/card.command.ts) (:306-318).
- `DropManager` is created at `apps/bot/src/services.ts:340` with no config source.
- `isWithinActiveHours` (:108) uses `date.getHours()`, the process time zone, not the guild time zone.
- **The TCG Manager Role is global.** It is key `tcg_manager_role_id` in `tcg_system_configs` ([tcg-config.service.ts](file:///Z:/Projects/ririko-v2-2026/packages/services/src/waifu-tcg/admin/tcg-config.service.ts) :15, :33). `/tcg-admin action:role` ([admin.command.ts](file:///Z:/Projects/ririko-v2-2026/apps/bot/src/commands/tcg/admin.command.ts) :306) writes it for every guild. The docs describe it as guild-scoped (`docs/dashboard.md:89,172`, `docs/waifu-tcg.md:769-780`).
- There is no guild-scoped TCG storage and no `tcg` module in `GuildConfigSchemas`.

- Tests run offline (`vitest.setup.ts` blocks non-loopback network).
- Coverage gate: `pnpm test:coverage` must pass every threshold in `vitest.config.ts`. Never lower a threshold.
- Never commit `apps/web/AGENTS.md` / `apps/web/CLAUDE.md` (written by `next dev`); stage explicit paths.
