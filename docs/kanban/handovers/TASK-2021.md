**Approach**
1. Create `apps/bot/src/commands/shared/guild-config-command.ts` with:
   - `canManageServer(member: GuildMember | null): boolean`: Administrator or ManageGuild. Copy the rule from `isManager` in `apps/bot/src/commands/tickets/ticket.command.ts:100`, and handle null.
   - `saveGuildConfig(ctx, services, module, patch)`: calls `services.guildConfigService.update(ctx.guildId!, module, patch, { userId: ctx.user.id, source: 'discord' })`. On `GuildConfigValidationError` it replies (ephemeral, `allowedMentions: { parse: [] }`) with the readable message and returns `null`. Other errors are rethrown. Otherwise it returns `values`. Keep it generic over `GuildConfigModule` so the return type is `GuildConfigValues<M>`.
   - `describeValidationError(error)`: move it here from `level-roles.command.ts:84`, unchanged (it strips the `Row N: ` prefix).
   - `parseToggle(text: string | null | undefined): boolean | null`.
2. Unit-test the helper in `apps/bot/src/commands/shared/__tests__/`, following the mock style of `level-roles.command.test.ts`.
3. In `level-roles.command.ts`, make `saveRewards` call `saveGuildConfig`. Add `stack` to `LEVEL_ROLE_ACTIONS`, a BOOLEAN slash option `enabled`, and prefix parsing of `args[1]` via `parseToggle`. With no value, reply with the current `keepPreviousRoles`.

**Relevant code** (from CodeGraph during grooming)
- `apps/bot/src/commands/roles/level-roles.command.ts:123` `saveRewards`: the try/catch pattern to centralise.
- `apps/bot/src/commands/roles/level-roles.command.ts:312` `execute`: `list` is open to everyone; every other action checks `canManage` (Manage Roles, Manage Server or Administrator). `stack` goes behind `canManage` too.
- `packages/services/src/guild/guild-config.service.ts:773` `GuildConfigService.update`: validates, audits and bumps the version. It returns `{ values, changes }`, and `changes` is empty when nothing changed.
- `packages/core/src/config/guild-config.ts:405` `levelroles` schema: `keepPreviousRoles` is a `FlagSetting`, so a boolean is accepted.

- A slash `say` is ephemeral, but a prefix reply cannot be. Keep the existing `say` behaviour.
- Do not change the levelroles permission rule for list, add, remove or sync.
