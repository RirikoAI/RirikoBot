**Approach**
1. `apps/cli/src/installer/render.ts`: pure functions from the step model and the session state to HTML strings. One `escapeHtml` used for every value. Icons as inline SVG.
2. `assets/installer/wizard.css`: port `.local/installer-1x/assets/scss/bd-wizard.scss` to plain CSS.
   - Keep the structure: `.steps > ul` flex row of tabs (top corners rounded 10px, padding 28px 30px 24px, 25% width); the icon square (34px, radius 4px); title 18px bold; subtitle 14px; `.content` padding 100px 35px 20px with `min-height: 420px`; `.content-wrapper` max 700px centered; `.actions` row right-aligned with 15px gaps; on narrow screens the tabs show only the icon.
   - Colors from `apps/web/src/app/globals.css`: page `--color-ink`, card and current tab `--color-panel`, borders `--color-edge`, icon of current and done tabs and the Next button `--color-sakura-strong`, links `--color-sakura`, text `#e7e5f0`. `color-scheme: dark`.
   - Guides: `<details class="guide"><summary>Click here to show/hide the guide</summary>...</details>` styled as the 1.x primary button and card.
   - Full-size images: each guide image is a link to `#img-<n>`; a `:target` overlay shows the image and caption, with a close link. No JavaScript.
   - Switches: a checkbox styled as the 1.x slider; `.feature:has(input:checked) .feature-fields { display: block }`. Fields of a switched-off feature are not required (the server decides, not the browser).
3. `apps/cli/src/installer/server.ts`: `startInstallerServer(options, deps)` with `node:http`.
   - Routes: `GET /?token=` (exchange), `GET /step/:id`, `POST /step/:id` (fields + `action=next|back|verify`), `GET /legal/terms`, `GET /legal/privacy` (the Markdown served as `text/plain; charset=utf-8`, or rendered with a minimal safe renderer for headings, paragraphs and lists), `GET /assets/*` (only files under `assets/installer/`, no `..`), `POST /finish`, `GET /download`.
   - Session: one in-memory session (answers, verified fingerprints per check, current step, form token). The fingerprint is a hash of the values a check used; Next requires a passing check whose fingerprint matches the current values.
   - Headers on every response: `Cache-Control: no-store`, `Content-Security-Policy: default-src 'self'; img-src 'self'; style-src 'self'; form-action 'self'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`.
4. Move `BOT_INVITE_PERMISSIONS` to `@ririko/discord` (for example `packages/discord/src/permissions.ts`, exported from the package index). `apps/web/src/lib/server/guilds/permissions.ts` re-imports it; the invite route and its tests keep working.
5. The Welcome page states the file path, the profile and whether the file exists (update mode). The Install page shows the summary, the invite link, the two tick-boxes, Finish and Download.
6. The result page for the source profile lists the next commands of SETUP.md sections 5 to 8, in that order: `pnpm db:reset` (only for a new database; it deletes the data), the TCG builders of section 6, `pnpm lavalink:install`, `pnpm lavalink:start`, `pnpm dev:bot`, and `pnpm dev:web` when the dashboard is on. For docker, the commands of `docs/deployment.md` sections 2.5 to 2.8. Copy them from those docs; do not invent commands. In update mode, leave out `pnpm db:reset`.

**Pitfalls**
- DNS rebinding: check the `Host` header against `127.0.0.1:<port>`, `localhost:<port>` and `[::1]:<port>`, plus the `--listen` address when it is not a loopback one (Docker).
- The token in the start URL must not stay in the browser history: redirect to `/step/welcome` right after setting the cookie.
- Do not log request bodies.
- `assets/installer/` must be found both from `tsx` (source) and from `dist` (built, and the Docker image at `/app`): resolve it from the repository root the same way other CLI code finds `assets/`, not from `__dirname` guesses.
- Tests: start the server on port 0 in tests only (the production option forbids a random port), inject the checks and a temporary folder for the file.
- Keep `render.ts` free of I/O so it can be unit tested without the server.

**Out of scope**
- The CLI command, the root script, opening the browser and Docker (TASK-1925).
- Client-side JavaScript of any kind.
