## GROOMING · 2026-10-09T17:53:32Z · claude-opus-5-5 (coordinator)

**Approach**
1. Add `packages/services/src/lyrics/lrclib.client.ts` with an `LrclibClient`, modelled on `WaifuImClient` (`packages/services/src/anime/waifu-im.client.ts`). Constructor options: `baseUrl` (default `https://lrclib.net`), `limiter` (default `new RateLimiter(500)`), `fetchFn`, `maxRetries`, `timeoutMs`. All requests go through `fetchWithRetry` with the header `User-Agent: RirikoBot/2.0 (+https://github.com/RirikoAI/RirikoBot)` and `Accept: application/json`. LRCLIB asks clients to name themselves this way. Export the client and its result type from `packages/services/src/lyrics/index.ts` and from `packages/services/src/index.ts`.
2. Client methods:
   - `findForTrack({ title, artist, durationSeconds })`: call `GET /api/get?track_name=&artist_name=&duration=`. A 404 means no match. Then call `GET /api/search?track_name=&artist_name=` and take the first result whose `duration` is within 3 seconds of `durationSeconds`. When the duration is 0 or missing, leave `duration` out of `/api/get` and take the first search result.
   - `search(query)`: call `GET /api/search?q=` and return the first result, or null.
   - Map the raw JSON to `{ id, trackName, artistName, albumName, durationSeconds, instrumental, plainLyrics, syncedLyrics }`. Every non-404 error status throws, so the caller can tell "no lyrics" from "LRCLIB is down".
3. Wire one `new LrclibClient({ maxRetries: 1, timeoutMs: 5000 })` into `createBotServices` and `BotServices` (`apps/bot/src/services.ts`). This matches how `waifuImClient` is wired at line 544.
4. Add `apps/bot/src/commands/music/lyrics.ts`. It holds the shared code: build the lookup from a queued track (`PrecisionTrackMatcher.cleanTitle(track.title)`, and `track.artist` with a trailing ` - Topic` removed), turn a result into embeds, split long text, and produce the failure messages. `/lyrics` in `commands.ts` (around line 640) and the `music_lyrics` case in `music-embed.controller.ts` (around line 655) both call it.
5. `/lyrics` calls `ctx.deferReply()` before the lookup and replies with the embeds. The button keeps its `deferReply({ ephemeral: true })` and `editReply` pattern.
6. Update `docs/music.md` (the `/lyrics` row and the note on line 239) and the lyrics row in `docs/legacy-feature-inventory.md`.

**Pitfalls**
- Checked live on 2026-10-09. `GET /api/get` works without `album_name`. A miss returns HTTP 404 with `{"name":"TrackNotFound"}`. `/api/search` returns a JSON array. Anime and J-pop coverage is reasonable: "YOASOBI Idol" was found.
- `/api/get` and `/api/search` can return `plainLyrics: null` with `instrumental: true`. Show an "instrumental" reply, not an empty embed.
- Some entries have only `syncedLyrics`. Remove the `[mm:ss.xx]` prefixes before you show them.
- Discord limits: 4096 characters per embed description, 10 embeds per message, 6000 embed characters in total, 256 characters per title. Split on `\n`, never in the middle of a line. Truncate track names in titles.
- Tests must not use the network (offline test rule since #658). Inject `fetchFn` in the client tests, and mock the client on the services object in the bot tests.
- `commands.test.ts` builds real services with an SQLite database. Look at how its helpers create `services` before you add the mock client, so other music tests keep passing.
- The prefix path (`!ly <text>`) goes through the same `execute`. Check that `ctx.deferReply` works for prefix contexts, as it does for `/play`.

**Out of scope**
- Lavalink's LavaLyrics endpoints. Lavalink is optional, and LRCLIB works in both player modes.
- Synced karaoke display that follows playback, and a select menu for several search results.
- The unused `music_guild_settings.lyrics_provider` column and its schema. Leave it as it is.
- Genius, Musixmatch or any other provider that needs a key or scraping.
