## 2. Key Deliverables & Implemented Architecture

### 2.1. Centralized 5-Tier `PermissionService`
Implemented in `packages/services/src/moderation/permission.service.ts`:
- **Tier 1 (Invoker Discord Permissions)**: Validates required bitfields (e.g. `KickMembers`, `BanMembers`, `ModerateMembers`, `ManageChannels`, `ManageNicknames`). Bypasses check if the invoker is the Guild Owner (`invoker.id === guild.ownerId`).
- **Tier 2 (Bot Discord Permissions)**: Confirms Ririko bot account has requisite permissions at guild and channel levels.
- **Tier 3 (Role Hierarchy & Self-Protection)**:
  - Strict check that invoker's highest role is strictly above target member's highest role.
  - Strict check that Ririko's highest role is strictly above target member's highest role.
  - Blocks self-moderation (`CANNOT_MODERATE_SELF`).
  - Protects server owner (`TARGET_IS_OWNER`).
  - Blocks moderating Ririko bot itself.
  - Supports `skipHierarchyCheck` for non-member actions (e.g. unban by user ID, channel lock).
- **Tier 4 (Guild Module Policy)**: Verifies moderation module status against `GuildSettings`.
- **Tier 5 (Channel Overrides)**: Inspects channel permission overwrites for channel-targeted moderation.

### 2.2. Discord Punitive Actions Core (`ModerationActionService`)
Implemented in `packages/services/src/moderation/moderation-action.service.ts`:
- Standardized methods for all core punitive actions:
  - `kick(params: KickParams)`: Kicks member, formats audit reason, sends DM notification (with safe error handling), creates database case, and emits event.
  - `ban(params: BanParams)`: Supports `GuildMember` or raw user ID string, message purge calculations (`deleteMessageDays` $\to$ `deleteMessageSeconds`), DM notification, database case, and event emission.
  - `softban(params: SoftbanParams)`: Bans member to purge message history (1-7 days) and immediately unbans them with structured audit reason.
  - `unban(params: UnbanParams)`: Revokes active ban for target user ID.
  - `timeout(params: TimeoutParams)`: Applies communication timeout with clamped duration bounds (1s to 28 days), formatted DM, and database case.
  - `untimeout(params: UntimeoutParams)`: Removes active timeout early.
  - `setNickname(params: NicknameParams)`: Changes or resets offensive/unrenderable member nickname.
  - `lockChannel(params: LockChannelParams)`: Edits `@everyone` permission overwrite to deny `SendMessages`.
  - `unlockChannel(params: UnlockChannelParams)`: Resets `@everyone` permission overwrite for `SendMessages`.

### 2.3. Dual-Dialect `ModerationRepository`
Implemented in `packages/database/src/repositories/moderation.repository.ts`:
- Atomic sequential per-guild case numbering: `getNextCaseNumber(guildId)` (`MAX(case_number) + 1`).
- Case creation and retrieval (`getCaseByNumber`, `getCaseById`, `listCases` with pagination and filters).
- Active warning tracking with automatic expiration filtering (`getActiveWarnings`, `clearUserWarnings`, `deactivateWarning`).
- Staff notes management (`createNote`, `getNotesByUser`, `deleteNote`).
- AutoMod rules persistence (`getRules`, `upsertRule`, `getRuleByType`).

### 2.4. Core Event Bus Integration
Added moderation events to `CoreEvents` in `packages/core/src/events/types.ts`:
- `'moderation:actionExecuted'`: Dispatched upon every successful punitive action.
- `'moderation:warningIssued'`: Dispatched when warnings are issued.
- `'moderation:caseCreated'`: Dispatched when a sequential case is registered in the database.
