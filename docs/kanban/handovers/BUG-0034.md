## GROOMING · 2026-10-04T22:19:37Z · Claude Code (Opus 5.5)

**Failure** (live, ririko-staging, Ubuntu 24.04, GNU tar 1.35)
```
[bootstrap] downloading deploy/host from https://codeload.github.com/RirikoAI/RirikoBot/tar.gz/feat/STORY-180-remote-lavalink
tar: */deploy/host/*: Not found in archive
tar: Exiting with failure status due to previous errors
[bootstrap] ERROR: feat/STORY-180-remote-lavalink has no deploy/host directory
```

**Approach**
1. In `fetch_release_tree` (`deploy/host/bootstrap.sh`), call `tar -xzf ... --strip-components=1 --wildcards '*/deploy/host'` with that one member. Keep the `die` messages.
2. Make the extraction testable:
   - Either move the tar call into a small function that a test can run through `bash -c` by sourcing the script behind a `[[ ${BASH_SOURCE[0]} == "$0" ]]` guard around the run section,
   - or have the test run the identical tar command line.

   The first option keeps the test honest when the script changes; prefer it if the guard stays simple.
3. Test: build the fixture archive with Node (`tar` CLI via `spawnSync`) in a temp directory: `RirikoBot-abc123/deploy/host/files/daemon.json`, `.../bin/x.sh`, and `RirikoBot-abc123/README.md`. Extract it, then assert `deploy/host/files/daemon.json` exists and `README.md` does not.

**Pitfalls**
- Windows' `tar.exe` is bsdtar, which does not know `--wildcards`. Detect it with `tar --version` (GNU prints "GNU tar") and skip with a reason there. CI (Linux) and WSL use GNU tar.
- Keep `--strip-components=1`: codeload archives have one top-level `<repo>-<ref>` directory.

**Out of scope**
- Anything else in `bootstrap.sh`. The coordinator re-runs it live after the fix and opens new bugs for further findings.
