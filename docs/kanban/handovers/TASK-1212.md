**Approach**
1. Write `.dockerignore`. Exclude only generated, secret and private paths:
   - `node_modules`, `**/dist`, `**/.next` and `*.tsbuildinfo`
   - `.git`, `.env*`, `.local/` and `.codegraph/`
   - `data/`, `storage/`, `public/cards/` and `public/bosses/`
   - `lavalink/` and `packages/music-private/`
   - `coverage/`, `test-results/`, `apps/web/e2e-results/` and `site-dist/`
   Keep `assets/`, `tests/` and every workspace package.
2. Write the root `Dockerfile` with these stages:
   - `base`: `node:22-bookworm-slim`, `WORKDIR /app`, `COREPACK_ENABLE_DOWNLOAD_PROMPT=0` and `corepack enable pnpm`. The version comes from `packageManager` (pnpm 10.8.1).
   - `build`:
     - Copy the manifests first: `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `.npmrc` and every `apps/*/package.json` and `packages/*/package.json` (not `music-private`).
     - Run `pnpm install --frozen-lockfile` with `HUSKY=0`.
     - Copy the source and run `pnpm build` (`tsc -b`; this builds the packages, the cli and the bot).
   - `bot-deps`: manifests only, then `pnpm install --prod --frozen-lockfile --ignore-scripts --filter @ririko/bot...`.
   - `runtime`: `node:22-bookworm-slim` plus `tini`, `fonts-dejavu-core` and `ca-certificates`, installed with `--no-install-recommends` and the apt lists removed. Create group and user `ririko` with uid/gid 10001 and no login shell. Set `NODE_ENV=production` and `HOME=/tmp`.
   - `bot-runner`: `runtime` plus `ffmpeg`. Copy:
     - From `bot-deps`: the root `node_modules` (the `.pnpm` store) and each `node_modules` folder under `apps/bot` and the six packages it uses (`core`, `database`, `discord`, `music`, `ai`, `services`).
     - From `build`: each `dist`.
     - From the context: each `package.json`, plus root `package.json`, `pnpm-workspace.yaml` and `assets/`.
   - In `bot-runner`, create `data`, `public/cards`, `public/bosses` and `storage/welcomer-backgrounds` and `chown 10001:10001` only those. Finish with `USER 10001:10001`, `ENTRYPOINT ["/usr/bin/tini", "--"]` and `CMD ["node", "apps/bot/dist/main.js"]`, with `WORKDIR /app`.
3. Write `scripts/docker-smoke.ts`:
   - Zero dependencies, run as `node scripts/docker-smoke.ts <bot|web>...`. Node 22 strips types, as with `scripts/build-status-site.ts`.
   - It shells out to `docker` and checks the already-built `ririko-bot:smoke` image:
     - `id -u` prints 10001.
     - The four data directories are writable. A file under `/app/apps` or `/app/packages` is not.
     - `ffmpeg -version` succeeds.
     - A run with `--cap-drop ALL --security-opt no-new-privileges -e DISCORD_TOKEN=dummy -e DISCORD_CLIENT_ID=1` prints `✓ Registered`.
   - Put the `web` checks in their own function so TASK-1211 can fill them in. For the boot check, stop the container once the line appears or after a timeout. Make sure it never needs network access to pass.
4. Rewrite `docs/deployment.md` section 2.1 to match the stages. Cover the build and run commands, the writable directories, and volume ownership: named volumes inherit 10001, and bind mounts must be chowned on the host. Leave section 2.2 (compose) to STORY-122.

**Relevant code** (from CodeGraph during grooming)

  - `public/cards` (`card-image.service.ts:10`) and `public/bosses` (`boss-synthesizer.ts:12`).
  - `storage/welcomer-backgrounds` (`background-store.ts:16`).
  - `data/` (SQLite, and the `data/tcg/images` art cache that card assets point at).

**Pitfalls**
- Prod installs:
  - Pass `--ignore-scripts`: the root `prepare: husky` script fails when devDependencies are missing.
  - Set `HUSKY=0` in the build stage too.
  - pnpm 10 already skips dependency build scripts (`protobufjs` and `@google/genai` are in `ignoredBuilds`), and none are needed at runtime.
- pnpm does not hoist (`shamefully-hoist=false`):
  - `@ririko/*` and their dependencies resolve through per-package `node_modules` symlinks into `/app/node_modules/.pnpm`.
  - Copy those trees to the same paths so the relative symlinks still resolve.
  - Check with a run, not by reading the Dockerfile.
- The manifest COPY list names every workspace package. Adding a package later breaks the build until the list is updated. TASK-1213's CI job catches this.
- fontconfig writes a cache under `$HOME`. The `ririko` user has no home directory, so set `HOME=/tmp` or canvas logs warnings.
- tini must be PID 1:
  - FFmpeg child processes need reaping.
  - `main.ts` handles SIGTERM for graceful shutdown.
- FFmpeg from bookworm is large. Report both image sizes (`docker image ls`) in the PROGRESS entry. There is no hard size limit.
- Docker on this machine is Docker Desktop with a Linux engine. Run `docker` from the Bash tool or PowerShell. In Git Bash, a PATH entry with a space can break a bare `docker` call, so use the full path or PowerShell if that happens.
- Never copy, mention or document `packages/music-private` in the Dockerfile or the docs, beyond excluding it in `.dockerignore`.

**Out of scope**
- The `web-runner` target and the `web` smoke checks (TASK-1211).
- The CircleCI job (TASK-1213).
- These belong to STORY-122:
  - Compose and docs section 2.2.
  - Health probes and `HEALTHCHECK`.
  - Lavalink.
  - Postgres schema setup.
- Code changes in `apps/` or `packages/`. If one seems necessary, set `BLOCKED` and explain why.

**Decisions & gotchas**
- `DATABASE_URL` is set in the image. Without it, `createBotServices` (`apps/bot/src/services.ts:332`) falls back to `sqlite:storage/ririko.db`. Every other entry point (`AppConfigSchema`, cli, scripts, `.env.example`) uses `./data/ririko.sqlite`. In a container that fallback would put the bot's database outside the `data` volume and away from the dashboard's. This is pre-existing and outside this ticket, so it is reported to the coordinator. A BUG ticket is suggested.
- No `# syntax=` directive: the built-in BuildKit frontend already supports `RUN --mount=type=cache`, so the build needs no extra image pull.
- pnpm installs both the glibc and musl prebuilds of `@napi-rs/canvas` and `@snazzah/davey`. Pinning `supportedArchitectures.libc` in `pnpm-workspace.yaml` would save about 30 MB, but it changes how the whole workspace installs, so it was left alone.
- The FFmpeg layer is the bulk of the image. A static FFmpeg binary would mean downloading from a third party, so Debian's package stays.
- In PowerShell 5.1, double quotes inside `sh -c '...'` arguments get mangled. The smoke script passes arguments through `spawnSync` arrays and has no such problem.
