## GROOMING · 2026-10-02T15:41:07Z · Claude Code (Opus 5.5)

**Approach**
- Add three rules to `applyLegacyAliases` (`packages/core/src/config/schema.ts:118`). An alias never overrides a value that is already set.
  - `AI_SERVICE_TYPE` sets `DEFAULT_AI_PROVIDER`.
  - `AI_SERVICE_DEFAULT_MODEL` sets `DEFAULT_AI_MODEL`.
  - `AI_SERVICE_API_KEY` sets `GEMINI_API_KEY` or `OPENAI_API_KEY`, chosen by the type.
- Export the alias function from `@ririko/core`. `main` applies it to `process.env` once, so `main.ts` and `services.ts`, which read `process.env` directly, see the same values.
- Add a pure old-layout check in a small `apps/bot/src` module. It takes the env, the data directory and file-system functions, and returns the upgrade lines or null. It triggers when any of these is true:
  - `DATABASE_NAME` is set.
  - A `ririko.db` is in the 2.0 data directory.
  - The data directory is not writable.
- `main` prints the lines and exits 1 before `createDatabaseClient` and before the health server starts.
- Add a smoke case in `scripts/docker-smoke.ts`. It copies `botLegacyUpgradeCheck` (line 353): a root-owned `/app/data` with a `ririko.db`. It expects the message and a non-zero exit.

**Relevant code**
- `apps/bot/src/main.ts:31-69`: startup order.
- `packages/database/src/client/sqlite.ts:10` `resolveDatabasePath`, and `:17` `createSqliteClient`, which creates the directory.
- `apps/bot/src/legacy-upgrade.ts`: the `/app/legacy` path that the upgrade lines point to.

**Pitfalls**
- Skip the file checks for Postgres URLs and `:memory:`.
- Tests must not need Docker. Only the smoke case uses Docker.

## PROGRESS · 2026-10-02T15:53:16Z · Claude Code (Opus 5.5) · REVIEW

**Files changed**
- `packages/core/src/config/schema.ts`: `applyLegacyAliases` is exported and rewritten around a small `alias` helper. It adds the 1.4.0 `AI_SERVICE_*` mapping:
  - `google_ai` goes to Gemini, `openai` and `openrouter` go to OpenAI, and `ollama` goes to Ollama.
  - OpenRouter runs on the OpenAI provider with `https://openrouter.ai/api/v1`, the 1.4.0 default.
  - `AI_SERVICE_BASE_URL` goes to `OPENAI_BASE_URL` or `OLLAMA_BASE_URL`.
- `packages/core/src/config/legacy-aliases.test.ts` (new).
- `apps/bot/src/legacy-layout.ts` (new): `findLegacyLayout` and `describeLegacyLayout`. `apps/bot/src/legacy-layout.test.ts` (new).
- `apps/bot/src/main.ts`: `main` first applies the aliases to `process.env`, then runs the old-layout check. It exits 1 before the database, the health server or the bot is created.
- `scripts/docker-smoke.ts`: `withContainer` takes extra `docker create` arguments. The new `botOldLayoutCheck` seeds a root-owned volume with `ririko.db` at `/app/data` and sets `DATABASE_NAME`. It expects all three reasons, a non-zero exit, and an unchanged volume.

**Verification**
- `pnpm vitest run packages/core/src apps/bot/src`: 68 files, 671 tests pass.
- `pnpm typecheck`, `pnpm build` and `pnpm lint --quiet` pass.
- `docker build --target bot-runner -t ririko-bot:smoke .` and `node scripts/docker-smoke.ts bot`: 7 of 7 checks pass, including the new one.
- `pnpm test:coverage`: 2699 tests pass and every threshold holds.

**Decisions & gotchas**
- The old-layout check walks up to the closest directory that exists, so a fresh install without `./data` passes.
- The legacy `AI_PROVIDER` and `AI_DEFAULT_*` names still win over `AI_SERVICE_*` when both are set.
- `DATABASE_TYPE` alone does not trigger the check. In the 1.4.0 compose files it always comes with `DATABASE_NAME`.
- `build` must run before `typecheck` when core exports change, because the bot typechecks against `@ririko/core` dist.
