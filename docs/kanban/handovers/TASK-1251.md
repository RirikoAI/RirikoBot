## FLAG · 2026-10-03T08:01:00Z · from TASK-1251 · ticket-worker (Sonnet 5.5)

**Finding 1 (fixed in this ticket, real bug)**: `AiRepository.create` and `addMessage` generated `conv_<uuid>` and `msg_<uuid>` ids, and `getOrCreateConversation` passed `conv_<uuid>` explicitly (`packages/database/src/repositories/ai.repository.ts`). On Postgres `ai_conversations.id` and `ai_messages.id` are `uuid` columns, so every AI conversation and message insert through `ConversationManager` failed with `invalid input syntax for type uuid`. Fix: `newId(client, prefix)` keeps the prefixed id on SQLite and uses a plain uuid on Postgres, and `getOrCreateConversation` no longer passes its own id. Covered by `ai.repository.behaviour.test.ts` on both dialects. **Impact**: the AI channel was broken on Postgres; worth a BUG ticket for the changelog.

**Finding 2 (not fixed)**: `DungeonSeasonRepository.create` falls back to `randomUUID()` (36 characters) for a missing id, but `dungeon_seasons.id` is `varchar(32)` on Postgres, so a season created without an id fails there (`packages/database/src/repositories/dungeon.repository.ts:125`). Callers always pass an id today, so it is latent. Fix when touched: widen the column or generate a short id.

**Finding 3 (not fixed)**: `CommandSettingsRepository.listForGuild` orders by `asc(channelId)`; NULL sorts first on SQLite and last on Postgres (`packages/database/src/repositories/command-settings.repository.ts`). Guild-wide overrides therefore appear above or below channel ones depending on the database. Add explicit NULL ordering if the order matters.

**Finding 4 (not fixed, outside this ticket)**: `packages/services/src/waifu-tcg/__tests__/rarity-and-card-generator.test.ts` "should scale stats according to rarity multiplier" failed once in a full run (`expected 170 to be greater than 181`, COMMON versus MYTHIC defense) and passed in six reruns. It uses unseeded random stats, so it is flaky and can fail the coverage gate (AGENTS.md section 8.3 requires deterministic seeds).
