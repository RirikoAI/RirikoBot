## GROOMING · 2026-10-23T15:52:42Z · claude-opus-5-5 (coordinator)

**Approach**
1. In `board-lib.mjs` add `stamp(ticket, actor)` that sets `updated_at = nowIso()` and `last_actor = { name, role, model, tier }`, where tier comes from `tiersOfModel(model)`. Call it from every write in `ticket.mjs`.
2. Add the `create`, `groom`, `edit` and `status` commands, and the `note --type GROOMING --edit <n> | --delete <n>` options. Number the grooming entries 1..n in file order.
3. An edit or delete keeps the log honest: the entry is rewritten (or replaced by "Removed: <reason>") and an `## AMEND · <time> · <agent> (<model>) · EDITED|DELETED` entry is appended, quoting the old text.
4. claim appends `{ worker, model, tier, claimed_at }` to `claims`; handover and recover close it with `released_at` and `outcome` (the new status).
5. `migrateBoard` in `bin/scrum-kanban.mjs` backfills the fields.

**Pitfalls**
- Coordinator commands (groom, edit, status, GROOMING notes) keep the large-tier check that `requireTier` already does.
- Keep the all-or-nothing write in `commit()`: a failed render undoes every file.
- The ID scheme differs per project (Ririko uses TASK-2031 and BUG-0053). `create` finds the next free number per type from the existing IDs and keeps their width.
