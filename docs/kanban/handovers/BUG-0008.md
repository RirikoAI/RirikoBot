# BUG-0008 Handover: Fix Waifu TCG Tutorial False Completion, Missing Starter Card Seed & $climb Route

## 1. Problem & Root Cause Analysis
1. **False Tutorial Completion & Foreign Key Error**:
   - `TutorialService.completeTutorial()` previously immediately recorded `highestClearedFloor = 4` in `season_tutorial` before attempting to insert `starter_waifu_01` into `user_cards`.
   - `starter_waifu_01` was never seeded into `waifu_cards`, causing SQLite to reject the insert due to `PRAGMA foreign_keys = ON;`.
   - The user remained with 0 cards while their `season_tutorial` progress was flagged as completed (Floor 4).
   - Any subsequent call to `/dungeon tutorial` emitted `You have already completed the Tutorial Prologue!` despite no cards or battles ever occurring.
2. **`$climb` Skipped Tutorial & Prefix Alias Parsing**:
   - Running `$climb` (or `/dungeon climb`) directly challenged the seasonal tower (`Season 1: Infernal Crucible`) instead of onboarding new summoners through the 4-floor Prologue Tutorial (`season_tutorial`).
   - In prefix dispatch, `$climb` (an alias of `dungeon`) had empty `rawArgs`, defaulting `action` to `'status'`.

## 2. Completed Changes
1. **Starter Waifu Card Seeding & Self-Healing (`services.ts`, `db-reset.ts`, `tutorial-service.ts`)**:
   - Seeded `starter_waifu_01` (`Flame Novice Aria [FIRE]`, Common, Lv.1) into `waifu_cards` in `services.ts` and `scripts/db-reset.ts`.
   - Implemented `ensureStarterCard(userId)` on `TutorialService` to ensure `starter_waifu_01` exists and is granted to the user in `EQUIPPED` state if they have no cards.
2. **Tutorial Enemy Bosses & Wards in `DungeonRunner` (`dungeon-runner.ts`)**:
   - Updated `DungeonRunner.runFloor` to detect `isTutorial` (`seasonId === 'season_tutorial'`).
   - Mapped enemies directly to `TUTORIAL_FLOORS[floorNumber - 1].dummyEnemy`.
   - Added `ElementalWard` (FIRE) on Floor T4 to teach multi-elemental shield breaking.
   - Enforced 0 energy consumption on tutorial runs and skipped regular seasonal loot tables.
3. **Tutorial Gate & Prefix Alias Resolution in `DungeonCommand` (`dungeon.command.ts`)**:
   - Detected `$climb` prefix alias using `ctx.source === 'prefix'` and `ctx.raw.content`.
   - Added Tutorial Gate to `case 'climb'`: if `tutorialProgress.highestClearedFloor < 4`, automatically routed to `handleTutorialClimb` for the current tutorial floor (T1..T4).
   - Updated `case 'tutorial'`: runs the next incomplete tutorial floor if `< 4`, or shows the completed status if `>= 4`.
   - Rendered dedicated tutorial battle embeds with tactical guide messages, combat highlights, and next floor directions.
4. **Database State Cleanup (`data/ririko.sqlite`)**:
   - Reset `user_dungeon_progress` for owner (`1257377848671600722`) to `highest_cleared_floor: 0, clear_count: 0, attempts_count: 0` in `season_tutorial`.
   - Verified `starter_waifu_01` is seeded in `waifu_cards`.
