## 1. Why this task exists (audit findings, 2026-09-28)
- **Global rules are stored but ignored.** `tcg_system_configs` keys and ranges are in [tcg-config.service.ts](file:///Z:/Projects/ririko-v2-2026/packages/services/src/waifu-tcg/admin/tcg-config.service.ts) (:4-34). What runtime actually uses:

  | Rule | Stored key | Runtime today |
  |---|---|---|
  | Market tax | `market_tax_rate` (0-0.5, default 0.05) | `MarketService` built without options (`apps/bot/src/services.ts:855-861`), falls back to 0.05 (`market-service.ts:53-54,86-87`) |
  | Listing expiry | none | hardcoded 7 days (`market-service.ts:53-54`) |
  | Energy cap / base / scaling | `global_max_energy_cap`, `base_energy_capacity`, `energy_scaling_per_level` | `calculateMaxEnergy` hardcodes `100 + (level-1)*2` + milestone, capped at `DEFAULT_GLOBAL_ENERGY_CAP=300` (`energy-lifecycle.service.ts:4,15-21`); `globalCap` option (:91) never passed |
  | Daily restore-pot limit | `daily_energy_restore_pot_limit` | `inventory.service.ts:302` uses `metadata.dailyUsageCeiling ?? 3`; `consumable-service.ts:11` hardcodes `DAILY_ENERGY_POTION_CAP = 3` |
  | Bonus energy | `max_bonus_energy_cap`, `daily_bonus_energy_increment` | consumed via `bonusConfigResolver` (`services.ts:437-443`) |

- Hardcoded "5%" and "7-day" are also in user text: `market.command.ts:13,102`, `info.command.ts:251,337,406`.
- **Privilege bug.** `/tcg-admin` ([admin.command.ts](file:///Z:/Projects/ririko-v2-2026/apps/bot/src/commands/tcg/admin.command.ts) :100-123) authorizes any guild Administrator/ManageGuild, who can then set global energy (:160-189), dungeon (:223-235) and market tax (:276) keys for every guild.
- **No audit.** `TcgConfigService.setConfig` writes no `audit_logs` row and uses no transaction.
- `tcg_system_configs` also holds per-user state rows (`tutorial:floor4:<user>`, `dungeon:progress:<season>:<user>`), so never list "all configs" as rules.
