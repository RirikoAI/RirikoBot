## GROOMING · 2026-10-21T15:45:00Z · claude-opus-5-5 (coordinator)

**Approach**
1. `apps/web/src/app/dashboard/[guildId]/tickets/page.tsx` and `actions.ts`, copied in shape from `logging/` (a single `SettingsForm` and a `saveGuildSettings(guildId, 'tickets', pickFormFields(formData, [...]))` action). Look at `autoroles/page.tsx` for the on/off switch and role list fields.
2. `guild-resources.ts`: add a `categories(guildId)` method on `GuildResourceDirectory`. The code at line 137 already filters `ChannelType.GuildCategory` to label text channels, so reuse that fetch.
3. `guild-pickers.tsx`: add `CategorySelectField` next to `ChannelSelectField` (line 19).
4. `dashboard-nav.ts`: `{ slug: 'tickets', label: 'Tickets', group: 'members' }` after Reaction Roles.

**Relevant code**
- `apps/web/src/app/dashboard/[guildId]/logging/page.tsx` and `actions.ts`: the whole pattern in about 50 lines.
- `apps/web/src/lib/server/authorization-coverage.test.ts`: lists every dashboard action and fails when one is not covered.

**Pitfalls**
- Settings pages need no passkey step-up. Only the actions that send messages as Ririko (reaction-role panels) do. Do not add one here.
- The form posts strings. The `tickets` schema helpers turn `""` into null and `"on"` into true, so do not convert values in the action.

**Out of scope**
- Posting the panel from the dashboard, and listing open tickets. Both are follow-ups (see the STORY-198 note).
