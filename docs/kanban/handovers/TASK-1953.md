## GROOMING · 2026-10-18T09:50:00Z · claude-opus-5-5 (coordinator)

The STORY-195 GROOMING note section 3 is the design spec: hero, Meet Ririko, section navigator, scroll and Docusaurus rules. Follow it closely. It answers the maintainer's brief, so do not swap in a different layout.

**Approach**
1. Restructure `website/src/pages/index.tsx` into five `<section>`s with ids `hero`, `meet`, `abilities`, `open-source`, `get-started` inside `<main>`. Keep the `Layout` title and description. Move the current feature grid into `#abilities`, the stats into the hero cover lines and the FAQ into `#get-started`; give `#open-source` its h2 and one true line about MIT and Docker with a link to `/docs/deployment`. TASK-1954 rebuilds those three sections.
2. Hero per the spec. Keep the `<link rel="preload">` for `ririko-hero.webp` with `fetchPriority="high"`; use `<img>` with width and height attributes, `alt=""` (decorative; the h1 names the product) and `decoding="async"`.
3. Meet Ririko per the spec. Read `website/src/components/DiscordDemo/script.ts` and `reply.ts` to list the commands the demo answers; write them as inline `<code>` in the "Try:" line.
4. `website/src/components/SectionNav/` (`index.tsx`, `styles.module.css`): prop `sections: { id: string; label: string }[]`. IntersectionObserver with a centre band (for example `rootMargin: '-45% 0px -50% 0px'`) sets the active id; render anchors `href="#id"` with `aria-label` "Go to section: <label>" and `aria-current="true"` on the active one. Disconnect the observer on unmount.
5. Gummy edge: one reusable class (mask with a repeating radial gradient) used at the bottom of the hero.
6. Scroll snapping and the html class per the spec. Then build and check the built CSS (`website/build/assets/css/*.css`) has no unscoped `html{` or `body{` rule from the home page.
7. Look at the page: `pnpm docs:build && pnpm docs:serve -- --port 3100` (port 3000 may be the dashboard dev server). If a browser tool is available, check 390, 768, 1280 and 1920 px wide, and Tab through the hero and the navigator. Record what you checked in the PROGRESS entry.

**Relevant code**
- `website/src/pages/index.tsx`: `Hero`, `MeetRiriko`, `Stats`, `Home`; constants `SUPPORT_SERVER` and `GITHUB` (reuse them).
- `website/src/pages/index.module.css`: current hero overlay and meet band (replace).
- `website/src/data/commands.json`: `commands.length` (117) and `categories.length`.
- The STORY-195 tokens are `--ririko-*` custom properties in `website/src/css/custom.css` (TASK-1951).

**Pitfalls**
- `min-height` with `svh`, never a fixed `height`: content must grow when text is zoomed.
- The navbar is sticky: anchors need the html `scroll-padding-top` (or `scroll-margin-top`).
- `onBrokenAnchors: 'throw'` checks in-page anchors too.
- Do not edit `website/src/components/DiscordDemo/`.

**Out of scope**
- The final design of abilities, open source and get started (TASK-1954).

**Decisions & gotchas**
- The ticket says the sections sit in `<main>`: `Layout` renders a `div`, so the page supplies the `<main>` (the old file nested a `<main>` in a `div` too).
- `aria-current="location"` on the active dot (AC says `aria-current`; `location` is the value for a position in the page).
- Do not use `pnpm docs:serve -- --port N`: the extra `--` reaches docusaurus and it fails. Run `npx docusaurus serve --port 3100 --no-open` in `website/`.
- The hero art is decorative (`alt=""`); the h1 names the product.
