## GROOMING · 2026-10-04T18:58:43Z · Claude Code (Opus 5.5)

**Approach**
1. Add `--role` to `bootstrap.sh` and branch only where the roles differ: timers, directories, deploy keys, nftables.
2. Keys: `umask 077; wg genkey > /etc/wireguard/private.key` only when missing; print `wg pubkey < private.key`.
3. Config in `ririko.conf`:
   - `WG_ADDRESS=10.77.0.1/24`
   - `WG_LISTEN_PORT=51820` (lavalink role)
   - `WG_PEERS` as lines `<public key> <allowed /32> [<endpoint host:port>]`
   - `WG_ALLOWED_ENDPOINTS` as the Lightsail static IPs (lavalink role)
4. Rendering functions in `deploy/host/lib/render-wireguard.sh` and `render-nftables.sh`, sourced by `bootstrap.sh`. Validate keys (44-character base64 ending in `=`) and addresses before writing anything.
5. nftables: write `/etc/nftables.d/ririko.nft` with `table inet ririko`, load it with `nft -c -f` then `nft -f`, and enable a small systemd unit (or `include` from `/etc/nftables.conf` without `flush ruleset`).

**Pitfalls**
- Ubuntu's default `/etc/nftables.conf` starts with `flush ruleset`. Loading it after Docker starts wipes Docker's NAT rules. Never use the global flush; delete and recreate only `table inet ririko`.
- Allow established and related traffic first, or the host loses its own outbound connections (apt, Docker Hub, cloudflared).
- The VPS provider may have no network firewall in front of the VPS; nftables is the only boundary, so the default must be drop.
- Lightsail's firewall is stateful, so WireGuard replies to the outbound keepalive come back in without an inbound rule.
- Test on Windows too: the render functions must not depend on GNU-only flags beyond what Git Bash has.

**Out of scope**
- Deploy and watchdog changes (TASK-1803).

## GROOMING · 2026-10-04T20:34:29Z · Claude Code (Opus 5.5)

**Facts from the staging host**
- `ririko-staging` has the static IPv4 `100.29.245.110` and the IPv6 `2600:1f18:4c47:6400:3e2b:8fe7:5b9a:6b09`. Both are its outbound addresses. Lightsail changes the IPv6 only when IPv6 is disabled and re-enabled.
- A Lightsail host prefers IPv6 when the WireGuard endpoint resolves to an IPv6 address, so its packets then come from the IPv6 address. Either:
  - set `Endpoint` to the VPS's IPv4 literal on the app hosts, or
  - let `WG_ALLOWED_ENDPOINTS` take IPv4 and IPv6 entries and render both an `ip saddr` and an `ip6 saddr` rule.

  Prefer the IPv4 literal; still validate and support both families in the renderer.
