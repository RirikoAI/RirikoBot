## GROOMING · 2026-10-21T15:45:00Z · claude-opus-5-5 (coordinator)

**Approach**
1. Add `packages/database/src/schema/sqlite/tickets.ts` and `pg/tickets.ts` with `ticketSettings` and `tickets`, following `giveaways.ts` on each dialect (text UUID ids, `timestamp_ms` integers on SQLite, the same column names on both). Export them from each `schema/*/index.ts`, and add `Ticket`, `NewTicket`, `TicketSettings` and `NewTicketSettings` to `schema/types/index.ts` next to `Giveaway` (line 92).
2. Run `pnpm db:generate` (root `package.json` line 25). It writes the SQL under `packages/database/migrations/{sqlite,pg}`, the embedded modules and both `ddl.ts` files. Review the SQL: it must only create tables and indexes.
3. Write `ticket.repository.ts` on `BaseRepository` like `giveaway.repository.ts` (an `isSqlite(client)` branch per method, every method takes an optional `tx`). For `upsertSettings`, copy the `onConflictDoUpdate` pattern in `autorole.repository.ts` `upsertGuildAutoRoles`. `openTicket` runs in `withTransaction` when no `tx` is given: read or create the settings row, take `next_number`, increment it, insert the ticket, and return it.
4. Export from `repositories/index.ts`.
5. Add both tables to `GUILD_DATA_INVENTORY` (`guild-data-inventory.ts` line 44, next to `giveaways` at line 71) and the three user columns to `USER_DATA_INVENTORY` (`user-data-inventory.ts` line 93; see the `moderation_cases` tombstone entries near line 188 for the shape, including `clear`).

**Relevant code**
- `packages/database/src/schema/sqlite/giveaways.ts`: table, index and JSON column patterns.
- `packages/database/src/schema/sqlite/utilities.ts:21` `guildAutoRoles`: a per-guild settings table with a JSON role id list, the closest match to `ticket_settings`.
- `packages/database/src/repositories/giveaway.repository.behaviour.test.ts`: how behaviour tests run on SQLite and PostgreSQL.

**Pitfalls**
- `guild-data-inventory.test.ts` and `user-data-inventory.test.ts` read both schemas and fail when a `guild_id` or user-id-looking column is not listed. That is expected; list them.
- `pnpm db:check` fails on stale embedded modules. Commit everything `db:generate` writes.
- Never hand-edit a generated migration.
- `status` is a text column. Keep the values to `open` and `closed`.

**Out of scope**
- The `tickets` guild config module (TASK-1982) and anything under `packages/services` or `apps/`.
