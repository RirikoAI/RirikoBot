## GROOMING · 2026-10-07T13:43:25Z · Claude Code (Opus 5.5)

**Approach**
1. `packages/database/src/copy/copy-database.ts`, exported from the package index: `copyDatabase(sourcePath, target: PostgresDatabaseClient, { batchSize?, dryRun? })` returns a report `{ tables: [{ name, sourceRows, targetRows }], warnings, coinsChecked }`.
2. Source: `new Database(path, { readonly: true, fileMustExist: true })` from better-sqlite3. Do not use `createSqliteClient`, which would auto-create a schema and set WAL pragmas.
3. Target: call `ensurePostgresSchema`, `ensureAdventureSchema` and `ensureCardSerialSchema` (the bot's startup order, `apps/bot/src/main.ts`). Then read `information_schema.columns` and the FK constraints for `current_schema()`.
4. Column conversions:
   - Look up the column in the Drizzle SQLite schema (`packages/database/src/schema/sqlite`) by table and column name. `getTableColumns()` and `getTableName()` from drizzle-orm give each column's mode, such as `integer({ mode: 'timestamp' })` (seconds) versus `'timestamp_ms'`, and `'boolean'`.
   - Use those modes to convert to what the pg column expects.
   - For columns not in the Drizzle schema, fall back to the pg `data_type`.
5. Insert with the pg pool (`target.raw`) using parameterised multi-row INSERTs per batch, inside one transaction.
6. Reset the sequences, verify the counts and the economy sum, then COMMIT.

**Relevant code**
- `packages/database/src/migrations/postgres-schema.ts:11` `ensurePostgresSchema`: creates the schema only when it is empty.
- `packages/database/src/migrations/adventure-schema.ts` and `card-serials.ts`: raw-DDL tables that the Drizzle schema may not cover.
- `packages/database/src/client/sqlite.ts:17` `createSqliteClient`: shows the pragmas; the source must avoid them.
- `packages/database/src/testing/dialects.ts` `describeDialects`: random-schema Postgres suites, run by CircleCI's `test-postgres` job (`TEST_POSTGRES_URL`).

**Pitfalls**
- Bigint balances: `pg` returns int8 as strings, and the source may hold numbers above 2^53. Use better-sqlite3 safe integers (`defaultSafeIntegers(true)` or per statement) and pass the values as strings or BigInt.
- SQLite booleans are 0/1 integers; pg rejects `0` for boolean.
- JSON columns in SQLite are TEXT; pass the text as-is to jsonb instead of parsing and re-stringifying.
- Do not `SET session_replication_role` (it needs superuser and is not portable); use the FK order instead.
- Coverage gate: write real tests. The Postgres suite only runs in CI (WSL is down on the maintainer's machine), so make sure the unit tests cover the helpers locally.

**Out of scope**
- The CLI (TASK-1812).

**Decisions & gotchas**
- Conversion is driven by the target column's `information_schema` data_type; the Drizzle SQLite schema is used only for the timestamp unit (seconds vs milliseconds, via `SQLiteTimestamp.mode`). Every timestamptz column in the current schema is a `timestamp_ms` column; a test plans the whole real pg schema against the whole real sqlite schema, so a future plain-integer-to-timestamptz column fails that test (and the engine refuses it, naming table and column) instead of guessing.
- SQLite integers are read as BigInt (`safeIntegers`) and passed to PostgreSQL as decimal text, so balances above 2^53 stay exact. JSON TEXT goes to jsonb as is. Booleans accept 0/1 only.
- The source is opened `readonly` + `fileMustExist`, with one read transaction (BEGIN) so row counts and rows come from one snapshot; no pragmas are set. A flow test reads rows that only exist in a live WAL and checks the main file's size and mtime do not change.
- Target preparation (ensurePostgresSchema, ensureAdventureSchema, ensureCardSerialSchema) runs before the copy transaction, as the bot does at startup. Refusals (non-empty target, missing table or column, required target column missing, unknown type, FK cycle) throw inside the copy transaction before any INSERT, so only the schema bootstrap has been written. The emptiness check covers every base table of the target schema, not only the copied ones.
- Tables are ordered by Kahn's algorithm over `pg_constraint` foreign keys (ties by name); self references are ignored (no table has one today). The only FK today is adventure_choices to adventure_sessions.
- The economy check sums wallet and bank in JS (BigInt) over the source rows while copying, and compares with `SUM()::text` in PostgreSQL. It runs whenever `economy_balances` is copied (empty tables compare 0 with 0), and is skipped (`coinsChecked: false`) when the source has no such table.
- Sequences: serial/identity columns of copied tables are set with `setval(pg_get_serial_sequence(...), max, true)`; empty tables are left alone; a column with no sequence yields a warning. The schema has no serial or identity columns today, so the integration suite creates a probe identity table to exercise this on a real server.
- `dryRun` runs everything and rolls back (`committed: false`); TASK-1812 can expose it as `--dry-run`.
