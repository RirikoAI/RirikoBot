## GROOMING · 2026-10-01T15:01:55Z · Claude Code (Opus 5.5)

**Approach**
1. Read the TASK-1212 `PROGRESS` entry first. This task builds on its `base`, `build` and `runtime` stages and on `scripts/docker-smoke.ts`.
2. In the `build` stage, after `pnpm build`, run `pnpm --filter @ririko/web build` with `NEXT_TELEMETRY_DISABLED=1`. CircleCI's `build-web` job runs this same command without any env, so the build needs no secrets.
3. Add a `web-deps` stage: copy the manifests, then run `pnpm install --prod --frozen-lockfile --ignore-scripts --filter @ririko/web...`.
4. Add a `web-runner` stage that starts from `runtime`, without FFmpeg. Copy:
   - From `web-deps`: the `node_modules` trees, at the same paths.
   - From `build`: `apps/web/.next` without `.next/cache`, and the `dist` of `core`, `database` and `services` plus any other workspace package the dashboard imports.
   - From the context: each `package.json`, `apps/web/next.config.ts` and the files it imports (`src/lib/security-headers.ts` and that file's imports), `assets/tcg`, root `package.json` and `pnpm-workspace.yaml`.
5. In `web-runner`, create `data`, `public/cards`, `storage/welcomer-backgrounds` and `apps/web/.next/cache` and `chown 10001:10001` only those. Finish with `USER 10001:10001`, `EXPOSE 3000`, tini as entrypoint, `WORKDIR /app/apps/web` and `CMD ["node", "node_modules/next/dist/bin/next", "start", "-H", "0.0.0.0", "-p", "3000"]`. Any equivalent that does not need pnpm at runtime is fine.
6. Fill in the `web` checks in `scripts/docker-smoke.ts` for `ririko-web:smoke`:
   - uid is 10001.
   - The writable directories are writable.
   - With dummy env (`DISCORD_TOKEN`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DASHBOARD_URL=http://localhost:3000` and a 64-hex `SECRET_VAULT_KEY`), started with `--cap-drop ALL --security-opt no-new-privileges`, `GET /` returns 200. Poll from inside the container with `docker exec ... node -e "fetch(...)"`, so no host port is needed.
   - The container logs show no `EACCES`.
7. Extend `docs/deployment.md` section 2.1 with the web target, its env, and the volumes it shares with the bot: `data` (SQLite mode and the card art cache), `public/cards` and `storage/welcomer-backgrounds`.

**Relevant code** (from CodeGraph during grooming)
- `apps/web/next.config.ts`:
  - It loads `../../.env` only when the file exists, so no `.env` is needed in the image.
  - `serverExternalPackages` lists `better-sqlite3`, `pg` and `@napi-rs/canvas`, which Node loads from `node_modules` at runtime.
  - It imports `./src/lib/security-headers`.
- `packages/core/src/config/schema.ts:146` `BaseWebConfigSchema`: requires `DISCORD_TOKEN`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DASHBOARD_URL` and `SECRET_VAULT_KEY` (64 hex characters). `DISCORD_API_URL` must use https, or http only on loopback.
- `packages/services/src/waifu-tcg/album/card-album.service.ts:66` `loadCardImageService`: the dashboard draws album cards with `CardImageService`. It reads `assets/tcg` through `CardSynthesizer`, reads art from `data/tcg/images` or a CDN URL, and writes `public/cards/<id>.png`.
- `packages/services/src/welcomer/background-store.ts:16`: the dashboard writes uploads to `storage/welcomer-backgrounds`.

**Pitfalls**
- `next start` runs from a production-only tree:
  - `typescript`, tailwind and `@playwright/test` are devDependencies and are absent.
  - Confirm that `next.config.ts` still loads (Next transpiles it itself).
  - If it does not, fix it in the Dockerfile, for example by copying the compiled config. Do not turn on `output: 'standalone'`: native-module tracing and `next start` warnings in the E2E job make that a larger change.
- `.next/cache` must exist and be writable. The image optimizer writes there for the Discord CDN avatars allowed in `images.remotePatterns`.
- Check with a run that `@napi-rs/canvas` and `better-sqlite3` resolve from `/app/apps/web`. Both are loaded at runtime because they are listed in `serverExternalPackages`.
- Do not copy `assets/adventure` (117 MB) into the web image. The dashboard does not use it.
- `GET /` may read the database. With the default SQLite URL, the database file is created in `/app/data`, so that directory must be writable.
- Rate limits and the CSP proxy (`src/proxy.ts`) apply to the smoke request too. A single `GET /` is fine.
