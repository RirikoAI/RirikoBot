## 1. Summary of Work Accomplished

### 1.1. Root Cause & Problem
Previously, `player_energy.bonus_energy` existed in the database schema (`integer('bonus_energy').notNull().default(0)`) and was read into energy capacity calculations in four distinct places (`PlayerEnergyRepository.consumePotion`, `EnergyLifecycleService.refundEnergy`, `ConsumableService.useItem`, and `InventoryService.useConsumable`). However, it was only ever written as `0` by the repository constructor. No item, achievement, event, or admin command wrote to it, making it dormant dead data (`maxEnergy + 0`).

### 1.2. Decision & New Mechanic
Per user decision, `bonus_energy` is now activated as an incremental daily progression reward:
- On each daily reset boundary rollover, players accumulate bonus energy:
  $$\text{newBonus} = \min(\text{maxBonusCap}, \text{currentBonus} + \text{dailyIncrement})$$
- The player's active stamina is replenished to their **effective capacity** ($\text{maxCapacity} + \text{bonusEnergy}$), preserving any overflow above it.
- Server administrators can dynamically inspect and tune both $\text{maxBonusCap}$ and $\text{dailyIncrement}$ via `/tcg-admin action:energy`.

## 3. Roadblocks, Gotchas & Decisions Made

- **Effective Capacity Replenishment**: When a user's stamina is replenished across the daily boundary, it now replenishes up to $\text{maxEnergy} + \text{bonusEnergy}$. If a player had excess energy from potions (overflow > effective cap), the overflow remains untouched.
- **Idempotency**: `bonusEnergy` is only incremented when `record.lastResetDate !== today`. Repeated actions on the same day never grant duplicate increments.
- **Admin Configuration**: Setting `daily_bonus_energy_increment: 0` freezes bonus energy progression without resetting existing player bonuses.
