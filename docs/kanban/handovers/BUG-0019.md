## 1. Root Cause Analysis

When users ran `/imagine` or `$imagine` using the Replicate backend (`black-forest-labs/flux-schnell`):

1. **`Prefer: wait` Connection Timeout**:
   - `ReplicateImageProvider` sent the header `Prefer: 'wait'` to `https://api.replicate.com/v1/models/{model}/predictions`. In Node.js / Undici HTTP client environments, long-lived wait connections without interim chunk streaming timed out after 30 seconds (`DOMException [TimeoutError]`).
   - Meanwhile, on Replicate's servers, the prediction actually finished in 4-7 seconds, but the client connection had already dropped.

2. **Silent Fallback to Mock Provider**:
   - In `ImageGenerationService`, if a primary provider threw an error, it caught `primaryErr` and silently fell back to `MockImageProvider` to prevent user-facing fatal crashes.
   - However, the response object stamped `providerName: provider.name` (`Replicate Cloud AI`), while the actual image buffer and generation time (`0.0s`) came from the Mock provider. This displayed the mock placeholder canvas inside Discord with misleading labels.

3. **Discord WebP Attachment Extension Mismatch**:
   - Replicate Flux outputs images formatted as `image/webp`.
   - `AttachmentBuilder` hardcoded `{ name: 'imagine.png' }` and embed `.setImage('attachment://imagine.png')`. Serving WebP bytes under a `.png` file extension prevented Discord's media proxy and desktop clients from parsing the preview correctly.

4. **Rate Limiting on CDN Image Downloads**:
   - Downloading the final image buffer from Cloudflare R2 (`ai-gateway-outputs...r2.cloudflarestorage.com`) was using `this.limiter`, which throttled image downloads unnecessarily against the Replicate REST API schedule.

## 2. Changes Implemented

### A. Provider Layer (`packages/services/src/image-generation`)
- [`packages/services/src/image-generation/providers/replicate.provider.ts`](file:///Z:/Projects/ririko-v2-2026/packages/services/src/image-generation/providers/replicate.provider.ts):
  - Removed `Prefer: 'wait'` from prediction creation headers. Creation now returns in ~200-300ms with HTTP 201 Created and prediction metadata.
  - Client polls `urls.get` at 1500ms intervals until `status === 'succeeded'`.
  - Downloads final image buffers directly from CDN using `fetch` with `AbortSignal.timeout(25000)` and extracts real `Content-Type` header (`image/webp`).
- [`packages/services/src/image-generation/image-generation.service.ts`](file:///Z:/Projects/ririko-v2-2026/packages/services/src/image-generation/image-generation.service.ts):
  - Added warning logging `console.warn('[ImageGenerationService] Primary provider failed, falling back to mock:', err)` so failures are immediately visible in server logs.
  - Labeled fallback provider results as `${fallbackProvider.name} (Fallback)`.
  - Preserved fallback `providerName` rather than overwriting with primary provider name.

### B. Discord Command Layer (`apps/bot`)
- [`apps/bot/src/commands/images/imagine.command.ts`](file:///Z:/Projects/ririko-v2-2026/apps/bot/src/commands/images/imagine.command.ts):
  - Added `getImageAttachmentName(mimeType?: string)` helper mapping `image/webp` -> `imagine.webp`, `image/jpeg` -> `imagine.jpg`, and default `imagine.png`.
  - Updated both `/imagine` command execution and `imagine:regen:` interactive button interaction to dynamically name the attachment and set `.setImage('attachment://' + fileName)`.
