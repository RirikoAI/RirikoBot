## GROOMING · 2026-10-10T20:59:20Z · claude-opus-5-5 (coordinator)

**Status**: BACKLOG. The maintainer asked for a deeper grooming later. Do not dispatch it until it has acceptance criteria from live samples.

**First look** (from the code only, not confirmed live)
- **Epic**: `storeUrl = https://store.epicgames.com/p/${slug}`. The slug is the first of `productSlug`, `urlSlug`, `offerMappings[0].pageSlug`, `catalogNs.mappings[0].pageSlug` and `game.id`. These are the likely broken links:
  - Epic's `productSlug` is often null, or has a suffix such as `/home`.
  - `urlSlug` is often an internal id, not a page slug.
  - The last fallback, `game.id`, is never a valid page.
  - Bundles and mystery games have no page slug at all.
- **Steam**: `https://store.steampowered.com/app/${id}/` from featured specials. Probably fine; confirm it.
- The same `storeUrl` is both the embed `url` and the "Claim on" link (`formatGameEmbed`).
- The migrated 1.4.0 ids (`freeGameId` in `transformer.ts`) only affect deduplication, not the links.

**The deeper grooming should**
1. Capture a live `freeGamesPromotions` response (current and upcoming) as a fixture.
2. List the URL each element would get, and check each one with a HEAD request.
3. Decide the slug order. The usual fix is offerMappings `pageSlug` with `pageType` "productHome" first, with a fallback to `https://store.epicgames.com/free-games`.
4. Write the tests from the fixture.

- `productSlug` is null for 10 of 14 elements; one is `thems-fightin-herds/home`.
- `urlSlug` is a 32-character hex id for 7 of 14. That is the broken link: `https://store.epicgames.com/p/<hex>`.
- Every element has a `productHome` mapping, except the add-on "Lost Castle: The Old Ones Awaken", whose offerMappings entry is `pageType: "offer"`; its `catalogNs.mappings` has the `productHome` slug of the base game.
- `store.epicgames.com` is still blocked here, so the page slugs could not be HEAD-checked. They are the slugs Epic's own store uses for product pages.

**Steam**: `specials.items` has 10 discounted items and none at 100% today, so no free item. `https://store.steampowered.com/app/<id>/` is Steam's standard page URL. No change.

**Approach**
1. In `epic.provider.ts`, replace the slug block (`// Resolve product slug`) with a small helper `resolveEpicPageSlug(game)` returning the slug or `null` in the acceptance order. `storeUrl` is `/p/<slug>` or `https://store.epicgames.com/free-games` for `null`.
2. Tests in `free-games.test.ts`: load the fixtures with `readFileSync(new URL('./fixtures/epic-promotions.json', import.meta.url))` and a `fetchFn` stub that returns them. Compare against the four games above. Add the small unit cases for each fallback step.

**Pitfalls**
- Keep `id: epic-${game.id || slug}`. The id is the deduplication key (and the migrated 1.4.0 ids depend on it); changing it would re-announce every game.
- The fixture's promotion dates are real. The provider takes active and upcoming offers without a date check, so the test does not need fake timers; if it compares dates, use the fixture's values.
- The existing tests that use `productSlug: 'test-free-game'` and `urlSlug: 'upcoming-game'` with no mappings must keep passing.

**Out of scope**
- `free-games.command.ts` and the engine embeds already use `storeUrl`. No change there. Steam giveaways that are not in `featuredcategories` specials.
