## GROOMING · 2026-10-10T20:59:20Z · claude-opus-5-5 (coordinator)

**Status**: BACKLOG. The maintainer asked for a deeper grooming later. Do not dispatch it until it has acceptance criteria from live samples.

**First look** (from the code only, not confirmed live)
- **Epic**: `storeUrl = https://store.epicgames.com/p/${slug}`. The slug is the first of `productSlug`, `urlSlug`, `offerMappings[0].pageSlug`, `catalogNs.mappings[0].pageSlug` and `game.id`. These are the likely broken links:
  - Epic's `productSlug` is often null, or has a suffix such as `/home`.
  - `urlSlug` is often an internal id, not a page slug.
  - The last fallback, `game.id`, is never a valid page.
  - Bundles and mystery games have no page slug at all.
- **Steam**: `https://store.steampowered.com/app/${id}/` from featured specials. Probably fine; confirm it.
- The same `storeUrl` is both the embed `url` and the "Claim on" link (`formatGameEmbed`).
- The migrated 1.4.0 ids (`freeGameId` in `transformer.ts`) only affect deduplication, not the links.

**The deeper grooming should**
1. Capture a live `freeGamesPromotions` response (current and upcoming) as a fixture.
2. List the URL each element would get, and check each one with a HEAD request.
3. Decide the slug order. The usual fix is offerMappings `pageSlug` with `pageType` "productHome" first, with a fallback to `https://store.epicgames.com/free-games`.
4. Write the tests from the fixture.
