**Approach**
1. Read `docs/kanban/handovers/STORY-192.md` and `.local/installer-1x/index.html` (the 1.x page with every guide text).
2. Create `apps/cli/src/installer/`:
   - `steps.ts`: the ordered pages as typed data. Suggested shape: `{ id, icon, title, subtitle: 'Step N', intro, note: string[], switches, fields, guides, checks }`. A field: `{ name (env variable), label, placeholder, kind: 'text' | 'secret' | 'url' | 'select', options?, required, switch?, rule }`. Take each `rule` from the schema (`BaseAppConfigSchema.shape.X` is not exported, so export what you need from `packages/core/src/config/schema.ts` or validate the planned env as a whole and map errors back to fields).
   - `guides.ts`: the guide data. Port the 1.x text faithfully where the step still exists (Twitch word for word). Write the new guides in the same voice: short numbered steps, one action each, the exact button names.
   - `env-plan.ts`: `planEnv(answers, current, profile, generate)` returns the variables to write; `writeEnv(path, plan)` copies the example when the file is missing, backs up an existing file, writes with `updateEnvFile`, and sets mode 0600.
3. Profiles: `source` uses `.env.example` and `.env`; `docker` uses `.env.production.example` and `.env.production`.
4. Pages and their variables:
   - Discord Bot: `DISCORD_CLIENT_ID`, `DISCORD_TOKEN`, `BOT_OWNER_ID` (optional), source only: `DISCORD_DEV_GUILD_ID` (optional).
   - AI: switch AI chat: `DEFAULT_AI_PROVIDER` (gemini, openai, ollama), `GEMINI_API_KEY` or `OPENAI_API_KEY` (+ optional `OPENAI_BASE_URL`) or `OLLAMA_BASE_URL`. Switch image generation: `IMAGE_DEFAULT_PROVIDER` (gemini, replicate, comfyui), `REPLICATE_API_TOKEN` or `COMFYUI_URL`. Gemini for images reuses `GEMINI_API_KEY`.
   - Stream Alerts: switch Twitch: `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`. Switch YouTube: `YOUTUBE_API_KEY`.
   - Database & Music: source: SQLite (default, `DATABASE_DIALECT=sqlite`, `DATABASE_URL=./data/ririko.sqlite`) or PostgreSQL (`DATABASE_DIALECT=postgres`, `DATABASE_URL`). Docker: nothing to type, `POSTGRES_PASSWORD` generated. Both: `LAVALINK_PASSWORD` generated (source keeps an existing value; replace only the example's `youshallnotpass`). Switch Spotify: `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`.
   - Dashboard: `DISCORD_CLIENT_SECRET`, `DASHBOARD_URL` (default `http://localhost:3000`), `SECRET_VAULT_KEY` generated. Docker always has the dashboard; source has a switch.
5. Copy the six images named in the acceptance to `assets/installer/images/`. `assets/` is already copied into the bot image.

**Relevant code**

- `apps/cli/src/utils/env-editor.ts:67` `readEnvFile`, `:27` `maskSecret`.

- `packages/discord/src/client/factory.ts:15` `DEFAULT_GATEWAY_INTENTS`: `GuildMembers` and `MessageContent` are the privileged ones. Build the intent guide text from this list.

**Pitfalls**
- **Empty values**: `.env.example` has `OPENAI_BASE_URL=` and `COMFYUI_URL=`, and both schemas reject an empty URL. Fix it at the root: make the config parsing treat an empty string as unset (for example in the `applyLegacyAliases` preprocess, or in `parseConfig`), with a core test that the untouched `.env.example` passes both schemas. Check that `DB_AUTO_MIGRATE`, `BOT_OWNER_ID` and `CLIENT_IP_HEADER`, which already handle empty strings, still behave the same.
- `.env.example` holds placeholder values (`your_bot_token_here`, `youshallnotpass`). Treat them as unset when you prefill the form.
- ComfyUI: the services read `COMFYUI_URL` (and `COMFYUI_BASE_URL`, written by older `image-configure` versions). Write `COMFYUI_URL`.
- Spotify cookies (`SPOTIFY_DC`, `SPOTIFY_SP_DC`, `SPOTIFY_KEY`) are not in the wizard: they come from browser developer tools and are fragile. The docs cover them.
- Never write `DATABASE_*` or `LAVALINK_HOST`/`LAVALINK_PORT` for docker: the compose file sets them and a written value would be ignored or, worse, confusing.
- Golden files: inject the secret generator so the output is byte-identical. Use LF line endings in the fixtures (Windows checkout).
- Some tests may already fail on Windows (CHORE-2002). Run the paths in `verify_cmd`; report any unrelated failure in the PROGRESS entry.

**Out of scope**
- The web server, rendering and HTML (TASK-1924); the live checks (TASK-1922); the CLI command (TASK-1925).
- TikTok, `SPOTIFY_DC`/`SPOTIFY_KEY`/`SPOTIFY_REFRESH_TOKEN`, reset times, `LOG_LEVEL` and other expert settings: they keep the example's values.

**Decisions**
- Field `rule` is `{ schema: 'app' | 'web' | 'none', extra? }`. `validatePage` probes the real `AppConfigSchema`/`WebConfigSchema` with a valid base env plus the one value, and takes the schema's message for that variable. Extras: `snowflake`, `postgres-url`. No schema export was needed.
- Conditional fields use `switch`, `appliesWhen` (any-of conditions) and `requiredWhen`. Docker forces the dashboard switch on. Install-page acceptances are `kind: 'checkbox'`, `env: false`.
- `planEnv` writes only active, non-empty answers; an emptied optional value that the file had is cleared; SECRET_VAULT_KEY (dashboard on), LAVALINK_PASSWORD, and for docker POSTGRES_PASSWORD are generated once (placeholders `youshallnotpass`, `your_*_here`, `https://dashboard.example.com` count as unset). Docker never writes DATABASE_DIALECT/DATABASE_URL/LAVALINK_HOST/LAVALINK_PORT.
- `writeEnv` validates every page, then parses the planned text with the schemas (web schema only when the dashboard is on), then backs up to `<file>.bak-<YYYYMMDDTHHMMSSZ>` and writes mode 0600. Update mode expects the answers to contain every required value (the web layer prefills from `prefillValues(readEnvFile(...))`).
- The untouched `.env.example` passes `AppConfigSchema`; it passes `WebConfigSchema` once `DISCORD_CLIENT_SECRET` and `SECRET_VAULT_KEY` (dashboard-only, absent from the example) are added. The test says so.
- Discord/OpenAI guides carry no screenshots (the 1.x ones show the old UI and three intents); CHORE-2004 adds new ones.
