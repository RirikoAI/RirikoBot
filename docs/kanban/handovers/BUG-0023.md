## GROOMING · 2026-10-02T20:27:42Z · Claude Code (Opus 5.5)

**Cause**
- `apps/bot/src/listeners/message.listener.ts:84` calls `antiSpamEvaluator.evaluateMessage`. A pass sets `lastRewardAt` (`anti-spam.ts:231`).
- The listener then calls `economyService.handleEvent` (line 110) without `content`. `handleEvent` (`economy.service.ts:80`) evaluates the same evaluator again with `''`, which fails `MIN_LENGTH`. If it had content, it would fail `COOLDOWN`.
- So `MESSAGE_SENT` never pays credits.

**Approach**
- `EconomyService.handleEvent` keeps ownership of the check.
- The listener stops calling `evaluateMessage`. It calls `handleEvent` with `metadata.content` and `metadata.timestamp`, then runs the card drop and chat XP only when the result is `awarded`.
- `handleEvent` must drop `content` and `timestamp` from the metadata before `modifyBalance`, so chat text never reaches `economy_transactions`.

**Pitfalls**
- Do not add a "skip anti-spam" flag. One owner, one evaluation.
- Voice events also go through `handleEvent`, but anti-spam only applies to `MESSAGE_SENT`.

## PROGRESS · 2026-10-03T06:14:58Z · Claude Code (Opus 5.5) · REVIEW

**Files changed**
- `apps/bot/src/listeners/message.listener.ts`:
  - The listener no longer calls `antiSpamEvaluator.evaluateMessage`.
  - It calls `economyService.handleEvent` first, with `content` and `timestamp` (`createdTimestamp`) in the metadata.
  - It runs the card drop, the user upsert and the chat XP only when `reward.awarded` is true.
- `packages/services/src/economy/economy.service.ts`: `handleEvent` removes `content` and `timestamp` from the metadata before `modifyBalance`, so chat text is never written to `economy_transactions`.
- `apps/bot/src/listeners/message-credits.test.ts` (new) drives the real `EconomyService` and `AntiSpamEvaluator` through the listener. Two valid messages 61 s apart each pay 20 credits and give chat XP, and the stored metadata has no `content`. A message inside the cooldown, a short message and a duplicate pay nothing and give no chat XP.
- `economy.service.test.ts` asserts that the ledger metadata holds neither the text nor the timestamp.
- `moderation-listeners.test.ts`: the `handleEvent` mock now returns a reward result.

**Verification**
- `pnpm vitest run packages/services/src/economy apps/bot/src`: 61 files, 675 tests pass.
- `pnpm typecheck` and `pnpm lint --quiet` pass.

**Decisions & gotchas**
- The user upsert now runs only for messages that passed anti-spam, as the card drop already did. `economy_balances` has no foreign key to `users`, so paying before the upsert is safe.
- `BotServices.antiSpamEvaluator` stays, because the economy service shares that instance.
