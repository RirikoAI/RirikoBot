## GROOMING · 2026-10-04T18:50:17Z · Claude Code (Opus 5.5)

**Approach**
1. In `docker-compose.production.yml`:
   - add an `x-logging: &logging` anchor (driver `local`, options `max-size: 20m`, `max-file: '5'`) and `logging: *logging` on all four services;
   - add `cap_drop: [ALL]` and `security_opt: [no-new-privileges:true]` to `bot` and `web`, and only the `security_opt` to `postgres` and `lavalink`;
   - change the `web` port to `'${DASHBOARD_BIND:-127.0.0.1}:${DASHBOARD_PORT:-3000}:3000'`;
   - change `_JAVA_OPTIONS` to `-Xmx${LAVALINK_HEAP:-1G}`.
2. Add `DASHBOARD_BIND` and `LAVALINK_HEAP` to the optional block of `.env.production.example`.
3. Add `yaml` to the root `devDependencies` at the version in `pnpm-lock.yaml` (2.9.1 today), then `pnpm install`.
4. Write `scripts/compose-production.test.ts`: read the compose file, `parse` it with `yaml` (anchors resolve), and assert each acceptance item.
5. Update `docs/deployment.md` section 2.2.

**Relevant code**
- `scripts/release-tags.test.ts:6` reads `.circleci/config.yml` with `readFileSync(new URL('../.circleci/config.yml', import.meta.url))`. Use the same pattern.
- `Dockerfile:99-122`: both runner images already run as uid 10001 with tini; nothing needs a capability.

**Pitfalls**
- Do not drop capabilities from `postgres`: its entrypoint chowns the data directory and switches user with gosu (needs CHOWN, SETUID, SETGID, FOWNER, DAC_OVERRIDE). `no-new-privileges` is fine there.
- The `local` log driver option values must be strings in YAML (`'5'`).
- The docker-smoke script builds and runs the images directly, not through compose, so it is unaffected.
- The bind default changes behaviour for self-hosters who reached the dashboard on the LAN; the env example and docs must say how to open it.

**Out of scope**
- `read_only` root file systems, memory limits, a reverse proxy service.
