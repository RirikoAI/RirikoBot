## 2. Key Deliverables & Implemented Architecture

### 2.1. Dynamic Warning Escalation Engine (`WarningEscalationService`)
Implemented in `packages/services/src/moderation/warning-escalation.service.ts`:
- **Default Escalation Policy**:
  - Threshold 1: Formal warning DM (`WARN`)
  - Threshold 2: Second warning DM (`WARN`)
  - Threshold 3: 10-minute timeout (`TIMEOUT`, 600s)
  - Threshold 4: 1-hour timeout (`TIMEOUT`, 3600s)
  - Threshold 5: 24-hour timeout (`TIMEOUT`, 86400s)
  - Threshold 6: Permanent server ban (`BAN`)
- **Custom Guild Policy Support**:
  - `getEscalationPolicy(guildId)`: Loads custom threshold mappings or defaults.
  - `setEscalationPolicy(guildId, steps)`: Saves customized thresholds to database.
- **Severity Weighting**:
  - Warnings support a `severity` multiplier (e.g. minor = 1, moderate = 2, major = 3).
  - Cumulative score is calculated as `SUM(active_warnings.severity)`. A single infraction with severity 3 immediately triggers threshold 3!
- **Sliding-Window Expiration Engine**:
  - Configurable expiration date per warning (`expirationDays`, default 30 days).
  - Active warning queries automatically filter out expired records (`expiresAt <= NOW()`).
- **Automated Disciplinary Execution Bridge**:
  - Automatically invokes `ModerationActionService` when cumulative score triggers punitive thresholds (`TIMEOUT`, `KICK`, `BAN`).
  - Sends comprehensive DM to the target member detailing warning count, weighted score, expiration timestamp, and any automated disciplinary actions enacted.
  - Registers moderation case (`type: 'WARN'`) in `moderation_cases` and dispatches `CoreEvents` (`moderation:warningIssued`, `moderation:actionExecuted`).
