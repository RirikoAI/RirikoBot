## 2. Summary of Implementation
We implemented a complete physical-style collectible visual card synthesis engine and card-building tooling conforming to [docs/tcg-card-synthesis.md](file:///Z:/Projects/ririko-v2-2026/docs/tcg-card-synthesis.md):

1. **Modular PNG Asset Architecture (`assets/tcg/`)**:
   - `assets/tcg/elements/`: 128×128 px circular emblems for all 7 elements (`fire.png`, `ice.png`, `water.png`, `earth.png`, `lightning.png`, `light.png`, `shadow.png`).
   - `assets/tcg/stars/`: 64×64 px golden star (`star.png`) and iridescent prismatic star (`star_prismatic.png`).
   - `assets/tcg/foils/`: 800×1200 px holographic overlay textures for `rare.png`, `super_rare.png`, `ultra_rare.png`, `secret_rare.png`, `sir.png`, and `mythic.png`.
   - `assets/tcg/frames/`: 800×1200 px border frames for `common.png`, `rare.png`, `super_rare.png`, `ultra_rare.png`, and `mythic.png`.
   - Dedicated generator script: [scripts/generate-tcg-assets.ts](file:///Z:/Projects/ririko-v2-2026/scripts/generate-tcg-assets.ts) (runnable via `pnpm tcg:generate-assets`).

2. **CardSynthesizer Engine (`packages/services/src/waifu-tcg/canvas/card-synthesizer.ts`)**:
   - High-definition 800 × 1200 px canvas rendering using `@napi-rs/canvas`.
   - 8-layer sequential visual stack:
     - **Layer 0**: Elemental Aura & Base Canvas (radial gradients tuned to the 7 elements).
     - **Layer 1**: Character Artwork (aspect-ratio preserving `cover` fit, rounded clipping, full-art support for SIR/Mythic, silhouette fallback).
     - **Layer 2**: Glassmorphic Stat & Skill Footer (HP, ATK, DEF, SPD indicator badges; Active Tactical Skill with MP badge; Passive Perk; serial number `#0001/0350` and attribution).
     - **Layer 3**: Card Frame & Metallic Borders (metallic bevels and corner filigree).
     - **Layer 4**: Holographic Foil Overlay (rarity-based composite blend modes: `soft-light`, `overlay`, `color-dodge`, `hard-light`, with procedural shader fallbacks).
     - **Layer 5**: Character Name Banner & Title Ribbon on top (glassmorphic capsule, bold typography).
     - **Layer 6**: Rarity Stars (1 to 8 stars on the top-right corner).
     - **Layer 7**: Top-Left Element Emblem (96×96 px circular jewel at `(24, 24)`).
   - Exported top-level helper: `synthesizeCardImage()`.

3. **Character Catalog & Card Manifest (`assets/tcg/catalog/`)**:
   - `characters.json`: 237 real anime characters indexed with AniList IDs, romaji/english names, anime series, and gender tags.
   - `manifest.json`: 350+ card specifications across all 7 elements, 8 rarity tiers, and designated starter pool tags (`starter_pool`).
   - Artwork source: Danbooru (rating:g, solo, single character) with AniList portraits as fallback; rate-limited client with retry.

4. **Card Builder CLI & Script (`scripts/tcg-card-builder.ts`)**:
   - `pnpm tcg:card-builder --sync`: Syncs manifest and catalog into SQLite/PostgreSQL database.
   - `pnpm tcg:card-builder --rerender`: Batch renders all card PNGs from the manifest into `public/cards/`.
   - `pnpm tcg:card-builder --starters`: Generates starter pool cards.
   - `pnpm tcg:card-builder --create`: Allows manual single-card creation via CLI flags or interactive terminal prompts.
   - Layout optimized for Discord: ~400px previews, automatic text wrapping/shrinking, and `--text-scale` (0.8–1.2).

5. **Discord Bot CardImageService & Attachment Integration**:
   - `CardImageService` (`packages/services/src/waifu-tcg/canvas/card-image.service.ts`): Caches synthesized cards under `public/cards/` and renders on demand.
   - `/card claim` and `/card inspect` attach the rendered 800×1200 px foiled card PNG directly to Discord messages.
   - Takedown handling: taken-down art automatically renders as a standardized silhouette, deleting the stale cache.
   - `resolveWorkspacePath` in `@ririko/core` ensures workspace-relative paths resolve cleanly when running from `apps/bot`.

## 4. Key Gotchas & Architecture Decisions
- **PNG Decoding Safety**:
  - `@napi-rs/canvas` uses native `libpng` which requires a valid `IDAT` chunk. Mock header-only buffers (`createMockPngBuffer`) cause native segfaults if passed to `loadImage()`. A real procedural canvas buffer (`generateArtworkBuffer`) was implemented for bulk generation.
- **Node.js Type Definitions**:
  - `GlobalCompositeOperation` is a browser DOM interface not present in Node.js `tsconfig.json`. Defined `FoilBlendMode` explicitly to ensure typecheck passes in headless environments.
- **Universal Font Compatibility**:
  - Replaced raw emoji icons with procedural colored badges and dots in the card footer to prevent headless/server environments without emoji fonts from rendering missing glyph boxes (`[]`).
- **Path Resolution from apps/bot**:
  - `resolveWorkspacePath()` in `@ririko/core` locates the monorepo root via `pnpm-workspace.yaml`, allowing both dev (`apps/bot`) and root CLI scripts to resolve `assets/` and `public/` consistently.
