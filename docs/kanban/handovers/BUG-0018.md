# BUG-0018 — Persist and Restore Guild Default Volume Across Music Sessions

**Status**: DONE
**Points**: 3
**Parent**: EPIC-005
**Branch**: `develop/2.0.0`

---

## 1. The Bug

When users configured music volume using `$volume <level>` or `/volume <level>` (e.g. `$volume 20`), the setting was saved into the `music_guild_settings` table via `musicRepo.upsertGuildSettings`, but upon ending a music session and starting a new one via `/play`:
1. The new playback session initialized with a hardcoded volume of `80%`.
2. The bot never read the saved `default_volume` from `music_guild_settings` when creating a new queue or Lavalink player.
3. Checking volume using `/volume` while idle instantiated an in-memory queue at 80% rather than displaying the guild's saved setting.
4. Interactive mute/unmute buttons on the music embed controller could fail under Lavalink because `LavalinkQueueAdapter` was missing the `setVolume(volume)` method.

---

## 2. Fix Implementation

### 2.1. In-Memory Cache & Resolver in `MusicPlayerService`
- Added `resolveGuildVolume?: ((guildId: string) => Promise<number | undefined> | number | undefined) | undefined` to `MusicPlayerServiceOptions`.
- Added `resolveVolumeForGuild(guildId: string): Promise<number>` to `MusicPlayerService`, which checks an internal `guildVolumeCache` (Map) first, falls back to the injected resolver, and defaults to `defaultVolume` (80%).
- Added `getGuildCachedVolume(guildId)` and `setGuildCachedVolume(guildId, volume)` methods.
- Updated `MusicPlayerService.setVolume(guildId, volume)` to keep `guildVolumeCache` synchronized whenever the volume is changed.

### 2.2. Player & Queue Initialization
- In `MusicPlayerService.play()`: Resolves the guild default volume asynchronously prior to starting playback, passing it to `lavalinkService.play(options, guildVol)` or `getOrCreateQueue(options.guildId, options.textChannelId, guildVol)`.
- In `MusicPlayerService.join()`: Passes the resolved guild volume when creating a Lavalink player.
- In `LavalinkService.play()`: Accepts `initialVolume?: number`, creating the player with the resolved guild volume (clamped between 0–150) instead of the hardcoded 80.
- In `LavalinkQueueAdapter`: Implemented `setVolume(volume: number): number`, clamping to [0, 150] and updating `this.player.setVolume(clamped)`.

### 2.3. Repository & Service Wiring
- In `packages/database/src/repositories/music.repository.ts`: Corrected fallback in `upsertGuildSettings` from `20` to `80` to align with the database table schema default.
- In `apps/bot/src/services.ts`: Wired `resolveGuildVolume` to query `musicRepo.getGuildSettings(guildId)`.

### 2.4. `/volume` Command Enhancements
- In `apps/bot/src/commands/music/commands.ts`:
  - When invoked with no argument while active music is playing: Displays `🔊 Current playback volume is **${queue.volume}%** (server default: **${savedVolume}%**).`
  - When invoked with no argument while idle: Displays `🔊 Current playback volume is **${savedVolume}%** (server default).`
  - When invoked with a level: Adjusts active volume, updates in-memory cache, persists to database, and responds with `🔊 Playback volume adjusted to **${clamped}%** (saved as server default).`
