## GROOMING · 2026-10-23T15:52:42Z · claude-opus-5-5 (coordinator)

**Found** on 2026-10-22: the bot started before Lavalink, logged "Unable to connect after 5 attempts" and kept music off until a restart.

**Cause**: lavalink-client 2.11.0 node defaults are `retryAmount: 5` and `retryDelay: 1e4` (dist/index.js line 1701); after that it emits the error and stops reconnecting. `LavalinkService` (packages/music/src/lavalink/lavalink-service.ts) only logs node `error` and `disconnect`.

**Approach**: in `wireManagerEvents`, on a node `disconnect` or the give-up error, schedule `node.connect()` with backoff unless already connected or destroyed. Clear the timer on `connect`. Add a `destroy()`/stop path if none exists, and call it where the service shuts down.

**Pitfalls**: avoid two loops racing the library's own retries. Start the outer loop only after the library gives up (the error message) or on a disconnect with no reconnect pending.
