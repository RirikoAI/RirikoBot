## 1. Summary of Changes

In [`packages/discord/src/middleware/permissions.ts`](file:///Z:/Projects/ririko-v2-2026/packages/discord/src/middleware/permissions.ts):
1. **Implicit Guild-Only Enforcement**:
   - Any command specifying `metadata.userPermissions` or `metadata.botPermissions` now automatically requires a guild context, throwing `CommandGuildOnlyError` if invoked in direct messages even if `metadata.isGuildOnly` was not explicitly set.
2. **Robust User Permission Resolution (`resolveUserPermissions`)**:
   - **Guild Owner Bypass**: Guild owners (`ctx.guild.ownerId === ctx.user.id`) implicitly hold all permissions (`PermissionsBitField.All`), preventing accidental lockouts on custom-role hierarchies.
   - **Direct & Fallback Resolution**: Safely extracts permissions from `ctx.member.permissions` (handling both direct `PermissionsBitField` with `.has()` and raw bitfield representations), slash interaction `raw.memberPermissions`, and falls back to asynchronous member fetching via `ctx.guild.members.fetch(ctx.user.id)` when `ctx.member` is uncached.
   - Throws `CommandPermissionError` if member permissions cannot be resolved in a guild.
3. **Robust Bot Member Resolution (`resolveBotMember`)**:
   - Safely retrieves the bot's own `GuildMember` by checking `ctx.guild.members.me`, with graceful fallback to `ctx.guild.members.fetchMe()` or fetching `ctx.client.user.id`.
4. **Exported Utility Resolvers**:
   - Exported `resolveUserPermissions` and `resolveBotMember` for use across interaction handlers and testing harnesses.
