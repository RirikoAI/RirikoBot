## 1. Summary of Changes

### The Problem
When a user asked Ririko AI in chat to play music (e.g. *"Please play me the intro song for Frieren"*), the model emitted a tool call to `music.play`.
`MusicPlayTool` was a dummy stub returning `{ query, action: 'queued', message: 'Searching and queuing...' }`.
No music was queued, no voice connection was established, and no audio was played.

### The Solution
1. **Tool Execution Context & Resolver**:
   - In `packages/ai/src/tools/types.ts`, extended `ToolExecutionContext` with `playMusic?: (query: string) => Promise<{ success: boolean; message: string; trackTitle?: string; trackUrl?: string; position?: number }>`.
   - In `packages/ai/src/tools/definitions/music.tool.ts`, introduced `MusicPlayResolver` type and constructor injection. Updated `execute()` to execute `context.playMusic` or `this.playResolver`.
   - Extended `MusicPlayResult` to return structured metadata (`trackTitle`, `trackUrl`, `position`).
2. **Bot AI Chat Controller Wiring (`AiChatController`)**:
   - Added `musicController?: MusicEmbedController` to `AiChatControllerOptions` and `AiChatController` in `apps/bot/src/controllers/ai-chat.controller.ts`.
   - Passed `musicController` from `apps/bot/src/main.ts` into `AiChatController`.
   - In `toolContext` for `this.services.toolExecutor.executeBatch`:
     - Checks whether message is in a Discord server.
     - Resolves member (fetching if uncached) and checks voice channel presence via `member?.voice?.channelId` with fallback to `guild.voiceStates?.cache?.get(userId)?.channelId`.
     - Evaluates effective voice channel permissions (`voiceChannel.permissionsFor(member)`) so users with channel-level Connect/Speak access are not blocked by guild-level defaults.
     - If user is not in voice, returns an actionable error asking the user to join a voice channel.
     - Invokes `services.musicPlayer.play({ guildId, voiceChannelId, textChannelId, member, query, adapterCreator })`.
     - Reactively updates the dedicated music channel player embed using `this.musicController?.updateController(guildId)`.
     - Returns rich track information (`trackTitle`, `trackUrl`, `position`).
3. **Slash Command Parity (`/ai chat`)**:
   - In `apps/bot/src/commands/ai/commands.ts`, populated `playMusic` in `toolContext` with uncached member resolution, `voiceStates?.cache` fallback, and `updateController` triggers.
4. **Fallback Formatter Enhancement**:
   - Updated `formatToolResultFallback` in `packages/ai/src/tools/formatter.ts` to cleanly format music errors (`⚠️ **Music**: ...`) and success messages with clickable track links (`🎵 **Music**: ... \n🔗 <url>`).

## 3. Key Decisions & Gotchas

- **Decoupled Tool Abstraction**: The `@ririko/ai` package does not depend on `@ririko/music` or `discord.js`. All live Discord voice channel discovery and player invocation occurs via the `playMusic` callback injected by `apps/bot`.
- **Bot Permissions in Mock Messages**: `ToolSecurityInterceptor` enforces `requiredPermission = 3145728n` (`Connect | Speak`) on both the user and the bot. In mock message harnesses, `guild.members.me` must have the appropriate permission bits set.
