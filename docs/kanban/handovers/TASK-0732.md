## 2. Key Deliverables & Implemented Architecture

### 2.1. Gateway Moderation Listeners (`messageCreate` & `guildMemberAdd`)
Located in `apps/bot/src/listeners/`:
- **`message.listener.ts` AutoMod Pipeline Integration**:
  - Automatically evaluates every guild text message through `services.autoModService.processMessage(context)`:
    - Verifies message against Phishing Shield, Invite Filter, Mention Spam, and Burst Spam rules.
    - If a rule matches, automatically deletes the message (or triggers warning/timeout/kick/ban escalations) and halts further execution.
    - Prevents illicit or spam messages from earning currency, XP, or triggering music/AI handlers.
- **`member.listener.ts` Anti-Raid Join Velocity Monitoring**:
  - Implements `registerMemberListener(client, services)` listening to `guildMemberAdd`.
  - Feeds each join context (`accountCreatedTimestamp`, `joinedTimestamp`, `isBot`) into `services.antiRaidService.handleMemberJoin(...)`.
  - When mass join velocity or coordinated fresh account spikes trigger raid detection:
    - Emits alert logs and fetches guild `logChannelId` configuration via `services.guildSettingsRepo.findById(guildId)`.
    - Dispatches rich alert embeds generated by `antiRaidService.generateAlertEmbed(result)` to the staff moderation log channel.
- **Bot Lifecycle Wiring & Monorepo Integration**:
  - `apps/bot/src/main.ts`:
    - Registers all 14 moderation commands (`createModerationCommands(services)`).
    - Binds `registerMemberListener(bot.client, services)`.
  - `apps/bot/src/index.ts`:
