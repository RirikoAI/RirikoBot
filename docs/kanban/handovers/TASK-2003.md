**Public API** (all exported from `@ririko/services`)
- `rolesForLevel(rewards: readonly LevelRoleReward[], level: number, keepPreviousRoles: boolean): { keep: string[]; remove: string[] }`
- `new LevelRoleService({ settings: Pick<LevelRoleSettingsRepository,'get'>, xp: Pick<XpRepository,'listMembersAtLevel'>, cacheTtlMs?, now? })`
- `invalidate(guildId?: string): void`
- `applyForMember(member: GuildMember, level: number): Promise<ApplyResult>`, `ApplyResult = { added: string[]; removed: string[]; skipped: { roleId; reason: 'missing' | 'everyone' | 'managed' | 'hierarchy' }[] }`
- `syncGuild(guild: Guild): Promise<SyncResult>`, `SyncResult = { busy: boolean; checked: number; added: number; removed: number }` (a second call during a sync returns `{ busy: true, checked: 0, added: 0, removed: 0 }`).

**Acceptance**
1. `rolesForLevel` is pure: with keep, every reward role at or below the level (ascending, deduplicated) and `remove: []`; without keep, the role of the highest reward at or below the level, and every other reward role (also those above the level) in `remove`. Level 0, a level below every reward and no rewards give empty lists. Met.
2. Settings cache with a 5 minute default TTL, `cacheTtlMs` and `now` options, and `invalidate(guildId?)`, copied from EventLogService (a missing row is cached as "no rewards"; a failed read is logged and not cached). Met.
3. `applyForMember` adds only missing roles and, without keepPreviousRoles, removes only reward roles the member holds, both with reason "Level <n> reward" and skipping the call when the list is empty. It skips missing roles, @everyone, managed roles and roles at or above Ririko's highest role (same rules as `AutoRoleService.isValidAssignableRole`, reported in `skipped`), and does nothing when Ririko is not in the member cache or lacks Manage Roles. A non-reward role is never touched. Add and remove are separate calls with their own try/catch; a Discord error is logged with the guild and role IDs (never the user) and the role is not reported as added/removed. The method never throws. Met.
4. `syncGuild` reads the settings, returns zeros with no rewards (or when Ririko lacks Manage Roles, before any member is read), calls `xp.listMembersAtLevel(guild.id, lowestRewardLevel)`, fetches members with `guild.members.fetch({ user: ids })` in batches of 100, skips users missing from the result, and applies each member in turn at their own XP level. A `Set` of syncing guild IDs is released in a `finally`. Returns checked (members found), added and removed counts. Failed batch fetch or account read is logged and the sync goes on or ends with the counts so far. Met.
5. Tests (40): rolesForLevel (both modes, gaps, multi-level jump, empty cases, unsorted input, shared role), each skip rule, hierarchy on remove, the remove rule, non-reward roles, failed add and remove, cache (TTL, default TTL, real clock, null row, invalidate one/all, failed read), sync (zeros, no permission, per-member levels, removed count, batching 100/100/50, one at a time, left members, failed fetch, failed account read, busy per server and release). Met.
