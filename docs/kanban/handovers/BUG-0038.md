## GROOMING · 2026-10-07T15:30:00Z · Claude Code (Opus 5.5)

**Why**
- The `db:copy` dry run against staging failed with `invalid input syntax for type uuid: "conv_<uuid>"`.
- A scan of the maintainer's SQLite found 962 non-uuid values in columns that are uuid in PostgreSQL:
  - `waifu_cards.id`: 351 rows such as `card_fire_001`;
  - `waifu_assets.id`: 350 rows such as `asset_card_bulk_fire_001`;
  - `economy_items.id`: legacy slugs such as `candy_minor`;
  - AI conversation and message ids with `conv_` and `msg_` prefixes;
  - the columns that reference these: `user_cards.card_id`, `waifu_cards.asset_id`, `economy_inventories.item_id` and `ai_messages.conversation_id`.
- Rewriting the ids is unsafe:
  - card images in `public/cards` are named by card id (384 of the 407 files are slug names);
  - ids also appear in adventure payloads, in a `tcg_system_configs` value and in `waifu_card_serials.card_id` (text).
- The maintainer chose text ids in PostgreSQL.

**Approach**
1. Change the listed pg columns from `uuid(...)` to `text(...)`.
   - Primary keys keep a random default, for example `.$defaultFn(() => randomUUID())` or a `gen_random_uuid()::text` SQL default.
   - Run `pnpm -F @ririko/database db:generate-ddl` afterwards.
2. Add an upgrade step, for example `ensureTextIdColumns(client)` in `packages/database/src/migrations/`.
   - Under `pg_advisory_xact_lock`, read `information_schema.columns`.
   - For each listed column that is still uuid, run `ALTER TABLE ... ALTER COLUMN ... TYPE text`.
   - Call it wherever `ensureAdventureSchema` and `ensureCardSerialSchema` are called (`apps/bot/src/main.ts`, and the web app if it runs them), and in `copyDatabase`'s target preparation.
   - On SQLite it does nothing.
3. Remove the dialect special cases:
   - the `UUID_PATTERN` guard in `ItemRepository.findById`;
   - the pg branch in `AiRepository.newId`.

**Pitfalls**
- **Foreign keys:** the only one in the pg schema today is `adventure_choices` to `adventure_sessions`, so these type changes hit no FK constraints. Check this before you rely on it.
- **Indexes:** uuid to text is a plain cast. Indexes and unique constraints are rebuilt with the column, and each table is rewritten, which is fine at the current sizes.
- **Other uuid assumptions:** grep the pg paths for `UUID_PATTERN`, `isUuid` and `::uuid` casts in raw SQL.
- **Postgres tests:** the Postgres suites run only with `TEST_POSTGRES_URL`. Write them as `describeDialects` suites. CircleCI was unreliable on 2026-10-07, so the coordinator also runs them against a staging port-forward during review.

**Out of scope**
- Rerunning the staging data move: the coordinator does it after the merge.

**Decisions & gotchas**
- A uuid default cannot be cast to text automatically, so the upgrade runs `DROP DEFAULT`, `TYPE text USING col::text`, then `SET DEFAULT gen_random_uuid()::text` for primary keys. Without the first step the ALTER fails on every primary key.
- No foreign keys touch these columns in the pg schema (only `adventure_choices` to `adventure_sessions`, both text), so nothing needs dropping. Indexes and the unique `(card_id, serial_number)` index are rebuilt by the ALTER. Each table is rewritten once.
- The upgrade reads the uuid columns from `information_schema.columns`, filters in JS on `data_type` too (the FakePostgres used by the copy tests ignores SQL filters), and takes advisory lock `(1704, 1)`, the next free number after 1701 to 1703.
- Left as uuid on purpose: `user_cards.id`, `market_listings.user_card_id`, `user_inventory_items.equipped_to_card_id` (owned-card ids), `economy_items.category_id` and `economy_item_categories.id`, `game_items.id`, `user_inventory_items.item_id` (game item ids). The maintainer's scan found no slug values there. `game_achievements.reward_item_id` became text: it holds a catalog code or alias (`achievement-service.ts` passes it to `grants.grant`), which a uuid column could never store.
- Startup order: the upgrade runs before `runLegacyUpgrade` and `createBotServices`, so no seed or read sees a half-upgraded schema.
- Staging: the next bot or dashboard start upgrades it in place. The coordinator's planned drop and recreate of the staging schema also works, because a fresh schema is already text.
