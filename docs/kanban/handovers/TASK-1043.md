# TASK-1043 Handover: Interactive Real-Time Dungeon Tower Battles with Card Rendering, Manual & Auto Combat

## 1. Summary of Changes
- **Stateful Combat Engine (`DungeonBattleSession`)**:
  - Implemented `packages/services/src/waifu-tcg/dungeon/dungeon-battle-session.ts`:
    - Turn-based stateful combat tracking player HP, MP, shields, boss HP, wards, and active status effects.
    - Discrete actions:
      - `ATTACK`: Basic elemental strike (+15 MP, crit rolls, elemental matrix multiplier, affix modifier, elemental ward check, boss HP deduction).
      - `SKILL`: Active elemental skill (costs MP, deals 1.5x damage, applies elemental status effects like Burn or Freeze, breaks matching wards).
      - `DEFEND`: Tactical guard (+10 MP, halves incoming boss damage for the turn).
      - `executeAutoTurn()`: AI decision making (casts skill when MP >= cost, else attacks).
      - `forfeit()`: Concedes the match immediately.
    - Speed-based action ordering (faster unit strikes first).
    - Boss soft-enrage on turn 10+ (+100% ATK/turn with unblockable true damage strikes).
    - Status effect ticks and environmental affix ticks at start and end of turn.
    - `getSnapshot()`: Returns an immutable state snapshot for UI rendering.
- **Dungeon Runner Extension (`DungeonRunner`)**:
  - Refactored `prepareFloorSetup` to share prerequisite verification, energy consumption, and boss/affix initialization.
  - Added `createBattleSession(options)` to construct and start an interactive `DungeonBattleSession`.
  - Added `finalizeBattleResult(session, options)` to record floor attempts in `UserDungeonProgressRepository`, dispatch loot via `DungeonLootService`, and award milestone drops.
  - Exported `DungeonBattleSession` and related types in `packages/services/src/waifu-tcg/index.ts`.
- **Discord Interactive Combat Controller (`DungeonBattleManager`)**:
  - Implemented `apps/bot/src/commands/tcg/dungeon-battle.manager.ts`:
    - Renders the player's real card image via `services.cardImageService.getCardImage(baseCard, asset)` and attaches it to the battle message.
    - Real-time ASCII/Unicode progress bars for HP (`❤️ [██████████]`) and MP (`🔷 [█████░░░░░]`).
    - Elemental Ward HP bars and status badges (`🛡️ Ward Layer [ICE]: [████░░░░]`).
    - Live combat feed showing the last 4-5 action logs per turn with bold emojis.
    - Manual mode buttons: `⚔️ Attack`, `✨ Skill`, `🛡️ Defend`, `⚡ Auto`, `🏳️ Forfeit`.
    - Auto mode loop: steps turns every 1.5s with animated health bar shifts.
    - Auto mode controls: `⏸️ Pause Auto`, `⏩ Skip to End`, `🏳️ Forfeit`.
    - Post-battle navigation: `⚔️ Next Floor`, `🔄 Retry Floor`, `🏰 Tower Status`.
    - Inactivity safeguard: auto-resolves remaining turns after 60s idle so player energy is never lost.
- **Dungeon Command Wiring (`dungeon.command.ts`)**:
  - Added optional `mode` option (`manual` or `auto`, defaulting to `manual`).
  - Wired `/dungeon climb` and `handleTutorialClimb` into `DungeonBattleManager`.
  - Added quick-start `⚔️ Climb Floor {N}` button to `/dungeon status` embed.

## 3. Decisions & Gotchas
- In Discord embeds, attachments uploaded on the initial message are cached by Discord CDN and preserved across message edits. We omit the `files` parameter on subsequent turn edits to achieve fast (~50-100ms) real-time turn transitions without re-uploading the 800x1200 PNG on every turn.
- The auto-battle loop uses a 1.5-second delay between edits, keeping the edit rate at ~0.66/sec, safely under Discord's 5 edits per 5 seconds rate limit.
- If a player enters auto mode and wants immediate results, clicking `⏩ Skip to End` instantly computes the rest of the battle without delays and displays the final victory/defeat report with rewards.
