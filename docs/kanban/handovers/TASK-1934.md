**Bounded deletes (what I chose)**: every purge is a loop of statements of at most 5000 rows (`PURGE_BATCH_SIZE`): `DELETE ... WHERE id IN (SELECT id FROM t WHERE <time and status filter> LIMIT 5000)`, repeated until a batch removes fewer than 5000 rows. The subselect finds rows through the new time index; the delete is by primary key. The summary clearing is batched the same way (an `UPDATE` with the same subselect). The batches are not one transaction (a caller may pass `tx`, which keeps them in the caller's transaction). The grooming note said one statement per table is fine at current sizes and not to loop row by row; batching by 5000 is neither, and keeps the first purge after a long gap safe. Tests use `batchSize = 2` to cover the loop.
