## GROOMING · 2026-10-01T16:10:59Z · Claude Code (Opus 5.5)

**Approach**
1. Read the TASK-1261 `PROGRESS` entry and the fixture first.
2. Add an upgrade module to `@ririko/database` (for example `src/migration/upgrade.ts`, exported through `migration`) with `upgradeLegacyDatabase(target, { sourcePath, force?, dryRun?, log })`. It should:
   - return `skipped: no-source` when the file is missing;
   - hash the source with sha256 while copying it, plus any `-journal`, `-wal` or `-shm` file, into `mkdtemp(os.tmpdir())`;
   - run `ensureLegacyMigrationSchema(target)` (additive DDL like `ensureAdventureSchema`);
   - skip when that sha256 is already recorded;
   - skip, with a reason, when the target already has users and `force` is not set;
   - otherwise run `MigrationEngine.migrate` against the copy;
   - always remove the temporary copy.
3. Make the record part of the same transaction as the migrated rows. That needs a small change in `MigrationEngine.migrate`, for example an `onCommit(tx)` hook or a `record` option. Also make the engine refuse to commit when `coinsConserved` is false: throw inside the transaction so it rolls back.
4. Bot wiring in `apps/bot/src/main.ts`:
   - Create the client with `createDatabaseClient(databaseConfigFromEnv())`.
   - Run the upgrade when `LEGACY_DATABASE_PATH` is set.
   - Then call `createBotServices(client, bot.client)`.
   - Log one summary line: counts, coins and batch id.
5. Manual entry point `apps/bot/src/legacy-upgrade.ts`, compiled to `dist/legacy-upgrade.js`, with `--dry-run` and `--force`. It reuses the same function and prints the inspector audit. It runs in the bot image as `docker run --rm -v ./data:/app/legacy:ro -v ririko_data:/app/data <image> node apps/bot/dist/legacy-upgrade.js --dry-run`.
6. `LEGACY_DATABASE_PATH` goes in `AppConfigSchema` (optional) and is set to `ENV LEGACY_DATABASE_PATH=/app/legacy/ririko.db` in `bot-runner`. Do not create `/app/legacy` as writable: it stays a root-owned or absent mount point.
7. Smoke check, without bind mounts:
   - `docker create`, then `docker cp` a legacy database into `/app/legacy`, then `docker start`, then wait for the migration summary and `✓ Registered`.
   - Build that database from the committed fixture. One way: copy the `.sql` file into the container and build it there with the image's own better-sqlite3 (`node -e`). The smoke script stays dependency-free.
8. Docs:
   - `docs/migrations.md`: a new "Docker upgrade (read-only legacy mount)" section.
   - `docs/deployment.md` section 2.1: the env var and the `/app/legacy` mount point.

**Relevant code** (from CodeGraph during grooming)

- `packages/database/src/migrations/adventure-schema.ts:28` `ensureAdventureSchema`: the additive DDL pattern, including the Postgres advisory lock.
- `apps/bot/src/main.ts:44`: `createBotServices(undefined, bot.client)`. `apps/bot/src/services.ts:328` accepts a `customDb`.
- `apps/bot/src/services.ts`: `seedDefaultCatalog` (line 404), `seedAchievements` (line 923) and `syncCanonicalItems` (line 951) write to the target, so the migration must come first.
- `packages/database/src/client/factory.ts` `databaseConfigFromEnv` (BUG-0029).

**Pitfalls**
- **Never open the source path.** Not even read-only, and not for hashing: hash while streaming the copy.
- **Skip on a non-empty target:** a target that already has users means 2.0 ran before. Merging is possible (`onConflictDoNothing`), but it must be an explicit `--force`, not automatic.
- **Restarts:** a crash loop (`restart: unless-stopped`) must not re-run anything. The sha256 record makes it idempotent.
- **File types:** the `.sql` fixture is not TypeScript. Make sure the smoke script and the tests read it from the repository, not from `dist`.
- **Coverage:** keep `pnpm test:coverage` green with real tests for the new module.

**Out of scope**
- The old-layout fail-fast, the env aliases and the user guide (STORY-127).
- Any change to `.local/RirikoBot`.
- Docker Hub.

     - the hash is already recorded;

- From Git Bash, `docker run -e` paths need `MSYS_NO_PATHCONV=1`.
