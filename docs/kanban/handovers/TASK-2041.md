## PROGRESS · 2026-10-23T15:59:30Z · claude-medium (claude-sonnet-5-5) · REVIEW

**Files changed**
- `scripts/release/version-files.ts` (new): the 17 places as { path, pattern } pairs; one capture group around the version; `CURRENT_VERSION_FILE` = root package.json.
- `scripts/release/version.ts` (new): pure functions `isVersion`, `compareVersions`, `readVersions`, `setVersion`, `checkVersion` (all take a `root` and a file list) plus `main`. `setVersion` locates every place first (exactly one match each), checks x.y.z and greater-than-current against the root package.json, and only then writes by splicing the captured group, so line endings and all other text stay byte for byte. `--check <x.y.z>` lists places that differ and exits 1.
- `scripts/release/version.test.ts` (new): 28 tests on a temporary copy of the 17 files (success, decoy text with the old version untouched, CRLF/LF kept, refusals for bad format / not greater / zero or two matches / missing file / no capture group, `--check`, `main` exit codes). A guard test also reads the real repo: 17 places, ten package.json, all holding one version.
- `package.json`: added `"release:version": "tsx scripts/release/version.ts"`.

**Verification**
- `pnpm vitest run scripts/release`: pass (33 tests incl. release-tags). `pnpm typecheck`, `pnpm lint --quiet`, `pnpm format:check`: pass.
- `scripts/` is not part of the tsc projects, so I also ran tsc by hand on the new files (strict, exactOptionalPropertyTypes, noUncheckedIndexedAccess): clean.
- Manual: `tsx scripts/release/version.ts --check 2.1.0` exits 0; `... 2.0.0` is refused with "not greater than the current version 2.1.0" and nothing changed. No version was bumped in the repo.
- No commit made.

**Decisions & gotchas**
- "Current version" is the root package.json; the other places are not compared to it (they are expected to agree, and the guard test fails when they do not).
- Patterns do not anchor on line ends, so they work with CRLF and LF. The package.json pattern needs a two-space indent, so a nested "version" key cannot match.
- Prerelease versions (2.1.0-rc.1) are refused: x.y.z only, as the ticket says.
- scripts/ is outside the coverage gate (it covers packages/*/src and apps/*/src), so no threshold is affected.

**New CodeGraph queries**
- None beyond the two in the ticket.

**Next steps**
