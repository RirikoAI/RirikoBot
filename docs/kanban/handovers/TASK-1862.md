**Decisions & gotchas**
- `--single-transaction` is added to the groomed `pg_restore --clean --if-exists` command: with it a failed restore leaves the database unchanged. It implies `--exit-on-error`.
- The restore takes the shared deploy lock (`flock` on `/run/lock/ririko-deploy.lock`, fd 9) so a deploy, the nightly backup or the watchdog cannot overlap it; this mirrors `take_lock`.
- The restore docs tell the operator to start the version named in the dump file and to leave `state/` alone; the next deploy rewrites it. Nothing documents editing state files by hand.
- Docs say production is not expected to need adoption but must show `status` before the first approval; I did not claim how production was created.
- `docs/adr/ADR-015-versioned-schema-migrations.md` line 64 still says "The production compose file sets `DB_AUTO_MIGRATE=false`", which the maintainer decision reversed (compose defaults true, `ririko-deploy` forces false).
