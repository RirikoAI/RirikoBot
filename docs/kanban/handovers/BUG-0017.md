## 1. Summary of Work Accomplished

### 1.1. Root Causes & Problems
1. **Silent Fallback on Unrecognized Prefix Subcommands**:
   - Running `!card <invalid>` (e.g. `!card gears`) silently fell back to rendering the user's waifu collection album because `action = ctx.options.getString('action') ?? 'collection'`. No validation was performed on the unrecognized action, and no error or Did-You-Mean suggestion was provided to guide the player.
2. **Card ID Confusion with Character Mint Serial (`#0001/1000`)**:
   - In `/card` and `/cards` album listings, cards were rendered with `[#0001/1000]`.
   - In the database, `serial_number` is a per-character mint counter (the Nth copy of that specific waifu card generated in the game). When a player drops their first copy of Megumin, Tanya, and Harribel, each card receives `serial_number = 1`, which was formatted as `#0001/1000`.
   - Neither the true Card UUID (`user_cards.id`) nor the Card Catalog Number (`collection_number`) was displayed in the album or inspect views.
   - Consequently, users naturally assumed `#0001/1000` was their card identifier and attempted to run commands like `!card inspect #0001/1000` or `!card equip 1`, which failed because commands strictly queried for a full UUID (`WHERE user_cards.id = ?`).

### 1.2. Solution & Design Decisions
1. **Fuzzy Action Routing & Did-You-Mean Suggestions (`apps/bot/src/commands/tcg/card.command.ts`)**:
   - Added Levenshtein distance calculation to compare unrecognized prefix commands against all valid card subcommands (`collection`, `inspect`, `claim`, `favorite`, `equip`, `dismantle`, `gear`, `loadout`, `equip-gear`, `unequip-gear`, `unequip-all`, `guide`, `info`).
   - If an unrecognized action has an edit distance $\le 2$, Ririko replies with a helpful Did-You-Mean suggestion (e.g. `❌ Unknown action: gears. Did you mean /card gear?`).
   - If the distance is $> 2$, Ririko replies with an error listing all valid actions.
2. **Card Resolver Engine (`apps/bot/src/commands/tcg/card-resolver.ts`)**:
   - Implemented `resolveUserCard(cardRepo, userId, query)` supporting multiple flexible query formats:
     - Full 36-character UUID (exact match)
     - 8-character short ID prefix (e.g., `137b8c24`)
     - 1-based album list index (`1`, `2`, `3`, `#1`) matching the order shown in `/cards`
     - Character name substring match (e.g., `Harribel`, `Megumin`, `Tanya`, case-insensitive)
     - Serial number fallback (`#0001`, `1`)
   - Integrated `resolveUserCard` across all card actions: `inspect`, `favorite`, `equip`, `dismantle`, `gear`, `equip-gear`, `unequip-all`, and `loadout`.
3. **Auto-Inspect Shortcut Routing (`card.command.ts`)**:
   - If the first argument passed to `!card` matches a user card (by 1-based index or character name, e.g. `!card 1` or `!card Harribel`), Ririko automatically routes the command to the `inspect` action for that card instead of treating it as an invalid subcommand.
4. **Album & Inspect Embed UI Overhaul (`apps/bot/src/commands/tcg/cards.command.ts`)**:
   - **Album Listing**: Replaced the ambiguous `[#0001/1000]` display with explicit, disambiguated labels:
     `1. ⚔️ Tier Harribel (COMMON | WATER) — Lv.15 • ID: 137b8c24 • No. 107 (Mint #1)`
   - **Inspect View**: Added dedicated fields:
     - Title: `Tier Harribel (No. 107 • Mint #1)`
     - Body: `• **Card ID**: \`137b8c24\` *(Full: \`137b8c24-...\`)*`
     - Body: `• **Catalog**: \`No. 107\``
     - Body: `• **Edition**: \`Mint #1\``
     - Footer: `Tip: Use '!card inspect 1' or '!card inspect 137b8c24' to reference cards quickly.`
   - **Interactive Dropdown**: Updated select menu descriptions to display short ID and catalog number for fast reference.

## 3. Roadblocks, Gotchas & Decisions Made

- **Read-only `rawArgs` in TypeScript**:
  - `CommandContext.options.getRawArgs()` returns `readonly string[]`. Directly mutating `rawArgs[1]` was disallowed by TypeScript compiler (`TS2542`). Handled cleanly by using an `implicitCardId` variable passed to the inspect handler.
- **Card Resolution Order**:
  - Precedence was established as: UUID $\rightarrow$ 8-char short ID prefix $\rightarrow$ 1-based collection index $\rightarrow$ character name substring $\rightarrow$ serial number. This prevents ambiguous collisions between collection index 1 and character collection number 1.
