## 1. Summary of Work Accomplished

**Root cause.** Tutorial, dungeon loot and achievement rewards wrote made-up `item_id` values (`item_novice_blade`, `potion_hp_minor`, `weap_iron_greatsword`, ...) into `user_inventory_items`. `game_items` rows have UUID ids, and every reader (`LoadoutService`, potion dropdown, inventory) calls `findById`, so these rewards were invisible and could never be equipped or used. New players therefore entered S1 with no weapon and no potions.

**Changes**
- [item-grant.service.ts](file:///Z:/Projects/ririko-v2-2026/packages/services/src/waifu-tcg/equipment/item-grant.service.ts) (new): `ItemGrantService`, the single entry point for granting catalog items.
  - `resolveItem(key)`: catalog code, then legacy alias (`LEGACY_ITEM_CODE_ALIASES`), then `game_items.id`.
  - `grant` / `grantItem`: consumables stack into one IDLE row; equipment gets one row per instance with `slot: 'NONE'`.
  - `repairLegacyInventoryRows()`: remaps rows that carry alias ids to the real item ids. Idempotent.
- [tcg-item.repository.ts](file:///Z:/Projects/ririko-v2-2026/packages/database/src/repositories/tcg-item.repository.ts): `UserInventoryItemRepository.remapItemId(from, to)` (SQLite + PG).
- [tcg-shop.service.ts](file:///Z:/Projects/ririko-v2-2026/packages/services/src/waifu-tcg/equipment/tcg-shop.service.ts): purchase provisioning now goes through `ItemGrantService` (same behavior, duplicated logic removed).
- [tutorial-service.ts](file:///Z:/Projects/ririko-v2-2026/packages/services/src/waifu-tcg/dungeon/tutorial-service.ts):
  - `completeTutorial` ensures the starter card first, then `grantStarterGear` grants `WEAPON_NOVICE_BLADE` (once) and 3x `POTION_MINOR_HP`, and **equips the blade on the starter card when its WEAPON slot is empty**.
  - Completion message now uses real catalog names and stats (it previously claimed +20 ATK; the item gives +25).
  - T3 potion helpers use `ItemGrantService`; the unused `itemRepo` field was removed.
- [dungeon-loot.service.ts](file:///Z:/Projects/ririko-v2-2026/packages/services/src/waifu-tcg/dungeon/dungeon-loot.service.ts): rewards are catalog codes; only items that actually landed in the inventory are reported. `DungeonLootItem` is now `{ code, name, type, rarity, quantity }` taken from the catalog row. Takes a new `itemRepo` option.
- [achievement-service.ts](file:///Z:/Projects/ririko-v2-2026/packages/services/src/waifu-tcg/achievements/achievement-service.ts) + [seeds.ts](file:///Z:/Projects/ririko-v2-2026/packages/services/src/waifu-tcg/achievements/seeds.ts): item and consumable rewards go through `ItemGrantService`. Seeds use catalog codes, and aliases still resolve rows already in the DB. `rewardsDispatched.consumables` / `items` are keyed by item name. Takes a new `itemRepo` option.
- [services.ts](file:///Z:/Projects/ririko-v2-2026/apps/bot/src/services.ts): wires `itemRepo` into loot and achievements; runs `repairLegacyInventoryRows()` on boot after catalog seeding.

## 3. Roadblocks, Gotchas & Decisions Made
- **Summon tickets and titles were removed from dungeon milestone rewards.** Nothing in the codebase can store or use them, so granting them created dead rows. Existing `item_summon_ticket` / `title_tower_vanquisher` rows are left untouched (no data deleted). STORY-156 redesigns milestone rewards.
- **Crafting dust is shown but never stored** (loot message, `crafting_dust` achievement reward). This behavior is pre-existing. The `crafting_dust` achievement key is now skipped instead of creating a dead inventory row. Owned by STORY-160 (crafting, deferred).
- **`SQLITE_SCHEMA_DDL` is stale.** It lacks `user_cards.battles_won` and `is_favorite`, so a fresh auto-migrated SQLite DB fails `createUserCard`. The new test adds the columns with `ALTER TABLE` as a workaround. The DDL must be regenerated before STORY-151 adds `dungeon_bosses`.
- `@ririko/services` resolves `@ririko/database` through its `dist` types. After repository changes, run `pnpm -F @ririko/database build` before typechecking dependents.
