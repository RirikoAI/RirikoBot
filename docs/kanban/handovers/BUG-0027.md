# BUG-0027 — Count Every Stamina Potion in Multi-Quantity Uses

Status: REVIEW (2026-09-29), 2 points, parent STORY-043. Branch codex/fix-stamina-potion-quantity; base develop/2.0.0 at 42fb743. User requested fixing the daily-limit bypass through bulk use.

## Change

InventoryService previously multiplied restored energy by the requested quantity but sent one potion use to EnergyLifecycleService/PlayerEnergyRepository. The repository now accepts the individual potion quantity (default 1), rejects a batch larger than the remaining daily allowance, and adds that quantity under its existing transaction/row lock. The existing transaction argument remains compatible. Both the lifecycle and direct-repository inventory paths pass the count. Invalid fractional/nonfinite/nonpositive quantities are rejected.

With the default daily limit, using two stamina potions records 2/3. A following batch of four (or two) is rejected without consuming inventory or granting energy. One further potion reaches 3/3; more uses are rejected. Restoration still clamps to capacity, but every consumed potion counts even if its energy is clipped. Custom lower limits and configured reset boundaries remain respected. Single-item TCG consumables keep their existing default count of one. No database schema, live balances, or historical counters were edited.
