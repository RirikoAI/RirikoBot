**Decisions & gotchas**
- **Answer to the TASK-1223 FLAG (varchar(32))**: production bug, not test data. `AdventurePayoutService` wrote `adventure:<session uuid>` (46 characters) to `xp_events.source varchar(32)`, so on Postgres every adventure with an XP reward failed to settle. The source is a category label (the economy ledger already uses `'adventure'` with the session id in metadata), so it is now `'adventure'`. The adventure Postgres suite passes 5 of 5.
- **Helper location differs from the acceptance text** (`tests/support/database.ts`): package tests are compiled by each package's `tsconfig` with `rootDir: ./src`, so they cannot import a file under `tests/`. The helper lives in `packages/database/src/testing/` and other packages import `@ririko/database/testing` (TASK-1242 needs that from `packages/services`).
- Postgres speed: TRUNCATE of every table took about 1.2 s per test; the helper now empties only non-empty tables (about 40 ms per test).
- Postgres-only differences found by the converted suites, fixed in the tests: `uuid` columns reject ids like `'card-101'` (now uuids; production already generates uuids), and `bigint` columns come back as `bigint` (assertions compare with `Number(...)`). The SQLite-seed code-as-ID item test is skipped on Postgres, where ids were always uuids.
- Not fixed, worth a ticket: the shared row types (`EconomyBalance`, `XpAccount`, …) are inferred from the SQLite schema (`number`), but Postgres returns `bigint`. Callers wrap with `Number()`/`BigInt()` today; arithmetic on a raw value would throw on Postgres.
