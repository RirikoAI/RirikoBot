## GROOMING · 2026-10-22T02:10:00Z · claude-opus-5-5 (coordinator)

**Approach**
- `apps/bot/src/listeners/event-log.listener.ts` with `registerEventLogListener(client, services)`: one `client.on` per event, each with its own try/catch, forwarding to `services.eventLogService`. Export it from `listeners/index.ts` and register it in `main.ts` beside `registerMemberListener`.
- `packages/discord/src/client/factory.ts`: add `GatewayIntentBits.GuildModeration` to `DEFAULT_GATEWAY_INTENTS`, and update `client.test.ts`.
- `apps/bot/src/services.ts`: build the repository and service, add them to `BotServices`, and add an `eventBus.on('guild:configChanged')` that invalidates for `module === 'eventlogs'`, next to the commandOverrideService one.

**Pitfalls**
- `guildMemberAdd` and `guildMemberRemove` already have handlers (anti-raid, welcomer, farewell) in `member.listener.ts`. Add separate handlers in the new file; do not touch the old ones.
- `voiceStateUpdate` already has two listeners (XP and music). Add a third in the new file.
- `messageDeleteBulk` gives a Collection and the channel.

**Out of scope**
- Embed content and rules (TASK-1993), the dashboard (TASK-1995).

## PROGRESS · 2026-10-22T02:30:00Z · claude-medium (claude-sonnet-5-5) · REVIEW

**Files changed**
- `apps/bot/src/listeners/event-log.listener.ts` (new): `registerEventLogListener(client, services)` with one `client.on` per event (messageUpdate, messageDelete, messageDeleteBulk, guildMemberAdd/Remove/Update, guildBanAdd/Remove, channelCreate/Delete/Update, roleCreate/Delete/Update, voiceStateUpdate). Each handler runs through a small `guarded()` wrapper with its own try/catch that logs `[EventLog] Failed to log <event>:`. DM messages (`guildId` null) and DM channels (`isDMBased()`) are skipped before the service is called. `services` is typed `Pick<BotServices, 'eventLogService'>`.
- `apps/bot/src/listeners/index.ts`: exports it.
- `apps/bot/src/main.ts`: registers it after `registerGuildRegistryListener`. The existing member, voice and channelDelete handlers are untouched.
- `apps/bot/src/services.ts`: builds `EventLogService({ repo: new EventLogSettingsRepository(db) })`, adds `eventLogService` to `BotServices`, and calls `invalidate(guildId)` on `guild:configChanged` for module `eventlogs`.
- `packages/discord/src/client/factory.ts`: `GatewayIntentBits.GuildModeration` added to `DEFAULT_GATEWAY_INTENTS`. `client.test.ts` asserts it.
- Tests: `apps/bot/src/listeners/__tests__/event-log.listener.test.ts` (new: every event forwarded with the same arguments, an error in each handler caught and logged, one failure does not stop the next event, DM skips) and two cases in `apps/bot/src/guild-config-sync.test.ts` (cache dropped on an `eventlogs` change through the real change feed; not dropped for another module).

**Verification**
- `pnpm build` clean. `verify_cmd` passes: listeners and client tests (122), bot and discord typecheck, `pnpm lint --quiet`, `pnpm format:check`. `vitest run apps/bot packages/discord` passes (89 files, 1267 tests).
- No commit made.

**Decisions & gotchas**
- Test file is in `listeners/__tests__/` (beside the other new listener tests) rather than `listeners/event-log.listener.test.ts`; `guild-config-sync.test.ts` is added to `context.files`.
- The service guards `guild` itself, but a `PartialMessage` in a guild still reaches it; the listener checks only `guildId`.
- The bot needs the GuildModeration intent only on the gateway; it is non-privileged, so no Developer Portal change. TASK-1996 docs should say bans are logged only after the bot restarts on this build.

**New CodeGraph queries**
