## 1. Summary of Work Accomplished

### 1.1. Root Cause & Problem
Discord select menus (`StringSelectMenuBuilder`) have a protocol limit of at most 25 options. Previously, in three interactive TCG menus:
1. **`/card gear` / `/loadout` (`gear-menu.ts`)**:
   - `for (const uc of userCards.slice(0, 25))` only loaded up to 25 cards. Any cards beyond index 24 were completely unreachable, and selecting them via direct argument or dropdown failed.
   - `candidates.slice(0, 25)` silently dropped spare gear in the selected slot beyond index 24.
2. **`/item craft` (`craft-menu.ts`)**:
   - `recipes.slice(0, 25)` truncated the recipe list at 25. With 26 craft recipes in the active catalog (e.g. in the `ALL` category), the 26th recipe was already silently invisible and uncraftable via menu.
3. **`/item shop` (`shop-menu.ts`)**:
   - `items.slice(0, 25)` truncated shop items at 25 with no indication of remaining stock or pagination.

### 1.2. Solution & Design Decisions
1. **Interactive Pagination Component Architecture**:
   - Discord permits at most 5 `ActionRow`s per message.
   - **`gear-menu.ts`**:
     - Preserves up to 4 base rows: Card Menu (Row 0), Slot Menu (Row 1), Gear Item Menu (Row 2), Action Buttons (Row 3: Equip, Unequip, Enhance, Unequip All, Close).
     - Dynamically attaches a 5th `ActionRow` for pagination controls when `totalCardPages > 1` or `totalCandidatePages > 1`:
       - If both paginate: `[◀ Card] [Card ▶] [◀ Gear] [Gear ▶]` (4 buttons).
       - If cards only: `[◀ Prev Cards] [Cards X/Y (disabled)] [Next Cards ▶]` (3 buttons).
       - If gear candidates only: `[◀ Prev Gear] [Gear X/Y (disabled)] [Next Gear ▶]` (3 buttons).
     - Displays visible indicator in embed description: `📄 Collection: Cards X–Y of N (Page P/T) · Gear A–B of M (Page Q/K)`.
     - Select menu placeholders reflect active page and collection count.
     - `loadGearMenuState` automatically calculates and navigates to the page containing any requested `cardId` or `selectedItemId`.
   - **`craft-menu.ts`**:
     - Slices active recipes by 25 with `page` state.
     - Embed description displays `📄 Recipes: Showing X–Y of N (Page P/T)`.
     - Adds a dedicated pagination button row (`[◀ Prev] [Page X / Y (disabled)] [Next ▶]`).
     - Collector handles `craft:prev` and `craft:next`.
   - **`shop-menu.ts`**:
     - Slices active catalog items by 25 with `page` state.
     - Embed description displays `📄 Catalog: Showing X–Y of N (Page P/T)`.
     - Adds a dedicated pagination button row (`[◀ Prev] [Page X / Y (disabled)] [Next ▶]`).
     - Collector handles `shop:prev` and `shop:next`.
2. **Automated Verification**:
   - Added unit test to `apps/bot/src/commands/tcg/__tests__/gear-menu.test.ts` with 30 cards and 28 candidate items, testing page 0 and page 1 navigation, button disabled states, and combined controls.
   - Added unit test to `apps/bot/src/commands/tcg/__tests__/craft-menu.test.ts` with 27 recipes verifying 2-page pagination.
   - Added unit test to `apps/bot/src/commands/tcg/__tests__/shop-menu.test.ts` with 28 shop items verifying 2-page pagination.

## 3. Roadblocks, Gotchas & Decisions Made

- **Component Limits**: Discord messages strictly forbid more than 5 ActionRows and more than 5 buttons per ActionRow. By dynamically showing pagination only when pages $> 1$ and combining card + gear controls into a 4-button row, the layout never exceeds Discord's constraints.
- **Direct Card ID Navigation**: When players pass `card_id` to `/card action:gear` or `/loadout`, `loadGearMenuState` computes the exact target card index and sets `cardPage = Math.floor(targetIndex / 25)`, immediately showing the requested card on its page without requiring manual clicking.
