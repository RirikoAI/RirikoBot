**Approach**
1. `deploy/host/bootstrap.sh`: parse `--ref`, `--deploy-key`, `--tunnel-token-file`, `--help`. Check root and `/etc/os-release` (`ID=ubuntu`, `VERSION_ID="24.04"`).
2. Download `https://codeload.github.com/RirikoAI/RirikoBot/tar.gz/<ref>` into a temporary directory and extract only `*/deploy/host`. Install `bin/*.sh` and `systemd/*` with `install -m`. `bin` and `systemd` may be empty in this task; keep a `.gitkeep` and skip it.
3. Packages: Docker's apt repo (`/etc/apt/keyrings/docker.asc`, `signed-by`), `docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin`; Cloudflare's repo (`https://pkg.cloudflare.com/cloudflared`, key `/usr/share/keyrings/cloudflare-main.gpg`); `unattended-upgrades`, `jq`, `curl`, `ca-certificates`.
4. Static files in `deploy/host/files/`: `daemon.json`, the sshd drop-in, the sudoers rule and the unattended-upgrades override. Install each with `cmp -s || install`, so the script knows whether to restart Docker or reload ssh.
5. User, layout, config example, the final "next steps" message.
6. `.gitattributes`: `deploy/host/** text eol=lf`.
7. CircleCI `lint` job: `sudo apt-get install -y -qq shellcheck`, then `find deploy/host -name '*.sh' -print0 | xargs -0 shellcheck`.
8. `scripts/deploy-host.test.ts`: no CRLF under `deploy/host`, `bash -n` on every `.sh`, `bootstrap.sh --help` exits 0. Spawn `bash` with `spawnSync`; skip the bash cases with a clear reason only when no `bash` is on PATH.

**Relevant code**
- `scripts/release-tags.test.ts`: how script tests are structured in this repository.
- `.circleci/config.yml` `lint` job.

**Pitfalls**
- Ubuntu 24.04 starts sshd through `ssh.socket`. Run `sshd -t`, then `systemctl reload ssh` only when the service is active; the drop-in changes no ports, so the socket needs no change.
- `/etc/ssh/sshd_config.d/*.conf` is read in lexical order and the first value wins. Name the drop-in `10-ririko.conf` so it beats `50-cloud-init.conf`, which Lightsail images use to enable password login.
- The `deploy` user needs a real login shell (`/bin/sh`) for the forced command to run, and no password (`passwd -l`).
- Lightsail's default user is `ubuntu`; keep it in `AllowUsers` or you lock yourself out.
- `cloudflared service install <token>` puts the token in the systemd unit; that is Cloudflare's documented way. Read it from the file so it is not in shell history.
- Do not touch ufw. The Lightsail firewall is the network boundary, and Docker-published ports bypass ufw anyway.

**Out of scope**
- The deploy, backup and watchdog scripts (TASK-1781, TASK-1791, TASK-1792).
- Running the bootstrap against a real host. The maintainer does that on staging.

**Decisions & gotchas**
- `sshd-10-ririko.conf` has the four directives from the live hosts plus one comment line. The comment text on the hosts may differ, so the first run on them rewrites that file once (same effective config) and reloads ssh after `sshd -t`; every run after that is a no-op. The same applies to `/etc/apt/apt.conf.d/20auto-upgrades` if the image's copy differs from ours.
- Swap and swappiness are checked by state (any active swap; a `vm.swappiness = 10` line), not by file content, so the hand-made hosts are left as they are. The Docker and Cloudflare apt sources are skipped when any file under `/etc/apt/sources.list*` already mentions `download.docker.com` or `pkg.cloudflare.com/cloudflared`, so the live `cloudflared.list` is not touched and no conflicting duplicate source is created.
- `install -d -m 0750` resets the mode of an existing `/opt/ririko` tree and `/etc/ririko` to 0750 root:root.
- Timers are enabled and started on every run, even before `ririko.conf` and the first deploy exist, so TASK-1791 and TASK-1792 must exit cleanly (or ping a failure) when unconfigured.
- Ubuntu 24.04 ships sshd socket-activated, and `/run/sshd` may not exist before the first connection; the script creates it so `sshd -t` works.
- `--deploy-key` accepts one line: ed25519, rsa, ecdsa or sk keys, with an optional comment holding no double quote or control character.
- Git Bash and WSL both provide a `bash` on this machine; `spawnSync('bash')` in the test uses whichever comes first, and stdin keeps it path-independent.
