**Pitfalls**
- Ubuntu 24.04 starts sshd through `ssh.socket`. Run `sshd -t`, then `systemctl reload ssh` only when the service is active; the drop-in changes no ports, so the socket needs no change.
- `/etc/ssh/sshd_config.d/*.conf` is read in lexical order and the first value wins. Name the drop-in `10-ririko.conf` so it beats `50-cloud-init.conf`, which Lightsail images use to enable password login.
- The `deploy` user needs a real login shell (`/bin/sh`) for the forced command to run, and no password (`passwd -l`).
- Lightsail's default user is `ubuntu`; keep it in `AllowUsers` or you lock yourself out.
- `cloudflared service install <token>` puts the token in the systemd unit; that is Cloudflare's documented way. Read it from the file so it is not in shell history.
- Do not touch ufw. The Lightsail firewall is the network boundary, and Docker-published ports bypass ufw anyway.
