## GROOMING · 2026-10-24T14:10:00Z · claude-opus-5-5 (coordinator)

**Found** on 2026-10-24: the maintainer posted a screenshot of a live `/profile`. Discord shows the 1200x400 PNG about 690 px wide (57%), so the 11 to 13 px labels end up 6 to 7 px tall. The wallet, bank, total XP, karma and card-slot emoji are empty boxes. The slot says NO CARD EQUIPPED even though cards can be equipped.

**Causes** (checked in the code)
- Emoji: `profile-card.renderer.ts` draws `🪙 🏦 ⭐ ✨ 🎴` with `fillText` (lines 422, 477, 489, 501, 707, 772). No code registers a font with `GlobalFonts`, and the Dockerfile (line 75) installs only `fonts-dejavu-core`, which has no emoji. Skia draws `.notdef` boxes even on a host that has Noto Color Emoji (reproduced in this container). No other canvas renderer (welcomer, TCG card, memes, boss) draws emoji, so the fix is drawn icons, not a new font.
- Small text: fonts are `bold 11px` (stat labels, watermark), `12px` (rank pills, remaining XP, hint), `13px` (karma, XP header) and `16px` (handle, level). There is no text at all between y 290 and y 400 in the middle column.
- Equipped card: `profileCommand.execute` (`apps/bot/src/commands/economy/commands.ts` lines 401-430) calls `renderFromRepositories` without `equippedCard`. Nothing else sets it. A card is equipped with `/card action:equip id:<id>` (`apps/bot/src/commands/tcg/card.command.ts` lines 442-480); it sets the user card's `state` to `EQUIPPED` and every other card of that user to `IDLE`, so there is at most one. `/tcg` is only a prefix alias of `card`, so the hint `/tcg equip` (renderer line 796) is wrong for slash.
- Presence: the command passes `presenceStatus: 'online'` (commands.ts line 411). `apps/bot` never requests `GuildPresences`, so the dot is always green, whatever the member's real status.
- Name: `target.displayName` is the account's global name, not the server nickname.
- Background: `drawBackground` (renderer line 262) calls `drawImage(bgImage, 0, 0, 1200, 400)`. The comment says "cover", but it stretches. `ProfileBackgroundManager` accepts any size up to 1200x400 (`profile-background.manager.ts` lines 48-49), so a 600x400 image gets stretched 2x horizontally. The overlay alphas 0.86 to 0.94 also hide almost all of the image.

**Approach**

1. *Layout* (keep the 1200x400 canvas: backgrounds are validated against it, and docs/economy.md section 2.2 says 1200 x 400). Minimum text size is 20 px; main values are at least 30 px. Suggested positions, which you may adjust if the render looks better:
   - Left column: avatar radius about 80 centred near (125, 140); level pill about 170x46 with `bold 26px` `LVL 50`; the karma line below it at 22 px with a drawn sparkle.
   - Middle column (x 250 to 925): display name `bold 44px` (truncated so it ends before the rank pills); `@username` at 22 px; SERVER and GLOBAL rank pills about 150x40 with `bold 20px`, right-aligned to x 925; three stat panels about 215x100 with a `bold 20px` label and a drawn icon plus a `bold 32px` value (truncated to fit); `EXP PROGRESS` and `962 / 15,100 XP (6.4%)` at 22 px; a bar about 30 px tall; `14,138 XP to Level 51` at 22 px. Remove the `RIRIKO AI 2.0 • LEVELING & FINANCIAL ENGINE` watermark.
   - Card slot: x 945, y 20, 240x360. That is 2:3, the shape of the 800x1200 TCG card (`CARD_WIDTH`/`CARD_HEIGHT` in `waifu-tcg/canvas/card-synthesizer.ts` lines 53-54).
2. *Icons*: add small private drawing helpers in the renderer (coin, bank, star, sparkle, card) made from arcs and paths, drawn in the value colour. Keep them in `profile-card.renderer.ts`: a new source file would need its own coverage (AGENTS.md rule 10).
3. *Equipped card, command side*: in `profileCommand.execute`, before rendering:
   - `const [userCard] = await services.waifuCardRepo.listUserCards(target.id, { state: 'EQUIPPED' })`
   - `base = await services.waifuCardRepo.findById(userCard.cardId)`
   - `asset = base.assetId ? await services.waifuAssetRepo.findById(base.assetId) : null`
   - `source = asset ? await services.waifuAssetRepo.findSourceById(asset.sourceId) : null`
   - `png = await services.cardImageService.getCardImage(base, asset, { attributionText: getCardAttribution(source).footerText, maxCollectionNumber: await services.waifuCardRepo.count() })`
   - Pass `equippedCard: { id: userCard.id, name: base.name, rarity: base.rarity, imageBuffer: png }`.

   These are the same arguments as `attachCardImage` and `buildCardInspectEmbed` in `apps/bot/src/commands/tcg/cards.command.ts` (lines 48-69 and 207-212). `getCardAttribution` is exported from `@ririko/services` (`packages/services/src/waifu-tcg/attribution.ts` line 17). Wrap the whole lookup in try/catch: on any error, `console.warn` once and render without the card.
4. *Equipped card, renderer side*: in `drawTcgCardSlot`, when the card image (buffer or URL) loads, draw it contain-fit in the slot, clipped to a rounded rect (radius about 16), with a border in the rarity colour. Do not draw the old name banner, rarity pill or serial on top: the rendered card already shows its name and rarity. When no image loads, draw the frame, a drawn card icon, the card name (`bold 22px`, truncated) and the rarity label (20 px). The empty slot keeps the dashed frame, a drawn card icon, `NO CARD EQUIPPED` (`bold 22px`), a 20 px subtitle and a hint pill `/card action:equip` at 20 px or more.
5. *Presence and name*: `member = target.id === ctx.user.id ? ctx.member : await ctx.options.getMember('target')`. Use `member?.displayName ?? target.displayName ?? target.username` as the display name. Use `member?.presence?.status` as the presence, with `invisible` mapped to `offline`; leave it undefined when it is unknown. In `renderFromRepositories`, drop the `?? 'offline'` default. In `drawAvatarSection`, draw the dot only when `presenceStatus` is set.
6. *Background*: cover-crop. `scale = max(1200 / w, 400 / h)`, then use the 9-argument `drawImage` with a centred source rectangle of `1200 / scale` by `400 / scale`. Lower the overlay to about 0.55 to 0.7 alpha so the image shows; the stat panels keep their own dark fill for contrast.
7. *Docs*: in `docs/economy.md`, line 10 and the section 2.2 row for `/profile`, say that the card also shows the equipped Waifu TCG card, set with `/card action:equip`.
8. *Preview*: render the empty-slot, equipped-card and custom-background cards to PNG files outside the repository (for example in the OS temp folder). Look at each one and list the paths in the PROGRESS entry, so the coordinator can check the layout.

**Tests**
- Renderer (`profile-card.renderer.test.ts`): spy on the 2D context prototype, `Object.getPrototypeOf(createCanvas(1, 1).getContext('2d'))`. Wrap `fillText` so it records `[text, this.font]` and still calls the original; restore it afterwards. This was tried during grooming and works with `@napi-rs/canvas`. For the empty-slot, equipped-card (imageBuffer), broken-image and custom-background renders, assert:
  - no text matches `/\p{Extended_Pictographic}/u`;
  - every font size is at least 20 px;
  - the empty slot draws `/card action:equip`, and the equipped card does not draw `NO CARD EQUIPPED`.
- Spy on `drawImage` the same way:
  - the 600x400 background is drawn with a centred 600x200 source rectangle;
  - the card image is drawn contain-fit (2:3).
  - Also cover the dot being drawn only with a presence.
- Command (`commands.test.ts`): the suite uses real `createBotServices` with SQLite. Mint a card definition and an `EQUIPPED` user card (see `packages/database/src/repositories/waifu-card.repository.test.ts` and `packages/database/src/testing/copy-fixture.ts` line 117). Spy on `services.cardImageService.getCardImage` with a small PNG and on `services.profileCardRenderer.renderFromRepositories`. Assert:
  - the options carry `equippedCard.imageBuffer`, and the `getCardImage` arguments carry `attributionText` and `maxCollectionNumber`;
  - when `getCardImage` rejects, the profile still replies with the PNG and no `equippedCard`;
  - with no equipped card, `equippedCard` is undefined;
  - with a `ctx.member` that has `displayName` and `presence.status`, both are passed; with no member, `presenceStatus` is undefined.

**Pitfalls**
- `getCardImage` writes `public/cards/<cardId>.png` into the workspace on a cache miss, and keeps the first render. In tests, always spy on it so nothing is written to the repository. In code, always pass the attribution like `/card inspect` does; otherwise a profile view could cache a card without its source credit.
- Workspace packages resolve from `dist` (`packages/services/package.json` exports). After you change `packages/services/src`, run `pnpm build` before the `apps/bot` tests; `verify_cmd` starts with it.
- `ctx.options.getMember` on slash can return the raw API member when the guild is not cached. Read `displayName` and `presence` optionally and fall back as in step 5.
- The test mock context (`commands.test.ts` lines 10-69) sets `member: null` and `getMember: async () => null`. Extend the helper with an optional `member` parameter rather than casting inside each test.
- The existing profile test expects the reply text `Profile Card for Saber`, which uses the username. Leave the reply text as it is.
- `apps/bot/src/commands/economy/commands.ts` as a whole is below the coverage thresholds today (branches 49.7%). That is why `verify_cmd` checks file coverage of the renderer only. Do not try to raise the whole file.

**Out of scope**
- Canvas size, the background size limit, and `ProfileBackgroundManager`.
- Adding the `GuildPresences` intent or any Dockerfile font package.
- `/profile` in DMs, where it shows level 0 because levels are per server.
- Other commands and canvas renderers.
