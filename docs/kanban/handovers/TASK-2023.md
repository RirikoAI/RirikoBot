**Relevant code** (from CodeGraph during grooming)

**Pitfalls**
- On prefix, the emoji argument may come before or after the threshold. Accept `setup #channel [emoji] [threshold]` in that order only, and say so in the usage text.
- A custom emoji from another server passes the schema but cannot be reacted with. Warn when its ID is not in `guild.emojis.cache`, but do not refuse.
- For the warning check, use `channel.permissionsFor(guild.members.me)` with ViewChannel, SendMessages and EmbedLinks.

**Decisions & gotchas**
- `off` saves `channelId: null` (the schema's `OptionalSnowflakeSetting` turns an empty value into null); emoji, threshold, self-star and ignored channels are kept. If it is already off, it says so and saves nothing.
- On prefix a lone number after the channel (`setup #chan 5`) is read as the threshold, since a number is never a valid emoji; otherwise the order is emoji then threshold. A non-numeric threshold word is refused with the 1 to 100 hint; a value out of range goes to the schema and its message is shown. More words than the action takes reply with the usage.
- `setup` accepts only text and announcement channels, found by mention or ID (cache, then fetch). The warning for missing View Channel, Send Messages or Embed Links uses `channel.permissionsFor(guild.members.me)` and is skipped when the bot member is not cached. The custom-emoji warning uses `parseStarboardEmoji(saved.emoji).id` against `guild.emojis.cache`; neither warning refuses.
- `ignore` toggles: an ID already in the list is removed without looking up the channel (so a deleted channel can be removed); a new one must exist. The 25-channel maximum comes back from the schema message.
- Replies to slash are ephemeral and end with the dashboard hint (**Starboard** page, Engagement section).
