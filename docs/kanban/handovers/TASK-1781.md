## GROOMING · 2026-10-04T18:50:17Z · Claude Code (Opus 5.5)

**Approach**
1. `deploy/host/bin/ririko-deploy-ssh.sh` (runs as `deploy`): split `SSH_ORIGINAL_COMMAND` with `read -r -a`, require exactly `deploy <version>` or `status`, check the version regex, then `exec sudo -n /usr/local/bin/ririko-deploy "$@"`.
2. `deploy/host/bin/ririko-deploy.sh` (runs as root): the steps in the acceptance list, in that order. Read defaults from the environment, then `/etc/ririko/ririko.conf`: `RIRIKO_REPO=RirikoAI/RirikoBot`, `RIRIKO_ENV_FILE=/opt/ririko/.env.production`, `READY_TIMEOUT=300`, `RIRIKO_LOCK=/run/lock/ririko-deploy.lock`.
3. Compose call: `RIRIKO_VERSION=<v> RIRIKO_ENV_FILE=<env> docker compose -p ririko -f <release>/docker-compose.production.yml --env-file <env> ...`. The compose file mounts `./docker/lavalink/application.yml`, which resolves from the release directory.
4. Readiness:
   - bot: `docker compose exec -T bot node -e "fetch('http://127.0.0.1:'+(process.env.HEALTH_PORT||8080)+'/ready').then(r=>process.exit(r.ok?0:1),()=>process.exit(1))"`;
   - web: the same against `http://127.0.0.1:3000/api/ready`.
5. Add the config keys to `deploy/host/ririko.conf.example` with comments.
6. Tests in `scripts/deploy-host.test.ts`: a temporary `RIRIKO_ROOT`, a fake `docker` that logs its argv to a file and fails on demand, and a fake `curl` that writes the two files.

**Relevant code**
- `scripts/release-tags.ts:14` `RELEASE_TAG_PATTERN` allows any prerelease suffix (`-.+`). The host regex is deliberately stricter because the version becomes part of a URL and a path.
- `apps/bot/src/health.ts:41-82` `probe` and `healthPort`.
- `apps/web/src/lib/server/health.ts:18` `webProbe`; the routes are `apps/web/src/app/api/ready/route.ts` and `/api/health`.
- `Dockerfile:99-122`: the HEALTHCHECK commands use the same `node -e fetch` approach, because the images have no curl.

**Pitfalls**
- Lock exit 3, rollback exit 4, failed first deploy exit 5, rejected command exit 2. TASK-1782 documents these, so keep them stable.
- Use plain files for `state/current` and `state/previous`; symlinks behave differently under Git Bash on Windows, where the tests also run.
- `docker compose exec` fails while a container restarts. Treat any error as not ready and keep polling.
- `sudo` resets the environment. Pass the words as arguments, never through environment variables.
- The bot's `/ready` needs a valid Discord token, so staging needs its own Discord application.
- Rolling back the image is safe only while schema changes are additive (`ensurePostgresSchema`). The exit message must name the pre-deploy dump for a manual restore.

**Out of scope**
- CircleCI changes (TASK-1782). Locking for backup and watchdog (TASK-1791, TASK-1792), apart from defining the lock path.
