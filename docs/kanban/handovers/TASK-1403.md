# Handover Note: [TASK-1403] ReactionRole Engine: Multi-Mode Emoji, Button & Select Menu Handlers

## 1. Summary of Changes
- **Reaction Role Service**:
  - Implemented `ReactionRoleService` in `packages/services/src/roles/reaction-role.service.ts`:
    - `hasPermission(guild)`: verifies bot's `ManageRoles` permission.
    - `isValidRole(guild, roleId)`: verifies role existence, guards against `@everyone` and managed bot integration roles, and enforces bot role position hierarchy.
    - `canManageMember(guild, member)`: protects guild owner and enforces hierarchy relative to target member.
    - `applyRoleMode`: handles 4 distinct role assignment modes:
      - `TOGGLE`: adds role if absent, removes if present.
      - `GIVE_ONLY`: grants role only, unreacting or re-clicking does not remove.
      - `REMOVE_ONLY`: removes role only.
      - `UNIQUE`: mutually exclusive radio group; removes any other roles in the same `groupId` before granting the selected role.
    - `handleReactionAdd(guild, messageId, emoji, member)`: handles emoji reaction add events.
    - `handleReactionRemove(guild, messageId, emoji, member)`: handles emoji reaction remove events (respects `GIVE_ONLY`).
    - `handleButtonInteraction(interaction)`: parses `rr:btn:<bindingId>` and `rr:btn:role:<roleId>:<mode>:<groupId?>`, validates permissions and hierarchy, applies mode, and replies with ephemeral confirmation.
    - `handleSelectMenuInteraction(interaction)`: parses `rr:select:<messageId>` or `rr:select:group:<groupId>`, synchronizes selected and unselected roles in the group, and replies with ephemeral confirmation.
- **Service Exports**:
  - Exported `ReactionRoleService` from `packages/services/src/roles/index.ts` and `packages/services/src/index.ts`.
  - Built `@ririko/services` via `tsc`.

## 3. Decisions & Gotchas
- Ephemeral replies in `handleButtonInteraction` and `handleSelectMenuInteraction` fallback to default messages (`Role updated.`) to satisfy `exactOptionalPropertyTypes: true` compiler strictness.
- In `UNIQUE` mode, only roles within the specified `groupId` that the user currently holds are removed, preventing accidental revoking of unrelated roles.
