## GROOMING · 2026-10-21T12:30:00Z · claude-opus-5-5 (coordinator)

**Approach**
1. `EnergyLifecycleService`: add `nextResetAt(now = new Date()): Date`, which returns `getNextResetAt(now, this.resetSchedule)` (`@ririko/core`, `packages/core/src/time/reset-schedule.ts:131`). Add a unit test in `reset-boundary.test.ts`.
2. New `apps/bot/src/commands/tcg/energy.command.ts`, `createEnergyCommand(services)`, in the style of `achievement.command.ts`:
   - Metadata: `name: 'energy'`, `category: CommandCategory.TCG`, `aliases: ['stamina']`, a usage line and examples, no options. Do not set `isGuildOnly`: energy is global, so it works in DMs.
   - `execute`: `const energy = await services.energyLifecycleService.getOrReconcileUserEnergy(ctx.user.id)` and `const rules = await services.energyLifecycleService.rules()`.
   - Reply with one embed, in the colours and emoji style of `/dungeon action:status`. Its fields:
     - **Energy**: `currentEnergy / (maxEnergy + bonusEnergy)`.
     - **Level cap**: `maxEnergy`.
     - **Bonus energy**: `bonusEnergy / maxBonusCap`, plus "+<dailyBonusIncrement> at the next reset" while `bonusEnergy < maxBonusCap` and `dailyBonusIncrement > 0`.
     - **Potions today**: `dailyEnergyPotsUsed / dailyPotionLimit`.
     - **Next refill**: `<t:${Math.floor(nextResetAt.getTime() / 1000)}:R>`.
     - Footer: "Energy refills at each daily reset. /dungeon, /game, /adventure and duels use it."
   - Slash replies are not ephemeral, which matches `/dungeon action:status`.
3. Register it: export it from `apps/bot/src/commands/tcg/index.ts`, and add `createEnergyCommand(services)` after `createDungeonCommand` in `registerBotCommands` (`apps/bot/src/command-set.ts:129`).
4. Tests in `apps/bot/src/commands/tcg/__tests__/energy.command.test.ts`, with the mocked context of `dungeon.command.test.ts` and a fake `energyLifecycleService` (`getOrReconcileUserEnergy`, `rules`, `nextResetAt`):
   - a slash call (embed values);
   - a prefix call `!energy`;
   - a player at the bonus cap (no "+5" text);
   - a call without a guild (DM).
5. Docs:
   - `docs/commands.md` section 7.8: add the row `| /energy | stamina | Shows your energy, bonus energy and next refill. | Everyone |` after `/dungeon`.
   - `docs/tcg-player-guide.md` section 4: replace "You can see your energy with `/dungeon action:status`." with `/energy`. Add a short paragraph on bonus energy: +5 at each daily reset, kept up to 50, refilled with the pool, and the bot owner can change both values.
   - Keep the docs' style: simple English, short sentences.

**Pitfalls**
- `command-set.test.ts` checks the global count and the guild-scoped list. `/energy` is global (the default `registrationScope`).
- The help generator and the website command list read the registry, so they need no change.
- A name collision: no command or alias named `energy` or `stamina` exists (checked 2026-10-21). `/adventure` has an `energy` option, which is unrelated.

**Out of scope**
- Changing the energy rules or the status embed of `/dungeon` (BUG-0050 does that).
