## GROOMING · 2026-10-10T13:35:44Z · claude-opus-5-5 (coordinator)

**Report** (maintainer, `pnpm cli db:migrate` on the development database): the four adoption notes, the backup path and the adoption print twice, and the run ends with "✔ Nothing to do: the database is up to date (0000_baseline)."

**Root cause**
- `runDbMigrate` (`apps/cli/src/commands/db-migrate.ts`, around line 134) collects every `log.info` and `log.warn` line from `migrateDatabase` into `logged` and prints them.
- It then prints its own summary: `Backup:`, `adoptionLines(result, 'recorded')`, and the last line.
- `runner.ts` logs the backup (line 577), every adoption note (line 599) and "Adopted the existing database" (line 600). These logs are right for bot startup, which has no summary.
- The last line only checks `result.applied.length` and ignores `result.adoption`.

**Approach**
- Change only the CLI. Drop the runner's info lines from the output.
- Keep the warnings, except the ones whose text is in `result.adoption?.notes`. A `Set` is enough.
- Pick the last line from `result.adoption` and `result.applied`.

**Out of scope**
- The runner's logging (the bot startup log).
- The dry run output.
