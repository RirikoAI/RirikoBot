## GROOMING · 2026-10-02T05:25:08Z · Claude Code (Opus 5.5)

**Approach**
- 1.4.0 reaction roles had no channel, so the migration writes `channel_id = guild_id` (`transformer.ts:349`). Keep that as the marker.
- Next to `ReactionRoleRepository`, add:
  - one helper that says whether a row's channel is unknown;
  - one method that sets `channel_id` on every row of a message.
- `apps/bot/src/listeners/reaction.listener.ts:33`: after `findByMessageAndEmoji`, check the row. If its channel is unknown, save `reaction.message.channelId`, then grant or remove the role as before.
- `apps/bot/src/commands/roles/reaction-roles.command.ts:101-106`: skip `channels.fetch` when the channel is unknown, and still delete the row.
- `apps/web/src/lib/server/guilds/reaction-role-panels.ts` (lines 147, 247, 271, 289, 333, 432):
  - Keep rows with an unknown channel out of every Discord call.
  - Return a flag so the panel shows "channel unknown, react once to link it" and builds no jump link.

**Pitfalls**
- For partial reactions, `reaction.message.channelId` is available without fetching.
- The web panel must list rows with an unknown channel read-only, without failing validation.

**Out of scope**
- A startup scan of guild channels. The maintainer chose the lazy backfill.

## PROGRESS · 2026-10-02T05:37:29Z · Claude Code (Opus 5.5) · REVIEW

**Files changed**
- `packages/core/src/config/reaction-roles.ts`: new `isReactionRoleChannelUnknown` (`channelId === guildId`).
- `packages/database/src/repositories/reaction-role.repository.ts`: new `linkUnknownChannel(messageId, channelId)`. It updates only the rows of that message whose channel is still unknown.
- `apps/bot/src/listeners/reaction.listener.ts`: `resolveReactionRoleBinding` saves `reaction.message.channelId` when the matched binding's channel is unknown. This covers both add and remove. A failure is logged, and the role is still handled.
- `apps/bot/src/commands/roles/reaction-roles.command.ts`: `remove` skips `channels.fetch` for an unknown channel and still deletes the row.
- `apps/web/src/lib/server/guilds/reaction-role-panels.ts`:
  - `PanelSummary.url` is `string | null`. `listPanels` gives `url` and `channelName` null for unknown channels.
  - `removeBinding` and `deletePanel` make no Discord call for such rows.
  - The delete-and-audit tail moved into `forget`.
- `apps/web/src/app/dashboard/[guildId]/reaction-roles/page.tsx`: shows "Channel unknown (moved from Ririko 1.4). React to the message once to link it." and no Discord link.
- Tests:
  - The repository test covers linking: two rows linked, and a known channel left alone.
  - Two listener tests: the backfill, and no backfill for a known channel.
  - A command test: remove without a fetch.
  - A web test: list, remove and delete with no REST calls.
- `docs/migrations.md`: the reaction-role row explains the marker and the backfill.

**Verification**

**Decisions & gotchas**
