# Handover Note: BUG-0026 Canonical Game Item Seed Used Dynamic UUIDs Breaking Inventory Foreign Keys on Schema Recreation

- **Ticket Type & Points**: Bug | 3 pts (parent `EPIC-010`)
- **Author / Agent**: Antigravity Coordinator & Waifu TCG Specialist
- **Status**: DONE (fixed on `feat/STORY-168-album-shop-achievements`)
- **Timestamp**: 2026-09-29T20:55:00+08:00

## 1. Summary of Work Accomplished

### Symptom
Players reported that their gear had disappeared from their inventories and card loadouts. When running `/loadout` or `/tcg item inventory`, no equipment or consumables were listed even though users had previously collected, crafted, and enhanced items.

### Root Cause
1. In commit `6abd2da` (`STORY-168`), the column `owner_overridden` was added to `game_items`.
2. When `pnpm db:push` (`drizzle-kit push`) was executed against the SQLite database, Drizzle Kit recreated the `game_items` table.
3. Upon bot startup, `syncCanonicalItems` in `packages/services/src/waifu-tcg/equipment/catalog.ts` found an empty `game_items` table and seeded all 53 canonical items using unpinned dynamic `randomUUID()`s.
4. Meanwhile, `user_inventory_items` was not modified by the push; all 70 player inventory records retained their pre-push `item_id` foreign key UUIDs.
5. Consequently, inventory lookups joining `user_inventory_items` to `game_items` failed (`null`), and the item presentation commands filtered them out (`if (!entry.def) return false;`), causing player bags and card loadouts to appear empty.

### Fix
1. **Deterministic Canonical UUID Pinning (`packages/services/src/waifu-tcg/equipment/catalog.ts`)**:
   - Pinned all 53 canonical item UUIDs in `CANONICAL_ITEM_IDS`.
   - Updated `syncCanonicalItems` to pass `item.id ?? CANONICAL_ITEM_IDS[item.code]` to `itemRepo.create()`.
   - Added unit test in `packages/services/src/waifu-tcg/__tests__/catalog-sync.test.ts` verifying that `syncCanonicalItems` assigns deterministic stable UUIDs.
2. **Player Gear Inventory Data Recovery (`scripts/recover-player-gears.ts`)**:
   - Reconstructed the complete historical UUID-to-item mapping for all 37 distinct pre-push UUIDs:
     - 16 UUIDs recovered from `data/ririko.backup-2026-09-19-pre-import.sqlite`.
     - 4 UUIDs recovered from `economy_transactions` crafting recipes (`ARMOR_MAGMA_MAIL`, `RELIC_CINDER_LANTERN`, `RING_BLAZING_SUN`, `AMULET_OBSIDIAN_HEART`).
     - 2 UUIDs recovered from `economy_transactions` item enhancement transactions (`WEAPON_CALIDOS_GAUNTLETS` at +4 and +10, `WEAPON_CRIMSON_CHANT_STAFF` at +1).
     - 11 UUIDs recovered from dungeon first-clear boss drops (`maki_oze` -> `RELIC_FIRE_BRIGADE_BADGE`, `megumin` -> `WEAPON_CRIMSON_CHANT_STAFF`, `darkness` -> `ARMOR_CRUSADER_PLATE`, `mikasa` -> `TALISMAN_MANEUVER_GEAR`, `eris` -> `RING_SWORD_SAINT_BAND`, `holo` -> `AMULET_HARVEST_POUCH`, `rias` -> `RING_RUIN_SIGNET`, `tohru` -> `ARMOR_CHAOS_DRAGON_SCALE`, etc.).
     - 4 UUIDs recovered from dungeon floor loot slot constraints (`CRAFTING_DUST`, `RELIC_EMBER_CHARM`, `RING_SOLAR_FLARE`, `TALISMAN_EMBERSTEP`, `RING_SUNFORGED_SIGIL`).
   - Ran transaction in `data/ririko.sqlite`: 70 / 70 user inventory items remapped and verified with 0 unmapped or broken records remaining.
   - All 12 equipped items on user cards (e.g. Tier Harribel and Aqua loadouts) are properly linked and rendering.

## 3. Decisions & Gotchas
- When SQLite table rebuilds happen under `drizzle-kit push`, tables lacking default-backed static seeds will generate new UUIDs if using dynamic generators. Any canonical reference table whose IDs serve as foreign keys in user tables must have static, pinned UUID constants.
- Added recovery script `scripts/recover-player-gears.ts` with `--dry-run` capability so data audit can be repeated safely at any time.
