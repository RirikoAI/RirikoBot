## GROOMING · 2026-10-19T15:58:00Z · claude-opus-5-5 (coordinator) · regroomed for TODO

TASK-1911 is DONE, so 2.0 is on master and this task can run. The ticket asked for a `.codefactor.yml`. CodeFactor's documentation describes no such file. File exclusions are a repository setting on codefactor.io (Settings, **Ignore Files**, patterns one per line, case sensitive, for example `src/blob/*`). The one repository file CodeFactor reads for exclusions is `.cfduplication.yml`, the config of its duplication check. Its default is in `codefactor-io/default-configs`. So the task is: add that file, document the Ignore Files patterns, and list the maintainer steps.

**Approach**
1. Create `.cfduplication.yml` at the repository root. Start from CodeFactor's default, keeping every line:
   ```yaml
   # duplication threshold [20 - 100]
   MinLineCount: 20

   # files/patterns to exclude
   IgnorePatterns:
     - "**/test/**"
     - "**/tests/**"
     - "**/unittests/**"
     - "**/*.unittest*/**"
     - "**/spec/**"
     - "**/*.spec.*"
     - "**/__tests__/**"
     - "**/mocks/**"
     - "**/schema.*"
     - "**/migrations/**"
     - "**/migration/**"
     - "**/migrate/**"
     - "**/dist/**"
   ```
   Then add these entries, with a short comment that they are this repository's additions:
   - `packages/database/migrations/**` (generated SQL and drizzle meta).
   - `packages/database/src/migrations/generated/**` (embedded migration modules from `db:generate-migrations`).
   - `packages/database/src/schema/*/ddl.ts` (generated DDL).
   - `**/__fixtures__/**` (the 1.4.0 legacy schema fixture).
   - `**/*.test.ts` and `**/*.test.tsx` (tests that sit next to their source).
   - `apps/web/e2e/**` (Playwright tests).
2. In `docs/development.md` section 2, after the Git hooks paragraph, add a short subsection "CodeFactor". Keep the style of the file: simple English, short sentences. It says:
   - CodeFactor grades the `master` branch, and the README badge shows that grade.
   - `.cfduplication.yml` sets which files the duplication check skips.
   - Other generated files are skipped in the CodeFactor repository settings. List these patterns in a code block, one per line, in CodeFactor's documented form:
     ```text
     packages/database/migrations/*
     packages/database/src/migrations/generated/*
     packages/database/src/schema/pg/ddl.ts
     packages/database/src/schema/sqlite/ddl.ts
     packages/database/src/migration/__fixtures__/*
     ```
   - Maintainer steps, numbered: (1) sign in to codefactor.io with GitHub and check that the CodeFactor GitHub app can read `RirikoAI/RirikoBot`; (2) open the repository's settings on CodeFactor and check that the default branch is `master`; (3) open **Ignore Files**, paste the patterns, and save; (4) start a new analysis and check that the files above no longer appear in the file list.
3. README.md: read line 4 only. The badge is `https://www.codefactor.io/repository/github/ririkoai/ririkobot/badge/master`, linking to `.../overview/master`. Do not change it.

**Pitfalls**
- Prettier formats YAML and Markdown, so run `pnpm format` on the two files before `format:check`.
- `docs/development.md` is also a page of the docs site (`website/sidebars.ts`). Add no links to files outside `docs/`.
- Keep the default IgnorePatterns entries. Removing them would make CodeFactor check tests and migrations for duplication.

**Out of scope**
- The CodeFactor web settings themselves: the maintainer does them.
- An ESLint or oxlint config for CodeFactor, and any README change.
