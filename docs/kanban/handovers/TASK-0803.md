# Handover Note: [TASK-0803] Multi-Platform Stream Watcher Engine Reinforcement, Resilient Adapters, CLI Stream Configuration & General Stream Commands

## 1. Summary of Changes
- **Parent Story**: `STORY-080` (Multi-Platform Stream Watcher Engine & Thumbnail CDN)
- **Parent Epic**: `EPIC-008` (Streamer Notifications & Free Games Announcer)
- **Points**: 3

### Addressed Core Problems:
1. **Offline Status Fixes Across 3 Platforms**:
   - **YouTube**:
     - Added `YOUTUBE_API_KEY` (Google Cloud YouTube Data API v3) support in `YouTubeStreamAdapter`, allowing high-quota instant resolution (`channels` endpoint) and reliable live status detection (`search` with `eventType=live`).
     - Enhanced web scraper fallback: Added modern browser `User-Agent` and consent bypass cookies (`SOCS=...`, `CONSENT=YES+1`) to bypass Google/YouTube EU & US consent walls.
     - Fixed `getStreamStatus` when given a handle or username: queries `/@handle/live` instead of invalid `/channel/handle/live` (which threw 404).
     - Integrated public RSS feed inspection (`https://www.youtube.com/feeds/videos.xml?channel_id=...`).
   - **TikTok**:
     - Added `TIKTOK_SESSION_ID` (session cookie) and `TIKTOK_API_KEY` options to `TikTokStreamAdapter`.
     - In `resolveStreamer` and `getStreamStatus`: Parse `<script id="__UNIVERSAL_DATA_FOR_REHYDRATION__">` JSON payloads (`liveRoom.status = 2` for LIVE) and verify status via lightweight Webcast room alive checks (`webcast.tiktok.com/webcast/room/check_alive/?aid=1988&room_ids=...`).
   - **Twitch**:
     - Added automatic 401 token invalidation and refresh retry to `TwitchStreamAdapter` to ensure token expiry never leaves Twitch streams offline indefinitely.
   - **Watcher Engine**:
     - Wrapped each platform iteration and individual streamer check in isolated `try/catch` boundaries within `StreamWatcherEngine`. An error on one platform/streamer now never aborts the poll cycle for others.
     - Added `STREAM_CHECK_INTERVAL_MS` environment variable support (default: 60,000 ms).
     - Added `checkStreamsDetailed()` returning diagnostic metrics (`totalChecked`, `liveCount`, `errors`, `durationMs`).

2. **CLI Stream Configuration Command (`ririko stream-configure`)**:
   - Implemented `apps/cli/src/commands/stream-configure.ts` with aliases `stream:configure`, `streams:configure`, `streams-configure`.
   - Supports non-interactive flags:
     - `--twitch-client-id <id>`
     - `--twitch-client-secret <secret>`
     - `--youtube-key <key>`
     - `--tiktok-session-id <session>`
     - `--tiktok-key <key>`
     - `--check-interval <ms>`
     - `--show`: View masked secrets and provider status
     - `--test`: Validate API credentials against Twitch Helix, YouTube Data API, and TikTok
     - `--interactive`: Step-by-step interactive wizard
   - Added `youtubeStreamCheck`, `tiktokStreamCheck`, and `streamPollerCheck` to `ririko doctor`.

3. **Cross-Platform Unsubscription (`/stream unsubscribe` & `!unsubscribe`)**:
   - Added `listGuildSubscriptionsWithStreamers(guildId)` to `StreamRepository` (dual-dialect Drizzle query).
   - Re-engineered `handleUnsubscribeStream`: Queries active subscriptions in the server and matches streamer identifier case-insensitively across `username`, `displayName`, and `platformUserId`.
   - If exactly 1 match exists in the server, unsubscribes immediately regardless of whether it is Twitch, YouTube, or TikTok (no longer defaults to Twitch).
   - If multiple matches across platforms exist, prompts the user to specify `--platform`.
   - Supports `!unsubscribe <streamer> [platform]` prefix arguments.

4. **Command Generalization & Aliases**:
   - Promoted `setup-twitch` to `setup-stream-notification` with aliases: `['setup-twitch', 'setup-stream', 'setup-streams', 'setup-stream-channel', 'setstreamchannel', 'stream-channel']`.
   - Promoted `twitch-status` to `stream-status` with aliases: `['twitch-status', 'streamstatus', 'streams', 'streamers']`.
   - Added `/stream check` (and `!stream check`) subcommand to trigger manual diagnostic poll checks on demand.
