## 2. Key Deliverables & Implemented Architecture

### 2.1. Multi-Filter Bulk Purge & Message Sanitizer (`PurgeService`)
Implemented in `packages/services/src/moderation/purge.service.ts`:
- **Centralized Permission Verification**:
  - Validates `ManageMessages` permission for the invoker.
  - Validates `ManageMessages` and `ReadMessageHistory` permissions for Ririko bot.
- **Multi-Filter Support**:
  - `userId`: Restricts message purge to a specific target author.
  - `botsOnly`: Purges messages exclusively sent by bot accounts.
  - `humansOnly`: Purges messages exclusively sent by human users.
  - `invitesOnly`: Purges messages matching Discord invite patterns (`discord.gg/*`, `discord.com/invite/*`).
  - `linksOnly`: Purges messages matching standard URL patterns (`http://`, `https://`, `www.*`).
  - `attachmentsOnly`: Purges messages containing uploaded attachments/images.
- **Discord 14-Day API Limit Enforcement**:
  - Detects messages older than 14 days (`createdTimestamp < Date.now() - 14 * 86400 * 1000`).
  - Automatically isolates and bypasses older messages to prevent Discord API `bulkDelete` exceptions, tracking `skippedOlderThan14Days`.
- **Audit Case Logging & EventBus Integration**:
  - Automatically persists case in `moderation_cases` (`type: 'PURGE'`) with detailed metadata (channelId, deletedCount, skippedOlderThan14Days, filter options applied).
  - Emits `moderation:actionExecuted` to the `EventBus`.
