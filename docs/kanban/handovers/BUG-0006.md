## 1. Summary of Changes

### The Problems
1. **Parallel Execution on Prefix Commands in Dedicated AI Channel / Mentions**:
   When a user executed a prefix command such as `$balance` or `!help` in a dedicated `#ririko-ai` channel or while mentioning the bot, `AiChatController.handleAiMessage()` evaluated the message as an AI chat message and responded simultaneously with the `CommandRouter`.
   This caused duplicate responses: the command router replied with the rich economy embed, while the AI chat controller simultaneously processed `$balance` as a chat prompt and invoked the AI model.
2. **Hardcoded Stubs in `EconomyBalanceTool`**:
   `EconomyBalanceTool` previously returned hardcoded `0` values (`wallet: 0, bank: 0, netWorth: 0`), regardless of the interacting user's actual database balances. As a result, asking Ririko about financial balances returned `0` credits even for users with active database balances.

### The Solutions
1. **Prefix Filtering in `AiChatController`**:
   - Added `defaultPrefix` option to `AiChatControllerOptions` and `AiChatController` constructor (defaulting to `options.defaultPrefix || process.env.DEFAULT_PREFIX || '$'`).
   - Added `getPrefix(guildId)` to dynamically resolve guild settings prefix with fallback to `defaultPrefix`.
   - Updated `handleAiMessage(message)`:
     - Checks if the message content starts with the active `prefix`, `defaultPrefix`, or standard fallback `'!'`. If so, returns `false` immediately, leaving execution strictly to the `CommandRouter`.
     - Also checks if a prompt after stripping a bot mention starts with `prefix`, `defaultPrefix`, or `'!'` (e.g. `@Ririko $balance`), and returns `false`.
   - In `apps/bot/src/main.ts`, passed `{ defaultPrefix: prefix }` into `new AiChatController(bot.client, services, { defaultPrefix: prefix })`.
2. **Real Database Integration for `EconomyBalanceTool`**:
   - In `packages/ai/src/tools/types.ts`, extended `ToolExecutionContext` with optional `getBalance?: (userId: string) => Promise<{ wallet: number; bank: number; netWorth: number } | null>`.
   - In `packages/ai/src/tools/definitions/economy.tool.ts`, added `EconomyBalanceResolver` type and constructor injection. Updated `execute()` to resolve balance from `context.getBalance(targetUserId)` or `this.balanceResolver(targetUserId)`.
   - In `apps/bot/src/services.ts`, wired `EconomyBalanceTool` in `toolRegistry` with live `economyRepo.findById(userId)` lookup.
   - In `apps/bot/src/controllers/ai-chat.controller.ts` and `apps/bot/src/commands/ai/commands.ts`, populated `getBalance` in `toolContext` connecting directly to `economyRepo.findById(targetId)`.

## 3. Key Decisions & Gotchas

- **Decoupled Architecture**: `@ririko/ai` remains strictly database-agnostic by using `getBalance?: (userId: string) => Promise<{ wallet: number; bank: number; netWorth: number } | null>` in `ToolExecutionContext` and `EconomyBalanceResolver` in `EconomyBalanceTool`. The actual Drizzle ORM call is isolated to `apps/bot`.
- **Prefix Multi-Shield**: `handleAiMessage` checks `prefix` (guild settings or env), `this.defaultPrefix` (passed from main), and standard fallback `'!'`. This guarantees that prefix commands are never intercepted by AI chat, preventing double responses.
