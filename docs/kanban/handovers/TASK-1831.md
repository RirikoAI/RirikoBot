## GROOMING · 2026-10-09T14:58:10Z · claude-opus-5-5 (coordinator)

**Approach**
1. **Schema.** Add `invitedById` (`invited_by_id`, nullable, varchar(32) in PostgreSQL like `owner_id`, text in SQLite) to `guilds` in both `schema/pg/identity.ts` and `schema/sqlite/identity.ts`. Run `pnpm -F @ririko/database db:generate-ddl`; commit both regenerated `ddl.ts` files.
2. **Upgrade for existing databases.** New `packages/database/src/migrations/guild-registry.ts` with `ensureGuildRegistrySchema(client)`, following `ensureCardSerialSchema` (`migrations/card-serials.ts`): one transaction; on PostgreSQL take an advisory lock first and use `ALTER TABLE guilds ADD COLUMN IF NOT EXISTS invited_by_id varchar(32)`. SQLite has no `ADD COLUMN IF NOT EXISTS`: check `PRAGMA table_info(guilds)` first. Export it from `packages/database/src/index.ts`. Call it:
   - in `apps/bot/src/main.ts` next to `ensureCardSerialSchema`, before the listener starts;
   - in `apps/web/src/lib/server/services.ts` after `ensureTextIdColumns` (around line 306);
   - in `packages/database/src/copy/copy-database.ts` next to `ensureCardSerialSchema(target)` (line 643).
3. **Repository.** New `GuildRepository` (`repositories/guild.repository.ts`), both dialects, the style of `BotActivityRepository`: `upsert({ id, name, iconUrl, ownerId, joinedAt, isActive: true })` (update name, icon, owner, active and `updatedAt` on conflict; never overwrite `invited_by_id` or `joinedAt` with null); `markInactive(ids)`; `markInactiveExcept(activeIds)` for the ready sync; `setInviterIfMissing(id, userId)`; `listAll()`. Add it to `BotServices` and the web services.
4. **Listener.** New `apps/bot/src/listeners/guild-registry.listener.ts`, registered in `main.ts` like the other listeners:
   - `ClientReady` (every ready, including reconnects): upsert every `client.guilds.cache` guild, then `markInactiveExcept` those IDs. Then, one guild at a time, for active rows with no inviter, look up the inviter.
   - `Events.GuildCreate`: upsert, then look up the inviter. `command-sync.ts:57` already listens to this event; add a separate listener, do not edit that one.
   - `Events.GuildUpdate`: upsert name, icon and owner.
   - `Events.GuildDelete`: if `guild.available === false` it is an outage, so do nothing; otherwise mark it inactive.
   - Inviter lookup: `guild.fetchAuditLogs({ type: AuditLogEvent.BotAdd, limit: 10 })`, take the entry whose `targetId` is `client.user.id`, and store `executorId` with `setInviterIfMissing`. Any error (Missing Permissions 50013, Missing Access) leaves it null.
   - Catch and log every error; never let a database or Discord error reject a listener.
5. **Docs.** Update the `guilds` line in `docs/database.md` section 2.1 and add the upgrade to the "Afterwards" list in section 1.

**Pitfalls**
- `GuildCreate` also fires for guilds that come back after an outage; the upsert must be idempotent and must not reset `joined_at` or the inviter.
- Use `guild.joinedAt` (when the bot joined) for `joined_at`, not `guild.createdAt`.
- The audit log is rate limited; the ready backfill must await each guild before the next.
- Staging runs PostgreSQL with existing data (`guilds` exists, empty). The upgrade must work on a database that already has the table without the column, and on a fresh one created from the new DDL.
- Keep real host names, IPs and server IDs out of tests and notes; use fake snowflakes.

**Out of scope**
- The owner console page (TASK-1832).
- Backfilling inviters older than the audit log keeps.
- Changing the invite permissions.
