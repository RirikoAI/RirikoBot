## GROOMING · 2026-10-12T16:25:21Z · claude-opus-5-5 (coordinator)

**Approach**
1. Gate helper in the bot, e.g. `apps/bot/src/privacy/ai-consent.ts`: `ensureAiConsent(user, respond)` returns true when accepted, otherwise sends the prompt through `respond` and returns false. Call it at the top of each AI path before anything is stored or sent:
   - `AiChatController.handleAiMessage` after the "should I handle this" checks (prefix, channel, mention) and before `processChat`.
   - `/ai action:chat` in `createAiCommands`.
   - translation (`apps/bot/src/commands/ai/translate.command.ts`) and image generation (`apps/bot/src/commands/images/imagine.command.ts`, plus `handleImagineButtonInteraction` for re-rolls).
2. Prompt: an embed built from the configured providers (`BotServices` knows which AI and image providers were created; list only those). Buttons with custom ids `consent:ai:accept:<userId>` and `consent:ai:decline:<userId>`; route `consent:` in `registerComponentInteractions`; reject a different user ephemerally.
3. `ai consent withdraw|status`: new `consent` action on the `ai` command (slash option + prefix word). Withdraw: `ConsentService.withdraw(userId, 'ai')`, `conversationManager.clearAllMemory(userId)` (TASK-1932), delete AI user preferences (add a repository method if missing).

**Relevant code**
- `apps/bot/src/controllers/ai-chat.controller.ts:80` `handleAiMessage`, `:151` `processChat`.
- `apps/bot/src/component-interactions.ts`: custom id routing.
- `packages/services/src/privacy/consent.service.ts` from TASK-1931.

**Pitfalls**
- A message (mention) cannot get an ephemeral reply: reply to the message, briefly, and put the buttons on it.
- Image generation and translation also send user content to providers: they are AI features and are gated.
- The `ai` command's own management actions (`model`, `channel`, `persona`, `clear`, `consent`) are not gated: they send nothing to a provider.
- Name providers, never hosting.

**Out of scope**
- The terms notice (TASK-1931). Retention (TASK-1934).

**The prompt (exact text: an embed titled "Before you use AI features", buttons "I agree" and "No thanks")**
```
To answer you, Ririko sends what you write (chat, text to translate, image prompts) to: **Google Gemini**, **OpenAI**.
**Ollama** runs on the host's own machine.
These providers keep what they receive under their own policies. The bot owner cannot change or recall it.

Ririko stores your AI chats for 90 days, then deletes them.

`ai clear` deletes the chat in this channel.
`ai clear all` deletes all your chats.
`ai consent withdraw` takes back your consent and deletes your AI data.

[Terms of Service](<TERMS_URL>) · [Privacy Policy](<PRIVACY_URL>)

Press **I agree** to use AI features.
```
The provider names and the "runs on the host's own machine" line follow the bot's live setup. The 90 comes from `RETENTION_DAYS.ai`. Replies: "I agree" gives "Thank you. AI features are on for you. Send your request again."; "No thanks" gives "No problem. AI features stay off for you."; another user gets an ephemeral "This question is for someone else. Ask Ririko yourself to get your own."

**Decisions & gotchas**
- A user without the terms who runs an AI command sees the AI prompt and then, after the command, the one-time terms notice (TASK-1931 wraps `next()` and counts the prompt as a successful command). Two messages with the same links; "I agree" records `terms` too. If the maintainer wants only one, the terms middleware must skip commands that ended in the consent prompt: a small change in `notice.ts`, not done here.
- The gate fails closed: a rejected consent check stops the request (commands: the router's normal error reply; chat messages: logged, silent).
- A chat message has no ephemeral reply, so the prompt is public; it contains no personal data. The 10-minute throttle is in memory, per process, user and channel.
- `ai consent withdraw` order: consent first, then conversations, then preferences, so no new AI request is accepted while data is deleted. AI preferences include the timezone that `/timezone` also reads; withdrawing resets it (the acceptance asks for deleting them).
- `ai consent` with no or an unknown choice replies with a usage hint and does nothing.
- Users who used AI before this ships have no record and are asked once. The legal texts' date `2026-10-15` is the consent version; raise `AI_CONSENT_VERSION` to ask everyone again.
